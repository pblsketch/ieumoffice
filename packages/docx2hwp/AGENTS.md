# docx2hwp (`@genoffice/docx2hwp`)

워드 문서(.docx)를 한컴 한글에서 열고 고칠 수 있는 한글 문서(.hwp, .hwpx)로 바꾼다. `docx-engine`이 읽은 문서 모델을 한글 문서 모델로 옮기고, 한글 편집기와 같은 rhwp 엔진(`@rhwp/core`)의 편집 API로 빈 문서에 새로 쓴다. 쪽 그림을 붙이거나 PDF를 거치지 않는다. 옮기지 못한 것은 기능 단위의 목록(`losses`)으로 돌려준다. 계획은 `docs/plans/docx-to-hwp.md`다.

## 맡은 범위

- 공개면(`src/index.ts`)은 이것뿐이다: `HwpEngine.start(wasm)`, `docxToHwp(docx, 'hwp' | 'hwpx', engine)` → `{ bytes, losses }`, `Docx2HwpError`(`code`: `not-docx`, `hwp-readback`, `failed`), 형 `HwpFormat`·`HwpConversion`·`Loss`·`LossFeature`·`LossKind`. 호출하는 쪽은 엔진 문서, 단위, 문단 번호, `free()`를 보지 않는다.
- `units.ts`: 곱하는 수 전부와 단위 형(`HwpUnit` 1pt=100, `ParaUnit` 1pt=200, `Rgb`). 숫자를 단위 형으로 바꾸는 곳은 이 파일뿐이다.
- `losses.ts`: 잃은 것 표 `LOSS_FEATURES`(기능 → `dropped` 빠짐 / `changed` 바뀜)와 변환 하나의 장부 `LossLedger`. 같은 개체·문단에서 여러 번 나와도 한 번으로 센다. 보고 순서는 표의 순서다.
- `model.ts`: 엔진 단위로 바뀐 작은 한글 문서 모델(문단, 표, 머리말·꼬리말, 쪽 설정, 번호 정의). 표 칸에는 문단과 칸 안의 표가 워드의 순서대로 든다.
- `lower.ts`: docx-engine 모델 → 한글 모델. 엔진 없이 도는 순수 함수이고, 잃은 것은 여기서 정할 때 장부에 적는다. 블록 종류는 `BLOCK_LOWERINGS`(docx-engine의 `BlockType`마다 하나, 새 종류가 생기면 형 검사가 실패한다), 해석하지 못한 블록은 `PASSTHROUGH_KINDS`(위에서부터 처음 맞는 것이 정한다, 남길 수 있는 글은 서식 없이 남긴다).
- `cursor.ts`: 문단을 쓰는 자리(`Place`: 본문, 본문 표의 칸, 머리말·꼬리말)와 `ParagraphCursor`.
- `write.ts`: 한글 모델 → 엔진 호출. 쪽 설정, 글꼴·스타일·번호 표, 본문, 표, 각주·미주, 머리말·꼬리말.
- `engine.ts`: `@rhwp/core`를 값으로 가져오는 유일한 파일. 문서는 `withNewDocument`·`withOpenedDocument` 안에서만 살고 `finally`에서 `free()`한다.
- `convert.ts`: 읽기(`not-docx`) → 낮추기 → 쓰기(일괄 모드) → `.hwp`면 한글 편집기와 같은 저장 검사(`exportHwpVerify`의 쪽 수가 같아야 함, 아니면 `hwp-readback`) → 내보내기 → 결과를 한 번 다시 열어 본다.

## 맡지 않는 것 (경계)

- docx 읽기는 `packages/docx-engine`, 한글 문서 쓰기는 `vendor/rhwp-core`다. 이 패키지는 둘을 고치지 않고 공개 API만 쓴다.
- 저장 창, 확인 창, worker, 경로 허락은 `apps/docs`(`src/main/hwp-export.ts`)가 한다. 화면 이름 표(`LossFeature` → 문구)도 거기 있다.
- 늦게 받는 그림(`genoffice-docx-media`)을 원래 바이트로 되돌리는 일은 호출하는 쪽이 변환 전에 한다.
- 엔진 WebAssembly 파일의 위치는 호출하는 쪽이 정한다(앱은 `file-parse`의 `rhwpWasmPath`, 터미널 명령어는 `packages/cli`의 `rhwpWasmPath`).

## 항상 지켜야 하는 것

- **쓴 문단을 다시 나누지 않는다.** 엔진의 문단 나누기는 글자 위치만 받고, 표·그림·각주는 글자 길이가 0이라 쓴 문단을 끝에서 나누면 개체가 다음 문단으로 끌려간다. 자리의 마지막 문단은 늘 빈 여분이고, 새 문단은 여분을 0에서 나눠 만든다. 여분의 번호는 매번 문단 수에서 다시 센다. 다 쓰면 여분을 지워 표 칸의 문단 수가 워드와 같다. 이 규칙은 `ParagraphCursor` 한 곳만 안다.
- 워드의 쪽 나눔이 문단 안에 있으면 그 뒤를 "앞에서 쪽 나눔"인 새 문단으로 잇는다. 엔진의 쪽 나누기 호출은 문단을 끝에서 나누므로 쓰지 않는다.
- 문단 모양은 여분에 먼저 입힌 뒤 나눈다. 두 쪽이 모두 그 모양을 가지므로 같은 모양이 이어지는 문단은 모양 호출이 없다. 표 문단도 바탕글 스타일로 입힌다(앞 문단의 스타일이 넘어오지 않게).
- **쓰기 전체를 일괄 모드(`beginBatch`~`endBatch`)로 감싸고, 본문은 한 구역에 쓴다.** 엔진은 일괄 모드에서 글자·문단 모양, 스타일, 표·칸·그림 속성, 머리말·꼬리말 서식, 각주의 다시 배치를 `endBatch`의 한 번으로 미룬다(엔진 패치 0043, 결정 0124). 일괄 모드 밖에서는 호출마다 구역 전체를 다시 배치해 문단 수의 제곱으로 느려진다. 일괄 모드 안에서는 문서 내용(문단 수·길이, 각주 글)만 읽는다. 쪽 수와 쪽 배치는 `endBatch` 뒤에 읽는다.
- 표 틀은 HTML 붙여넣기로 만들고(칸 합침, 폭, 행 높이, 테두리, 빈 칸) 칸 배경은 칸마다 따로 넣는다. 붙여넣기에 배경을 넣으면 엔진이 첫 칸의 배경을 표 전체 배경으로도 넣는다. 붙여넣기는 그 문단의 모양을 바꾸므로 표 문단 모양은 붙여넣은 뒤에 다시 입힌다.
- **표 안의 표도 본문에서 만든다.** 그때까지 쓴 본문 뒤의 새 문단에 본문 표처럼 다 만들고, 엔진의 개체 복사(`copyControl`)로 복사해 그 문단을 지운 뒤 칸 문단에 붙인다(`pasteInternalInCellByPath`). 엔진의 칸 테두리·배경·여백·세로 정렬 호출(`setCellProperties`)은 본문 표에만 있고 경로판이 없다. 칸 안의 HTML 붙여넣기는 표를 만들지 않고 글만 넣는다. 그래서 `createTableInCellByPath`로 칸 안에 바로 만들면 칸 배경·테두리·여백을 줄 길이가 없다. 더 깊은 표는 바깥 표를 옮기기 전에 그 칸에 먼저 옮긴다. 그래서 글을 쓰는 자리는 늘 본문, 본문 표의 칸, 머리말·꼬리말 중 하나이고 문단 쓰기 규칙이 칸 안의 표에도 그대로 선다. 만든 문단은 `ParagraphCursor.drop`으로 되돌린다(여분을 그 문단에 합쳐 다시 여분으로 쓴다).
- 칸 안의 표는 칸 너비에서 좌우 칸 여백을 뺀 폭에 맞춰 줄인다. 워드는 칸 안의 표를 칸 여백까지 그리고, 한글은 여백 안에 두고 넘친 쪽을 잘라 그린다. 퍼센트 폭은 칸 안쪽 폭을 기준으로 잰다. 본문 표는 워드의 폭을 그대로 둔다.
- 엔진이 칸 안의 표를 거절하면(붙여넣기·복사·칸에 붙이기) 그 표의 칸 문단을 칸 안의 문단으로 풀어 쓰고 `nested_table`로 알린다. docx-engine은 여덟 겹보다 깊은 표를 칸 하나짜리 표의 서식 없는 문단으로 넘기므로(`MAX_TABLE_NEST_DEPTH`) 그 표도 `nested_table`로 알린다.
- 각주 글은 각주 번호 뒤에 넣는다. 새 각주의 첫 문단에는 번호 자리가 있다.
- 머리말·꼬리말의 쪽 번호는 워드가 둔 자리에 쪽 번호 필드로 넣는다(docx-engine이 `PAGE_MARK`로 표시한 곳).
- 글꼴: 한글·한자·일어·기호 칸에는 동아시아 글꼴, 나머지 칸(라틴, 기타, 사용자)에는 라틴 글꼴을 쓴다. 워드는 한국어 문서의 ○·※ 같은 기호를 동아시아 글꼴로 그린다. 동아시아 글꼴이 없거나 라틴 전용 글꼴(Calibri 등)이면 한글 기본(함초롬바탕)을 둔다.
- 워드의 내어쓰기는 첫 줄을 왼쪽으로 빼고, 한글의 내어쓰기는 다음 줄을 오른쪽으로 민다. 그래서 한글 왼쪽 여백 = 워드 왼쪽 들여쓰기 + (음수인) 첫 줄 들여쓰기다.
- 한글의 머리말 칸은 위쪽 여백 아래에 있다. 워드의 위쪽 여백(본문까지)은 한글의 위쪽 여백(= 워드의 머리말 거리)과 머리말 칸으로 나눈다. 용지는 세운 크기로 주고 가로 방향은 표시로 준다.
- 엔진이 개체 하나(그림, 각주, 표)를 거절하면 장부에 적고 나머지를 쓴다. 글자·서식 호출이 실패하면 변환 전체가 실패한다(서식 없는 문단은 조용한 손실이다).
- `LOSS_FEATURES`에 기능을 더하면 `apps/docs/src/main/hwp-export.ts`의 이름 표와 `hwp-export-strings.ts`의 21개 언어 문구, 터미널 명령어의 이름 표(`packages/cli/src/formats/docx-hwp.ts`)도 더한다(형 검사가 지킨다). `docs/contracts.md`의 식별자 목록에도 더한다(`packages/cli/tests/convert-docx-hwp.test.ts`가 지킨다). 식별자는 명령어의 `detail.hwp_report`로 밖에 약속한 값이라 이름을 바꾸지 않는다. ODT의 보고 ID(`REPORT_FEATURES`)와 섞지 않는다.

## 첫판에서 옮기지 않는 것

`docs/plans/docx-to-hwp.md` 6절의 표다. 빠지는 것: 메모, 변경 내용(받아들인 결과로 쓴다), 수식, 차트, 도형, 글상자, 기타 개체, 펜 글씨, 워터마크, 숨긴 글자, 쪽 테두리, 문단 테두리·배경, 줄 번호, 편집 제한. 바뀌는 것: 하이퍼링크(글만), 구역 나눔·다단(한 구역), 첫 쪽·짝수 쪽 머리말, 머리말 안의 그림·표, 떠 있는 그림(글자처럼), 표 안의 표(엔진이 거절했거나 여덟 겹보다 깊을 때만 칸 안의 문단으로 풀림), 표 배치, 번호 모양, 탭, 차례·필드(결과 글), 글자 효과, 각주의 글자 모양, 세로 쓰기, 서식 없이 옮긴 문단.

## 알려진 한계

- 엔진이 만든 문서는 문단 대부분에 저장된 줄 정보(`linesegarray`)가 없다. 한컴 한글은 열 때 다시 나눈다(시험 판에서 확인).
- 걸리는 시간은 문서 길이에 비례한다(204쪽 2,484문단 약 11초, 94쪽 844문단 약 3.5초, `.hwp`, 결정 0124). 대부분은 문단마다의 글자 모양 호출과 칸 문단 쓰기, 끝의 쪽 나누기 한 번이다.
- 표 칸 안의 각주는 엔진에 만들 길이 없다.
- 칸 안의 표 하나마다 본문에 한 번 붙여넣고 지운다.

## 테스트

- 패키지 폴더에서 `npx vitest run`, 또는 루트에서 `npm run test -w @genoffice/docx2hwp`. 실제 엔진을 쓴다(`node_modules/@rhwp/core` = `vendor/rhwp-core`).
- `tests/convert.test.ts`: 시험 문서(`tests/fixtures`의 가정통신문·탭 문서·표 안의 표 문서, `apps/docs/tests/pagination-corpus/docx`의 각주·혼합·기본 견본)를 HWP와 HWPX로 바꾸고 `tests/helpers/read-back.ts`가 엔진으로 다시 열어 요약한다. 가정통신문 본문을 열 번 이은 긴 문서(160문단)가 가정통신문 열 벌과 같게 읽히는지도 본다. 문단 모양은 저장된 XML에서 pt로 읽는다(엔진의 속성 조회는 문단 간격을 다른 배율로 돌려준다).
- `tests/lower.test.ts`: 엔진 없이 낮추기 규칙. `tests/engine.test.ts`: 엔진을 가져오는 파일과 단위를 만드는 파일이 하나씩인지, 성공과 실패 모두에서 문서가 모두 `free()`되는지.
- 한컴 한글 확인은 사람이 돌린다: 결과를 한컴 한글 2024로 열어 쪽 수·글자 수를 보고 PDF로 그려 견준다(`tools/odt-hancom/`의 방식).
