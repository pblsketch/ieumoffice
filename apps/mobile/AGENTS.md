# apps/mobile (`@genoffice/mobile`)

이음오피스의 Android·iOS 모바일 앱(`com.ieumoffice.mobile`, Tauri 2 Mobile)이다. 스마트폰·작은 태블릿(`<840px`)부터 큰 태블릿·폴드·DeX(`≥840px`)까지 한 화면에서 한글(`.hwp`/`.hwpx`)과 마크다운(`.md`/`.markdown`/`.txt`) 문서를 열고 고치며, AI 도우미를 함께 쓸 수 있다.

## 맡은 범위

- 모바일 렌더러(`src/renderer/`):
  - 반응형 셸(`shell/EditorShell.tsx`, `shell/useViewportLayout.ts`), 홈·바텀시트·AI 패널·미저장 전환 모달(`components/`), 설정·AI 연결·HWP 원본 백업 관리(`settings/SettingsScreen.tsx`), 종단 통합(`App.tsx`).
  - 편집기 호스트(`editors/MarkdownMobileEditor.tsx`, `editors/HwpMobileEditor.tsx`): 보기 우선 열기, 마크다운 인라인 그림 첨부, 한글 Canvas2D 강제 부팅(`dist/studio/`).
  - 편집기 등록표(`editors/registry.ts`, 형은 `editors/editorKind.ts`)와 형식 종류(`editors/hwpKind.tsx`, `editors/markdownKind.tsx`): 열기·저장·공유·복구 사본·AI 스킬·도구 막대·편집 화면을 종류마다 갖는다. `App.tsx`는 등록표에서 종류를 찾아 부르기만 한다. AI 실행과 AI 설정 상태는 `ai/useMobileAi.ts`, 설정 화면은 절마다 `settings/sections/*.tsx`.
  - 22개 언어 문구(`i18n/`), 토큰 전용 스타일(`styles/mobile-tokens.css`), OFL-1.1 한글 글꼴(`assets/fonts/`).
- Tauri 2 Rust 백엔드(`src-tauri/`):
  - 단일 활성 문서 세션·최근 목록·자동 복구·HWP 최초 덮어쓰기 전 백업(`src/storage/`). 형식 목록(`storage/session.rs`)에 1판 형식(pdf·html·xlsx·xlsm·xls·csv·epub·pptx)이 있고, 열 수 있는 형식 문지기(`mobile_set_openable_formats`)가 등록표에 없는 형식을 최근 목록에 넣기 전에 거절한다(`mobile.format.notOpenable`).
  - `packages/hwp5-wasm`(`rlib`) 직접 링크 기반 HWP 컨테이너 검사·암호/배포용 판정·변경 추적 제거·저장 보정(`src/hwp/`).
  - AES-256-GCM 봉인 저장소(`src/secrets/`)와 HTTPS 전용 AI 스트리밍·ChatGPT 공식 모바일 OAuth(`src/ai/`).
  - 로컬 모바일 플러그인(`src-tauri/plugins/tauri-plugin-ieum-mobile/`): Android Kotlin(SAF·FileProvider·Keystore·Custom Tabs) / iOS Swift(`UIDocumentPicker`·보안 북마크·`UIActivityViewController`·Keychain·`ASWebAuthenticationSession`) + 호스트 테스트 스텁.
- 네이티브 설정 주입(`native-config/{android,ios}/`, `scripts/apply-native-config.mjs`).

## 항상 지켜야 하는 것

- **단일 활성 문서**: 모바일 WebView OOM을 막기 위해 동시에 여는 문서는 최대 1개다. 미저장 상태에서 다른 문서로 넘어가거나 외부 열기 인텐트가 들어오면 반드시 확인 모달을 거친다.
- **Canvas2D 강제**: 모바일 한글 편집기는 `canvaskit-wasm`을 로드하지 않고 Canvas2D로만 부팅한다. `vite.config.ts`는 `apps/hwp/scripts/rhwp-patches.mjs`의 `rhwpPatches('sdk-scheme')`로 `tauri:` 프로토콜을 허용하고 `apps/hwp/public/studio`를 `dist/studio`로 복사한다.
- **원본 보호와 백업 게이트**: 암호·배포용 한글 문서는 저장과 편집본 공유를 모두 거절(`PASSWORD_PROTECTED`)하고 원본 공유(`mode: 'original'`)만 허용한다. 최초 덮어쓰기 전 백업이 실패하면(`BACKUP_FAILED`) 원본을 덮어쓰지 않는다.
- **보안과 요금 경로**: API 키와 OAuth 토큰은 Rust 봉인 저장소에만 두고 WebView로 원문을 내보내지 않는다. 키 제공자 요청은 웹뷰가 키 자리에 표식(`__sealed__:<제공자>`)만 넣고, Rust 중계가 그 제공자의 정해 둔 호스트로 가는 https 요청에서만 진짜 키로 바꾼다(아래 "T7 AI"). `IEUM_MOBILE_CHATGPT_CLIENT_ID`가 없는 릴리스 빌드에서는 ChatGPT 연결 카드를 숨긴다. `dev-chatgpt-loopback` 피처는 릴리스 빌드에서 컴파일하지 않는다. `auto` 선택은 API 키 제공자로 넘어가지 않는다. OpenRouter 무료 연결은 `:free` 모델만 보낸다(웹뷰와 Rust 양쪽에서 거절).
- **디자인 시스템**(`docs/plans/mobile-design-system.md`, 결정 0165): 겉모습은 두 플랫폼에서 하나이고, 플랫폼별로는 동작만 가른다. 간격·글자 크기·터치 크기·움직임은 `mobile-tokens.css`의 `--m-*` 토큰으로만 쓴다(직접 px 값을 새로 적지 않는다. 글자 크기는 rem 토큰이라 OS 글자 크기를 따른다). 누를 영역은 `--m-hit`(48px) 이상이다. 창 크기는 `useViewportLayout`이 `<html data-window="compact|medium|expanded|large">`(600/840/1200px)와 `--m-kb`(키보드 높이)로 내보내고, 옆 패널 배치(`isTablet`)는 expanded부터다.
- **공용 껍데기 부품**(디자인 시스템 5.2·5.5·5.9·5.11): 뒤로 가기는 `shell/backStack.tsx`의 `useBackLayer` 하나로 쌓는다(시트 → 저장 안 함 확인 창 → 편집 모드 → 편집 화면·설정). 층마다 브라우저 기록 한 칸을 쓰고, Android 시스템 뒤로 가기(웹뷰 뒤로)가 `popstate`로 맨 위 층을 닫는다. 하단 시트는 `components/Sheet.tsx`(중간·크게 두 멈춤, 손잡이 끌기, 아래로 밀어 닫기, 키보드 위로 올라감), 알림은 앱 한 곳의 `components/Toast.tsx`(4초, 동작이 있으면 8초, 누르는 동안 멈춤). 편집 화면 상단 바는 주 단추 하나([편집] / [완료])이고, 저장 단추 대신 제목 아래 저장 상태(저장됨·저장 안 됨·저장 중)를 보이며 눌러 저장한다. [완료]는 바뀐 것이 있으면 원본에 저장한 뒤 보기로, 편집 중 뒤로 가기는 저장하지 않고 보기로 간다.
- **한글 흐름(읽기) 보기**(`editors/hwpFlow.ts`, `editors/HwpFlowView.tsx`, 결정 0165): rhwp 엔진의 HTML 내보내기(`exportSelectionHtml` 문단별, 표·그림은 `exportControlHtml`)로 화면 폭에 다시 흘린 문서를 만든다. 문단마다 `data-sec`·`data-para`를 붙인다(흐름 편집이 엔진 위치로 되돌리는 열쇠). 표는 엔진이 내보낸 뼈대(테두리·너비·채움·합친 칸)를 그대로 쓰고 칸 안은 칸 문단마다 다시 채운다. 내보낸 표 HTML은 빈 문단을 빠뜨려 엔진 위치로 되짚을 수 없어서다. 칸 문단에는 엔진의 칸 경로(`data-path`, `[{controlIndex, cellIndex, cellParaIndex}, ...]`, 겹표는 단계가 늘어난다)를 붙이고, `<td>`는 문서 순서가 엔진 칸 번호와 같다(합친 칸 포함, 시험 양식 52칸 확인). 칸 문단 안의 표·그림은 `exportControlHtml(구역, 문단, 칸 문단 경로, j)`를 j=0부터 오류가 날 때까지 불러 찾는다. 글상자와 그림 캡션은 그 개체의 "칸 0"으로 닿아서(`[{controlIndex, cellIndex: 0}]`) 표 칸과 같은 방식으로 보이고 고쳐진다. 표 캡션은 평면 칸 호출(`getCellParagraphCount(구역, 문단, 개체, 65534)` 등)로만 닿고 HTML로 못 내보내서 글자만(정렬·글꼴·크기) 보인다. 글머리표는 문단 속성(`headType: Bullet`)과 `getBulletList`로 찾아 `<p data-marker>`에 두고 CSS로 그린다(고칠 글에 섞이지 않게). 각주·미주는 `getFootnoteInfo`의 글을 그 문단 뒤에 읽기 전용으로, 머리말·꼬리말은 구역 처음·끝에 한 번 읽기 전용으로 둔다. `getHeaderFooter`가 준 문단·개체 번호로 머리말을 "칸 0"처럼(`[{controlIndex, cellIndex: 0}]`) 칸과 같이 그려서 안의 표·그림도 보인다. 머리말 목록은 평면 칸 호출이 받지 않아(표·글상자만 받는다) 경로 호출로 돌려 부르고(`pathCallsOnly`), 편집 주소(`data-sec`·`data-path` 등)는 모두 떼어 편집기가 건드리지 않게 한다. 그리지 못하면 글만 보인다. 자동 문단 번호(1., 가., ①)는 엔진 패치 0057의 `getParagraphHeadText`로 쪽 화면과 같은 번호 글을 받아 같은 방식(`data-marker`, 번호는 `data-number`도)으로 그린다. 엔진이 번호를 쪽 배치 중에 문서 순서로 세고 수준별 번호 모양을 내주지 않아 앱에서 셀 수 없기 때문이다. 문단을 나누거나 합치면 편집기가 `data-number` 문단의 번호를 모두 다시 받아 온다. 칸 안 글상자·캡션(경로가 두 단계 이상)의 Enter·Backspace는 경로 나누기·합치기로 하고, 엔진 패치 0058이 그 호출이 표 칸 밖의 글상자·캡션도 받게 한다. 엔진이 그래도 편집을 거절하면 화면을 엔진 글로 되돌리고 "이 자리에서는 할 수 없는 편집" 알림(`flowEditRefused`)을 띄운다. 문서에서 온 HTML이라 스크립트를 못 돌리는 틀(`sandbox="allow-same-origin"`)에만 넣는다. 엔진은 studio가 이미 싣고 있는 같은 WASM 파일을 쓴다(`vite.config.ts`의 `ieum-shared-rhwp-wasm`, `__IEUM_RHWP_WASM__`) — 두 벌을 싣지 않는다. 휴대폰·작은 태블릿(compact·medium)은 보기 모드에서 흐름 보기가 기본이고, 쪽 편집기(studio)는 그 아래에 늘 올려 둔다(저장·공유·AI가 그것으로 문서를 읽는다). 편집하고 보기로 돌아오면 studio에서 내보낸 바이트로 흐름을 다시 만든다.
- **흐름 보기 안 편집**(`editors/flowEditing.ts`): 흐름 쪽은 자기 엔진 문서(`HwpDocument`)를 들고 고친다. 엔진의 문단 글자 위치는 글자만 센다(표·그림은 자리를 차지하지 않음)라서 화면 커서 위치가 곧 엔진 위치다. 타자(한글 조합 포함)는 브라우저가 바꾼 뒤 그 문단의 글을 엔진 글과 비교해 차이만 넣고 지운다(조합 중에는 넣지 않음). Enter·문단 합치기·여러 문단 지우기·붙여넣기·되돌리기는 가로채 엔진 연산(`splitParagraph`·`mergeParagraph` 등)으로 한다. 고치기 전 화면 글이 엔진과 다르면 고치지 않고 엔진에서 다시 그린다. 표 칸 안(겹표 포함)·글상자·캡션도 같은 방식으로 고친다. 한 단계 경로(본문 표의 칸, 글상자, 캡션)는 평면 칸 연산(`insertTextInCell`·`splitParagraphInCell` 등), 더 깊은 경로는 `...InCellByPath` 연산을 쓴다. 평면 연산만 표 캡션에 닿고 글상자·캡션 문단을 나누고 합친다. 엔진이 연산을 거절하면 입력을 취소하고 그 블록을 엔진에서 다시 그린다. 칸 안에서 문단을 나누거나 합치면 그 칸 전체를 다시 그린다(칸 문단 번호가 바뀌므로). 여러 문단 지우기는 같은 그릇(본문끼리, 같은 칸끼리) 안에서만 하고, 서식은 화면 순서대로 걸친 블록 모두에 건다. 문단 서식(정렬·줄 간격·글머리표·번호)도 흐름 보기에서 캐럿이나 선택이 걸친 문단마다 엔진의 `applyParaFormat`(본문)·`applyParaFormatInCell`(한 단계 경로)·`applyParaFormatInCellByPath`로 건다. 목록은 첫 문단 기준으로 한꺼번에 켜고 끄며, 되돌리기는 바꾸기 전 문단 속성(정렬·줄 간격·머리 종류·번호 정의·수준)을 다시 건다. 표의 짜임(줄·칸 더하기, 합치기)과 그림은 고치지 않는다. 마지막으로 고른 쪽/흐름 보기는 문서별로 기억한다(`shell/layoutMemory.ts`). **그림 넣기**: 흐름 보기에서는 서식 판 [넣기]의 그림 넣기가 시스템 선택 창으로 그림을 받아(`editors/pickPicture.ts`, PNG·JPEG·GIF·BMP는 그대로, 다른 형식은 PNG로 다시 그림) 캐럿이 있는 문단의 끝에 글자처럼 취급 그림으로 넣는다(본문 `insertPicture`+`setPictureProperties`, 칸·글상자 `insertPictureInCell`+`setCellPicturePropertiesByPath`). 엔진은 본문에 새 그림을 쪽 기준 떠 있는 그림으로 넣으므로 바로 글자처럼 취급으로 바꾼다. 흐름은 문단의 그림을 글 뒤에 보이므로 문단 끝에 넣어야 쪽 보기와 자리가 같다. 크기는 원래 크기(96dpi)를 글 영역 너비(칸 안은 3분의 1)와 높이의 절반 안으로 줄인다. 되돌리기는 그 그림을 지운다. 쪽 보기에서는 studio의 `insert:image`(눌러서 놓기)를 쓴다. **메모**(`components/MemoSheet.tsx`): 흐름 보기의 [메모] 보기 도구와 서식 판 [넣기]의 메모 넣기가 메모 시트를 연다. 메모는 엔진의 `getMemoList`(위치 경로 `{type: cell|textbox, controlIndex, cellIndex, paraIndex}`를 흐름 블록 주소로 바꿈)로 읽고, 선택한 글(첫 블록 안)에 `insertMemo`/`insertMemoByPath`로 넣고, `insertMemoReply`·`setMemoText`·`removeMemo`(답글도 함께 지움)로 고친다. 메모 범위는 CSS Custom Highlight API(`::highlight(ieum-memo)`)로 칠해 DOM을 바꾸지 않는다(타자·비교에 영향 없음, API가 없는 웹뷰는 목록만). 메모 고치기는 글 되돌리기 쌓기에 넣지 않는다. 작성자 이름은 기기에 기억하고, 없으면 제품 이름이다. **쪽 번호**(`editors/pageNumbers.ts`, `components/PageNumberSheet.tsx`): 서식 판 [넣기]의 쪽 번호가 위치(없음·아래 가운데·아래 오른쪽·위 가운데·위 오른쪽)·모양(1·I·i·가)·줄표를 고르는 시트를 연다. PC 플러그인과 같은 규칙으로 첫 구역과, 제 쪽 번호가 있는 뒤 구역에만 `setPageNumberPos`(엔진 패치 0014)를 건다. 쪽 번호처럼 문서 전체에 거는 바꾸기는 `changeWholeDocument`(App)가 한다: 흐름 편집을 먼저 넘긴 studio 바이트를 엔진 사본에서 바꾸고 studio(`loadBytes`)와 흐름 보기에 다시 싣는다(되돌리기 기록은 새로 시작). **마크다운 → 한글**(`editors/markdownToHwp.ts`): 마크다운 문서의 [더 보기] "한글 문서로 저장"이 PC와 같은 길(결정 0135)로 바꾼다. 마크다운 편집기(`apps/markdown`)의 Tiptap 파서·워드 내보내기 → `@genoffice/docx2hwp`(`look: 'hangul'`) → `.hwpx`를 새 파일로 저장(`saveConvertedHwpx`)하고 알림의 [열기]로 연다. 이 길은 바꿀 때만 불러오는 덩어리라(약 5MB, Mermaid·KaTeX 등) 앱 시작 크기는 그대로다. 그 소스의 창 전역·모듈 선언(`apps/markdown/src/renderer/env.d.ts`, `types/wavedrom.d.ts`)을 이 앱의 `tsconfig.json`이 함께 읽는다(`packages/cli`와 같음). `.hwp`로는 바꾸지 않는다(.hwp 저장 보정이 쪽 편집기 측정값을 쓰기 때문). 엔진은 흐름 보기가 이미 띄운 같은 모듈을 쓴다. **문서 점검**(`components/DocCheckSheet.tsx`): 한글 문서의 [더 보기] "문서 점검"이 PC의 점검 창과 같은 일을 한다. 흐름 편집을 넘긴 뒤 쪽 편집기 플러그인(PC와 같은 studio 묶음에 든 `ieum-agent`, `HwpMobileEditor.callPlugin`)의 `documentProfile`로 문서를 읽고 `@genoffice/doc-rules`의 `audit`(같은 규칙 묶음, 기본으로 꺼 둔 검사 넷은 스위치)으로 판정한다. 모델도 네트워크도 없다. 걸린 곳을 누르면 흐름 보기에서는 그 블록(칸 문단에만 든 표·그림은 `data-obj-path`로 찾은 개체)으로, 쪽 보기에서는 플러그인 `reveal`로 간다. 한글 전용 글꼴은 편집 모드에서 함초롬바탕으로 바꿀 수 있다(플러그인 `replaceFont`). AI에게 넘기기는 넣지 않았다(모바일 AI 기본 꺼짐). 문구는 PC 점검 창의 번역을 그대로 옮겼다. 글 블록 밖(칸 테두리 자리 등)의 입력은 막는다. **흐름에서 고친 것은 저장·공유·복구 사본·AI·쪽 보기 전환 전에 `createFlowSyncedPort`가 studio에 넘긴다**(흐름 문서를 내보내 `loadBytes`). 저장 경로는 studio 하나로 유지한다. 흐름 틀은 스크립트를 못 돌려도 부모가 붙인 이벤트 처리기는 돈다(Chromium 확인).
- **흐름 보기의 공백**: HTML은 연이은 공백과 블록 앞뒤 공백을 한 칸으로 줄이므로, 줄어들 공백은 줄바꿈 없는 공백(NBSP)으로 바꿔 문서 그대로 보인다(`keepSpacesVisible`). 보기와 편집 모두, 글 블록·머리말·꼬리말·각주에 한다. 편집 모드에서만 하던 때는 편집을 누르면 "2026년␣␣0월" 같은 칸이 넓어졌다. 블록 글을 읽을 때(`paragraphText`) NBSP는 공백으로 돌아가 엔진 글은 그대로다.
- **AI는 기본 꺼짐**: 새 설치는 `aiEnabled: false`(Rust `MobileAppPrefs::default`와 화면의 초기값)로 시작한다. 꺼져 있으면 AI 진입점을 모두 숨기고, 설정의 켜기 스위치만 남긴다.
- **한글 AI 도구**(`ai/hwpAgent.ts`): PC 한글 편집기의 도구(`apps/hwp/src/renderer/ai/hwp-skill.ts`)를 그대로 쓴다. 도구는 쪽 편집기에 이미 든 같은 플러그인(`ieum-agent`)을 `HwpMobileEditor.callPlugin`으로 부른다. 웹(웹 검색·URL 읽기·그림 검색·그림 넣기), 그림 만들기, 사진 보기, AI 창에 붙인 사진은 T7의 공용 AI 도구(`ai/tools`)로 돈다. 스킬의 가용성 질문(`webAvailable`·`imageGenAvailable`·`pictureAnalysisAvailable`)에 `getMobileAiTools().availability()`를 그대로 넘기고, 실행 동안만 `window.hwpApi`를 PC 한글 preload 모양으로 답하는 대역으로 두었다가 끝나면 되돌린다. 메모를 지우는 편집의 허락은 묻지 않고 거절한다(메모 창의 예/아니요가 휴대폰에 없음). 문구(22개 언어)와 도구, 공용 AI 도구 묶음은 AI를 쓸 때만 불러오는 덩어리(`hwpAgent`, 약 577KB, gzip 약 169KB)다. 실행 전에 흐름 보기 편집을 쪽 편집기로 넘기고(`flushFlowToStudio`), 끝나면 흐름 보기를 다시 그린다. 한 실행의 변경은 PC처럼 플러그인 `undo(단계 수, 시작 때의 바깥 변경 수)`로 한 번에 되돌리고, 그 사이 문서가 바뀌었으면 되돌리지 않고 알린다(`aiUndoRefused`). 보기/편집 게이트(`wrapSkillWithViewEditGate`)는 PC 도구의 편집 도구 목록(`HWP_EDIT_TOOLS`)으로 씌운다.
- **질문 카드**: 한글·마크다운 모두 공용 `ask_questions`(A2UI v1.0, 결정 0164)를 함께 내놓고, 카드는 공용 `AiQuestionCard`·`useAiInlineQuestions`로 AI 시트의 대화 아래에 그린다. 카드는 그 실행 동안 보이고, 답은 이어지는 답 글이 담는다. 새 메시지는 열린 카드를 닫고(`skip`), 문서를 바꾸면 카드 상태도 비운다.
- **스타일과 언어**: 모든 CSS는 `src/renderer/` 아래에 두고 색은 `packages/ui/src/tokens.css` 변수만 사용한다. 22개 언어 문구는 `LANGS` 전체를 유지하고 `brandText`로 제품 이름을 치환한다.

## 1판 트랙 자리

모바일 1판은 트랙 일곱(T1 엑셀, T2 PDF, T3 PDF 도구, T4 HTML·마크다운, T5 EPUB·PPT 읽기, T6 홈·설정, T7 AI)이 나란히 만든다. 서로 같은 줄을 고치지 않도록 공용 파일을 트랙 자리로 갈라 두었다(S0, 바탕 공사). 트랙은 **자기 폴더의 파일만 채운다.** 등록표·문구 묶음·아이콘 지도·다리 내보내기·`commands/mod.rs`는 이미 이어 두었으므로 고치지 않는다. 공용 파일에 줄을 더하는 곳은 셋뿐이고, 모두 자기 표시 주석 바로 아래다: `src-tauri/src/lib.rs`(`// T1 sheets` 등 명령 등록, `// T1 sheets state` 등 관리 상태), `src-tauri/Cargo.toml`(`# T1 sheets` 등, "deps:" 커밋), `native-config/`(Android `<!-- T1 sheets MIME types -->` 등 두 거르개 모두, iOS `<!-- T1 sheets document types -->`·`<!-- T1 sheets imported types -->` 등).

- **편집기 종류**: `editors/<트랙>/index.ts`의 배열(`sheetsEditorKinds`, `pdfEditorKinds`, `htmlEditorKinds`, `readersEditorKinds`)에 `EditorKind`를 넣는다. 형식·확장자(`openExtensions`)가 등록되면 파일 고르기 창과 열 수 있는 형식 문지기에 저절로 들어간다. 등록 전에는 그 형식을 열지 않고 "이 파일 형식은 열 수 없습니다" 알림(`formatNotOpenable`)을 띄운다. 무거운 편집기는 처음 쓸 때 불러오는 덩어리(동적 `import`)로 둔다(앱 시작 크기를 늘리지 않게). 불러오기는 `open()` 안에서 하거나, Workspace 안에서 `React.lazy`를 쓰면 그 Workspace 안에 `Suspense`를 둔다(App은 `Suspense`로 감싸지 않는다). 읽기 전용 종류는 `editable: false`로, 저장·복구 사본 함수를 두지 않는다. AI가 없으면 `hasAi: false`.
- **문구**: `i18n/<트랙>/<언어>.ts`(22개 언어, `zh`가 키를 정함). 키 앞머리는 `sheets…`·`pdf…`(`pdfTools…`로 시작하지 않게)·`pdfTools…`·`web…`·`readers…`·`home…`·`ai…`(기본 사전의 `ai…` 키와 같은 이름 금지). 겹침은 `tests/i18n-bundles.test.ts`가 잡는다. 기본 사전(`i18n/<언어>.ts`)과 `strings.ts`에는 더하지 않는다.
- **다리**: `@genoffice/mobile-bridge/<트랙>`(`src/<트랙>/index.ts`)에 자기 명령 감싸개를 `invokeMobileCommand(client.transport, …)`로 만든다. `MobileClient`는 넓히지 않는다.
- **Rust 명령**: `src-tauri/src/commands/<트랙>.rs`. 하위 모듈은 `commands/<트랙>/` 폴더에(`lib.rs` 머리의 `pub mod`를 고치지 않게). T1은 `src/sheets/`도 쓴다. `cargo fmt`를 크레이트 전체에 돌리지 않는다(기존 파일들이 rustfmt 모양이 아니라 다른 줄까지 바뀐다).
- **아이콘**: `components/icons/<트랙>.tsx`(`sheets`·`pdf`·`pdfTools`·`web`·`readers`·`home`·`ai`). 선 아이콘은 `components/icons/svgIcon.tsx`의 `SvgIcon`으로 그린다(`MobileIcons.tsx`에서 가져오지 않는다 — 서로 물린다). 파일 형식 그림은 그 파일의 `<이름>DocTypeIcons` 지도에. 편집 도구 막대 단추의 아이콘은 `EditorQuickActionItem.icon`으로 넘긴다(`EditorShell.tsx`를 고치지 않는다).
- **설정**: 절마다 파일(`settings/sections/*.tsx`). AI 절(`AiSection.tsx`의 `AiEnabledRow`·`AiSection`·`AiStorageRows`)은 T7, 나머지(`GeneralSection`·`BackupsSection`·`StorageSection`, `SettingsScreen.tsx`, 기본값 `settings/defaultPrefs.ts`)는 T6. T7은 설정 기능을 `ai/settingsSlot.ts`의 `MobileAiSettingsSlot`과 `useMobileAi`로 늘린다.
- **홈**: `home/homeTabs.ts`(탭 목록, 지금은 `HOME_TABS_ENABLED = false`), `home/ToolsTab.tsx`(T3), `home/FoldersTab.tsx`(T6), 들어온 문서 `home/incoming.ts`(T6). 홈 화면과 탭은 `home/homeHost.ts`의 `HomeHost`(문서 열기, `createNew`, 알림, 홈 새로 읽기, 설정 열기)로 앱에 부탁한다.
- **AI**: AI 실행·대화·AI 창·설정 값은 `ai/useMobileAi.ts`(T7). 편집기 트랙은 자기 종류의 `createAiRun`만 만든다.
- **문서마다 다른 것**: 열린 문서(`EditorDocument`)가 `editable: false`(이 문서만 읽기 전용, 보기 모드로 열림)·`aiAvailable: false`(이 문서에서는 AI 진입점 숨김, 예: 편집·복사가 금지되거나 읽을 수 없는 보호 문서. 단, 암호를 풀어 연 PDF는 PC와 같이 읽기 전용 AI를 허용)를 낼 수 있다. 문서를 닫거나 다른 문서로 바꿀 때 앱이 `dispose()`를 부른다(엔진·임시 파일 정리). `open()`이 준비한 것을 쓰기 전에 전환이 취소되면(저장 안 함 확인에서 취소) `EditorOpened.discard()`를 부른다. `open()` 안에서 사람이 취소하면(예: 암호 창) `USER_CANCELLED`를 던지면 앱이 조용히 넘긴다. `EditorOpened.encrypted`는 "보호된 문서라 고칠 수 없음"(한글 규칙)이라, 풀어서 고칠 수 있는 문서는 켜지 않는다.
- **빌드 설정**: Vite 플러그인·가져오기 별칭(PC 전용 모듈의 모바일 대역 등)·`define`·Vitest 준비 파일은 `config/tracks/<트랙>.ts`(`sheets`·`pdf`·`pdfTools`·`web`·`readers`·`home`·`ai`)의 `TrackBuild`에 둔다. 묶음과 시험이 모두 읽는다(`vite.config.ts`·`vitest.config.ts`·`tsconfig.json`은 고치지 않는다). 플러그인은 자기 모듈에만 걸리게 짠다. 다른 편집기의 전역 선언(`env.d.ts`)이 필요하면 `src/env/<트랙>.d.ts`에 `/// <reference path="…" />`로 둔다.
- **S0 시험**(`tests/editor-registry.test.tsx`, `open-gate.test.tsx`, `home-slots.test.tsx`, `i18n-bundles.test.ts`, `native-config-slots.test.ts`, `settings-sections.test.tsx`, `document-lifecycle.test.tsx`, `track-build.test.ts`)은 트랙이 자기 형식·그림·문구·MIME을 더해도 그대로 통과하게 짰다. 트랙은 이 파일들을 고치지 않고, 자기 시험은 새 파일로 둔다.
- `App.tsx`, `shell/**`, `editors/editorKind.ts`·`registry.ts`·`hwpKind.tsx`, 기본 사전·`strings.ts`, `components/MobileIcons.tsx`·`components/icons/index.ts`·`types.ts`·`svgIcon.tsx`, `config/tracks/index.ts`·`types.ts`, `vite.config.ts`·`vitest.config.ts`·`tsconfig.json`은 어느 트랙도 고치지 않는다. 바꿔야 하면 기획에서 까닭과 바꿀 줄을 적고 승인을 받아 따로 커밋한다. 트랙별 계획·결정·발견은 `docs/plans/mobile-v1/<트랙ID>.md`(안내는 `docs/plans/mobile-v1/README.md`).

### T1 엑셀 (1판)

`.xlsx`·`.xlsm`·`.xls`·`.csv`를 열고 고치고 원래 형식으로 저장한다. 문서 엔진(`apps/sheets/native/xlsx-engine`, `packages/xlsx-gateway`)과 PC 엑셀 화면 코드는 고치지 않고 가져다 쓴다. 코드는 `editors/sheets/`(파일별 몫은 그 폴더의 `README-slots.md`), 문구 `i18n/sheets/<구역>/<언어>.ts`(구역 open·grid·toolbar·save·ai), 다리 `@genoffice/mobile-bridge/sheets`, Rust `src-tauri/src/commands/sheets.rs`·`src-tauri/src/sheets/`. 계획·결정·발견은 `docs/plans/mobile-v1/T1.md`.

- **엔진은 따로 빌드한다**(사용자 결정): 엔진 크레이트를 앱 크레이트 의존에 넣지 않는다. `src-tauri/src/sheets/engine-lib/`(자기 `Cargo.toml`·`Cargo.lock`)가 엔진 `main.rs`의 명령 분기를 라이브러리 공개 함수 위에 같은 순서로 다시 짠다. `build.rs`의 `// T1 sheets` 블록이 그것을 자기 작업 공간에서 정적 라이브러리로 빌드하고, `ieum_sheets_engine_*` C 함수만 남겨 붙인다(`sheets/engine_build.rs`). 앱 크레이트는 C 경계(`sheets/engine.rs`)만 본다. 까닭은 둘이다. 엔진의 `zip 9`이 같은 빌드에 들어오면 flate2가 `zlib-rs`로 바뀌어 휴대폰 한글 저장의 압축 바이트가 달라진다(`hwp_and_hwpx_compression_matches_the_app_before_the_engine` 시험이 지킨다). 그리고 엔진 라이브러리는 `panic = "unwind"`로 빌드해 C 경계에서 `catch_unwind`로 받아 **그 요청만** `workbook_error`로 실패시킨다(앱 프로필의 `panic = "abort"`는 그대로). 엔진이 명령을 더하면 `engine-lib/src/dispatch.rs`의 같은 자리에 더한다. 요청·응답 글은 PC 사이드카와 키 순서까지 같아야 한다. 하나만 다르다. 외부 연결이 가리키는 다른 파일을 읽거나 있는지 보는 `update_external_links`·`read_external_links`는 휴대폰 분기가 `invalid_request`(`EXTERNAL_LINKS_NOT_READ`)로 거절한다(스펙 2.1, 저장된 마지막 값만 보인다). 목록만 읽는 `list_external_links`는 그대로다. PC 비교 시험은 이 둘을 보내지 않는다.
- **작업 폴더는 앱 캐시의 `ieum-tmp/sheets/`**(T6과의 약속): 작업 사본·변환 사본·암호를 푼 평문·저장 중간 파일이 모두 여기 있고, 엔진 세션 캐시는 `ieum-tmp/sheets/engine/`(Android `TMPDIR`)이다. 앱이 시작할 때 비운다. 웹뷰가 부르는 파일 명령(`mobile_sheets_temp_*`)은 작업 폴더 밖과 `engine/`을 가리키지 못하고, 엔진·암호 요청의 경로는 작업 폴더 밖을 가리키지 못한다(`engine-lib/src/path_guard.rs`, `engine/`은 빼지 않음). 아직 없는 경로(저장 대상 등)는 그 위로 가장 가까운 있는 폴더를 실제 경로로 풀어 작업 폴더 안인지 본다. 작업 폴더 안의 링크를 거쳐 밖으로 나가는 대상을 막는다. 다시 켠 뒤에도 남아야 하는 파일은 여기 두지 않는다. iOS는 엔진 세션 캐시가 샌드박스 tmp에 생긴다(`TMPDIR`을 바꾸면 WebKit까지 바뀌어 바꾸지 않음).
- **종류와 열기**: 종류 하나(`kind.ts`, `id: 'sheets'`, `createFormats: ['xlsx']`, `recoveryFormat`은 늘 `xlsx`)는 가볍게 두고, 무거운 것은 `open()`(`open/openDocument.ts`)과 Workspace의 격자 덩어리에서 불러온다. 열기 순서는 선택 창의 파일을 작업 폴더로 복사(연 때의 스냅숏, 저장의 바탕) → 암호 확인 → `.xls`·`.csv`는 PC 방식 그대로 임시 `.xlsx`로 변환(`convert/`) → 엔진 세션이다. 큰 파일은 여는 동안 진행 문구를 보인다. 매크로 문서와 외부 연결이 든 문서는 열 때 알림을 한 번 띄운다. App이 문서로 바꾸지 않으면 `discard()`, 닫거나 다른 문서로 바꾸면 `dispose()`가 정리한다. 저장할 때마다 엔진 세션이 저장한 파일의 새 세션으로 바뀌므로, 문서가 연 엔진 세션에는 주인 표시(`MobileWorkbookSession.owner`)가 붙고 저장이 새 세션에 그대로 옮긴다. 닫기는 그 표시가 붙은 세션을 모두 닫고 작업 사본·열 때 만든 파일을 지우고 암호를 버린다(`forgetWorkbookPassword`). 저장이 도는 중에 닫히면 그 저장이 바꿔 넣은 세션도 닫는다. 그래서 문서를 닫으면 엔진 세션 목록이 비고, 다음 열기가 작업 폴더를 다시 비운다.
- **암호 문서**: `msoffice-crypto =0.1.0`(`legacy-binary`)과 CFB FAT 보정(`engine-lib/src/cfb_fat.rs`)을 엔진 라이브러리 쪽에 두어 앱 크레이트 의존에 섞지 않는다. 보정은 PC의 officecrypto-tool이 쓴 파일을 Rust `cfb`가 "Malformed FAT"로 거부해서 필요하다. 판을 바꾸면 `engine-lib/src/crypto_tests.rs`의 PC 왕복 시험 묶음을 다시 돌린다. 풀기·잠그기는 작업 폴더 파일에서 파일로 하고, 평문은 웹뷰로 가지 않는다. 암호가 틀리면 다시 묻고, 취소는 `USER_CANCELLED`다. 풀어 연 문서는 `EditorOpened.encrypted`를 켜지 않는다(그 표시는 "고칠 수 없음"이다). 고칠 수 있고 AI도 쓰지만 복구 사본은 쓰지 않으며, 저장·공유는 같은 암호로 다시 잠근 파일만 내보낸다. ODS는 PC처럼 거절한다.
- **PC 모듈은 그대로 가져다 쓴다**: 격자 불러오기(`univer-sync`), 편집 기록(`edit-journal`), 리본 명령(`ribbon-actions`의 `handleRibbonCommand`), 저장(`save-actions`의 `handleSave` 등), 인쇄 HTML, AI 도구가 모두 PC 파일 그대로다. `WorkbookVisuals.tsx`에 닿는 PC 모듈은 모바일 타입 설정에서 TS2783이 나서 `import.meta.glob`으로 묶고 형을 손으로 적었다(`grid/pcGridModules.ts`, `journal/pcJournalModules.ts`, `toolbar/pcToolbarModules.ts`, `ai/pcAiModules.ts`, `pdf/pcPrintModules.ts`). PC가 내보내지 않아 **다시 적은 곳**은 PC 글이 바뀌면 실패하는 요약값 시험이 지킨다. `App.tsx`의 `openLazyWorkbook` 첫 상태(`grid/lazyWorkbook.ts`), 편집 기록 수신기 둘(`journal/editJournal.ts`, `sheets-pc-journal-modules.test.ts`), `runUiOps`·`opExecutorContext`·`ribbonContext`·재계산 분기(`toolbar/runRibbon.ts`)와 `lazy-find`의 모두 바꾸기(`toolbar/find.ts`, 둘 다 `sheets-toolbar-pc-modules.test.ts`), `sheets-main.ts`의 `writeWorkbookTo`(`save/writeWorkbookTo.ts`, 본문 글자까지 같음, `sheets-save-write-workbook-to.test.ts`)가 그렇다. 시험이 실패하면 PC 변경을 옮겨 적은 뒤 요약값을 바꾼다. PC 파일은 고치지 않는다.
- **편집 기록**: 격자·도구 막대·AI는 Univer 명령만 보내고, PC 편집 기록이 그것을 받아 저장 요청에 넣는다. 그래서 새 기능은 PC가 보내는 것과 같은 명령을 보내면 저장까지 따라온다. 휴대폰에 화면이 없어 뺀 PC 동작(차트 실시간 갱신, 시트 복제 등)은 `journal/editJournal.ts` 머리와 `README-slots.md`에 있다.
- **보기 모드는 고치지 않는다**: 칸 편집 시작은 `BeforeSheetEditStart`에서 막는다(두 번 누르면 편집 모드로 바꾼다). 그 밖의 길(칸 길게 누르기 메뉴, 태블릿 키보드 단축키, 채우기 손잡이, 범위 끌기, 칸 안의 필터·유효성 단추)은 `grid/viewModeGuard.ts`가 막는다. 보기 모드에서는 Univer의 길게 누르기 메뉴를 끄고, 편집 기록이 기록하는 변경(`journalListensTo`)은 무엇이 보냈든 취소한다. 불러오기 쓰기(`journalSuppression`)·수식 결과(`fromFormula`)·확대·틀 고정은 지나간다. 되돌리기·다시 하기는 AI 창의 한 번 되돌리기(`withAiUndoPass` 안에서 보낸 것)만 지나간다. 태블릿 키보드의 Ctrl+Z·Ctrl+Y 같은 나머지는 명령 단계에서 취소해 되돌리기 목록이 움직이지 않는다. 새 되돌리기 길을 더하지 말고, AI 말고 보기 모드에서 되돌려야 할 것이 생기면 이 규칙을 먼저 고친다. 새 편집 길을 더하면 편집 모드에서만 보이게 둔다.
- **격자 손짓**(`grid/gestureLayer.ts`, 잡기 단계에서 먼저 본다): 누르기는 10px·350ms 안, 두 번 누르기는 사이 300ms·24px 안, 길게 누르기는 500ms다(`grid/gestureJudge.ts`, 실기기를 보고 고칠 값). Univer는 빠르게 두 번 밀어도 두 번 클릭으로 읽어서, 판정이 두 번 누르기라고 한 것만 편집을 연다. 머리글 길게 누르기는 편집 모드에서만 우리 줄 메뉴(`HeaderMenuSheet`, PC 머리글 메뉴의 명령)를 연다. 화면 가장자리 24px 안에서는 손잡이를 잡지 않고, 그 밖에서는 손잡이가 틀 고정 경계선보다 앞선다. 두 손가락 확대는 우리 층(`grid/pinchZoom.ts`)이다. 시트 바꾸기는 Univer 시트 막대 대신 `SheetSwitcher`이고, 새 시트는 화면 언어와 상관없이 `Sheet1`을 잇는다. 틀 고정은 더 보기 → 보기에 있다. 키보드 보조 막대(`FormulaKeyboardBar`)의 단추는 `pointerdown`을 막아 초점을 지키고, 한글 조합이 끝난 뒤 명령을 보낸다. 가상 키보드는 칸을 고칠 때만 뜬다(`grid/keyboardHold.ts`). Univer는 칸을 고르기만 해도 숨은 칸 입력에 초점을 주는데(하드웨어 키보드로 바로 치게), 휴대폰에서는 그 초점이 키보드를 올린다. 그래서 편집 밖의 그 초점에는 `inputmode="none"`을 걸고(초점과 하드웨어 입력은 그대로), 칸 편집이 시작되면 떼고 다시 초점을 준다. 통합 문서를 (다시) 여는 동안에는 그 초점을 아예 거둔다(`.xls`의 다른 이름으로 저장 뒤 등).
- **도구 막대는 PC 리본 글을 보낸다**: 묶음 단추([셀 서식][행·열][정렬·필터][삽입])의 항목(`toolbar/groups.ts`)은 PC 리본이 보내는 명령 글(`bold`, `fill:#RRGGBB`, `insert-row-here`, `sort:asc` …)을 PC `handleRibbonCommand`로 그대로 보낸다. 기능을 더할 때 Univer를 직접 부르지 않고 PC 명령 글로 항목을 더한다. 차트·피벗·조건부 서식은 보기만이고 편집 명령이 없다. PC 상태 표시줄 글은 알림으로 띄우되, 진행·확인 줄(스트리밍, 색인, 재계산 대체, "적용했습니다")은 띄우지 않는다(`journal/statusLines.ts`의 PC 키 목록). 거절과 오류는 띄운다.
- **저장은 PC와 같은 순서다**(`save/saveWorkbook.ts`): 연 때의 스냅숏에서 패치한 새 파일을 만들고(`writeWorkbookTo` → `saveWorkbookViaSidecar`, `assertManifestPreserved`가 계획에 없는 항목을 거절), 엔진으로 다시 열어 확인한 뒤에만(휴대폰의 짧은 날짜 모양을 넘김) 원본이나 다른 이름으로 저장의 새 문서에 쓰고, 세션을 결과로 바꾼다. 확인이나 쓰기가 실패하면 원본과 세션은 그대로다. 바뀐 것 없는 저장은 엔진을 거치지 않고 스냅숏 바이트를 그대로 쓴다(빈 계획도 엔진을 거치면 `xl/workbook.xml`이 바뀐다). Rust가 원본의 SHA-256을 연 때와 비교해 다른 앱이 바꿨으면 거절한다(`mobile.sheets.diskChanged`, 자기가 쓴 결과는 새 바탕). `.xls`·읽기 전용·제목 없음·되살린 문서는 `원래이름.xlsx`(매크로는 `.xlsm`)를 채운 다른 이름으로 저장이고, 원본 `.xls`는 어느 길로도 쓰지 않는다. `.csv`는 저장마다 CSV·엑셀·취소를 묻는다. CSV를 고르면 격자의 CSV 글을 먼저 만들고, 세션의 `.xlsx`에 편집을 넣은 뒤, 마지막에 원본에 쓴다. 그래서 앞 단계가 실패하면 원본은 그대로이고, 마지막 쓰기가 실패하면 그 까닭을 알리고 문서는 "저장 안 됨"으로 남는다. 읽기 전용·다른 앱에서 받은 `.csv`(그리고 저장소가 제자리 쓰기를 거절한 경우)는 CSV를 새 파일로 내보낸다(PC CSV 내보내기). 암호 문서는 쓰기 전에 같은 암호로 다시 잠근다. 약 14MB 넘는 파일의 쓰기는 T6 부품의 한도로 실패하고, 그때 "너무 커서 쓸 수 없음, 원본은 그대로"라고 알린다(T1 쪽 상한은 두지 않는다). 한 문서에 저장 일은 한 번에 하나다. 엔진 오류 문장은 PC `localizeSaveError`로 번역한다. 저장 중 앱이 내려가거나 끝나도 원본은 그대로이거나 확인을 마친 결과다. Rust는 원본을 읽을 때 본 것(`DocumentMark`: 이름이나 내용이 `.xls`인지, 엔진 라이브러리 `probe`로 암호가 걸렸는지)을 문서 세션마다 기억하고 마지막 방어선으로 쓴다. `.xls` 원본에 쓰기는 거절하고(`mobile.sheets.legacyOriginal`), 암호 문서는 잠기지 않은 통합 문서(ZIP)를 원본·다른 이름으로 저장·공유로 내보내지 못하며(`mobile.sheets.notLocked`, 사람이 고른 CSV·PDF는 지나감) 복구 사본을 쓰지 못한다(`mobile.sheets.noRecoveryForLocked`, 그래서 복구 명령은 문서 세션 id도 받는다). 다른 이름으로 저장한 새 문서는 암호 표시를 이어받는다.
- **내보내기·공유·복구 사본**: 다른 이름으로 저장과 공유는 PC `sheetsSaveAsFilters`의 모양(엑셀 원래 형식, CSV 지금 시트, ODS 사본, PDF 지금 시트)을 내놓는다. 매크로 문서에는 CSV가 없다. CSV·ODS·PDF는 사본만 쓰고 세션·저장 안 된 편집·복구 사본은 그대로다. 큰 바이트는 다리에 base64로 싣지 않고 작업 폴더 파일(4MB 조각)로 Rust에 넘긴다. 공유는 바뀐 것이 없으면 원본 파일을 보낸다. 복구 사본은 공용 타이머가 부르면 저장과 같은 길로 만들고, `.xls`·`.csv` 세션은 `이름.xlsx`로 되살아난다. 암호 문서는 쓰지 않는다.
- **PDF**(`pdf/`): PC 인쇄 HTML을 PC 함수 그대로(`planPrintPages`·`layoutSheetPrint`·`assemblePrintHtml`) 만들고, 스크립트 없는 숨은 iframe에 배치한 상자를 pdf-lib로 벡터 PDF에 옮긴다(8쪽씩). 글꼴은 묶어 둔 열린 글꼴을 PC 글꼴 이름으로 쓴다. Carlito(Calibri), Liberation Sans(Arial), Caladea(Cambria), Liberation Serif(Times New Roman), Liberation Mono(Courier New), 한글은 KS X 1001 2,350자 글꼴이다. 그림·차트가 빠지거나 그 밖의 글자가 빈 상자로 나오면 만든 뒤 한 번 알린다. 네이티브 인쇄는 쓰지 않는다.
- **AI**(`ai/`, 처음 쓸 때 불러오는 덩어리): PC 엑셀의 통합 문서 스킬(`createWorkbookSkill`)만 그대로 내놓는다. 휴대폰 제한은 `ai/phoneLimits.ts` 한 곳에 있다. `create_document` 도구를 빼고, 그림·차트·도형·스파크라인·피벗·조건부 서식·시트 복제 연산은 계획 전에 거절하고, 모델에게 한 줄로 알린다. 편집 도구 목록은 PC 도구의 `mutated: true`에서 나온다(`propose_operations`). 되돌리기는 PC `ai-run-receipt` 판정이고, 고친 칸 표시는 화면 전용이다. 휴대폰 `desktopApi`는 그림 읽기를 거절한다(`desktop-api/ai.ts`). PC의 개인정보 열 정책(`apps/sheets/src/ai/privacy-policy.ts`)은 PC도 부르지 않으므로 휴대폰도 부르지 않는다. AI 진입점·창·설정은 T7이 맡고, 꺼져 있으면 자리째 없다.
- **빌드 자리와 전역 선언**: 게이트웨이의 저장·가져오기 파일과 PC `legacy-import.ts`가 부르는 `node:fs`·`fs/promises`·`os`·`path`·`crypto`·`jszip`은 `config/tracks/sheets.ts`의 플러그인이 휴대폰 대역(`editors/sheets/node-shims/`, 작업 폴더 위의 가상 파일 층)으로 바꾼다. 그 importer에만 걸리게 좁혀 두었으니 다른 모듈로 넓히지 않는다. 대역은 경로를 POSIX(`/`)로 다룬다. PC 엑셀 화면의 전역 선언은 `src/env/sheets.d.ts`가 `/// <reference>`로 읽는다.
- **시험**: apps/mobile의 `npx vitest run tests/sheets-*`(실제 Univer·PC 모듈·게이트웨이를 돌리는 무거운 시험은 시간 제한을 적어 두었다), `packages/mobile-bridge`의 `sheets` 시험, `cargo test --offline --locked --manifest-path apps/mobile/src-tauri/Cargo.toml`(엔진 왕복·패닉·작업 폴더·저장·한글 압축 동일), 엔진 라이브러리 자체의 `cargo test --locked --manifest-path apps/mobile/src-tauri/src/sheets/engine-lib/Cargo.toml`(PC 사이드카와 같은 응답, 암호 왕복). 느린 디스크의 시간 초과는 그 파일만 다시 돌려 가린다. 브라우저 미리보기에서는 PC 사이드카 실행 파일이 엔진을 대신한다.
- **1판에 없는 것**: 칸 길게 누르기 메뉴를 우리 시트로 바꾸기(지금은 Univer 시트, 편집 모드에서만), 차트·피벗·조건부 서식·그림·도형 편집, 시트 복제, 테두리 색 고르기, 사용자 정렬 창, 칸 넣기 창, 행 높이·열 너비 창(머리글 메뉴의 크기 입력과 자동 맞춤은 있음), 큰 시트 필터(PC `large-filter`), PC의 파일·병합·검색·그림 AI 스킬과 사용자 스킬, 약 14MB 넘는 파일의 저장·공유(T6 부품이 바뀌면 갈아탐), iPhone 실행 확인.

### T2 PDF (1판)

PDF 보기·주석·그리기·서명·양식·글자 넣기와 고치기·쪽 작업·링크·AI(읽기·주석·양식·쪽). 계획과 결정 후보는 `docs/plans/mobile-v1/T2.md`.

- **저장은 PC 코드 그대로**: 저장 본체는 PC `apps/pdf/src/main/save-pdf.ts`와 그것이 부르는 파일(`pdf-crypt.ts`, `text-edit.ts`, `annot-flatten.ts`, `annot-strip.ts`, `blank-pdf.ts`)이다. **PC 파일을 고치지 않고** 불러 쓴다. PC 전용 이름(`fs`, `crypto`, `zlib`, `module`, `path`, `os`, `process`, `buffer`, `electron`)은 `editors/pdf/engine/node-shims/`의 대신 부품으로 돌린다(`engine/build/nodeShimPlugin.ts`, 걸리는 곳은 `apps/pdf/src/main`·`packages/font-metrics`·`packages/electron-utils`에서 오는 import뿐). 파일 읽기는 가상 파일 표(PDFium·harfbuzz WASM, 앱 글꼴)이고, 쓰기는 저장 결과를 받는 메모리 자리(`/ieum-mobile/save-sink`) 밖에서는 오류다. 저장 계산은 웹 워커(`engine/worker.ts`, ES 모듈 워커)에서 하고 PDFium은 필요한 요청에서만 싣는다. 같은 원본·같은 요청·같은 바깥 입력(시각·난수·글꼴)이면 PC와 바이트가 같아야 한다 — `tests/pdf-engine-parity.test.ts`가 대신 부품 없는 Node 실행과 비교한다. 빌드 설정은 `config/tracks/pdf.ts`(대신 부품, 워커 설정, PDF.js 자산 `dist/pdfjs`), 전역 선언은 `src/env/pdf.d.ts`.
- **글꼴**: 휴대폰에는 설치 글꼴이 없어 앱 글꼴 셋만 쓴다. PC 편집 글꼴 id는 그대로 두고 뜻만 바꾼다(`arial`→GenOffice Sans KR, `times`→Serif KR, `courier`→Gothic KR, 대체 글꼴 첫 경로도 Sans). 흔한 한글 2,350자·영문·숫자만 그리므로, 그리지 못하는 글자는 넣기 전에 막고 문서 글꼴이 모자라 앱 글꼴로 바뀌면 알린다.
- **구조**: 종류 `editors/pdf/kind.ts`(가벼움, 화면은 `open()` 안 동적 import) → 보기 `view/`(PDF.js, 이어 넘기기, 보이는 쪽 ±1만 그림, 찾기·목차·링크, 암호 시트) → 편집 틀 `edit/`(PC `edit-ops` 연산과 되돌리기, `SavePdfRequest` 만들기, 저장·다른 이름으로 저장(주석 그대로·굽기·빼기)·공유·복구 사본) → 기능 `features/<annot|draw|sign|form|text|pages|link>/`(각자 `PdfFeature` 하나, 쓰기는 `services.dispatch`만) → AI `ai/`(PC `pdf-skill.ts`의 `surface: 'mobile'`). 편집 막대는 [펜][형광펜][글상자][서명]·[AI]이고, 쪽 정리·링크 넣기·체크 표시는 [⋯]에 있다.
- **지킬 것**: 고친 것이 없으면 쓰지 않는다(원본 바이트 그대로). 주석 굽기·빼기는 다른 이름으로 저장에서만, 암호 문서의 사본은 늘 그대로 두기. 암호 문서는 복구 사본을 쓰지 않는다. 읽기 전용(권한·손상·쓸 수 없는 파일)은 `editable: false`, `encrypted`는 권한 때문에 읽기 전용인 암호 PDF에만. 다른 PDF에서 쪽 가져오기는 확인을 받고 먼저 저장한 뒤 파일에 바로 쓴다. 파일 고르기는 웹뷰 파일 입력이다(`pickOpenFile`을 쓰면 열린 세션이 바뀐다). 열린 글상자는 저장·공유 전에 확정한다(`services.registerDraft`). 펜을 한 번 쓰면 펜은 그리고 손가락은 화면을 옮긴다(`features/draw/penInput.ts`, 기기에 기억, 스위치로 손가락도 그림). AI 도구는 15개만 내놓고 `apply_ops`는 정한 13개 연산만 받는다.

### T3 PDF 도구 (1판)

PC "PDF 도구"의 1판 묶음(병합·분할·추출·역순·모두 회전·빈 페이지 찾아 지우기·이미지로 PDF·텍스트로 저장·용량 줄이기·암호 걸기·풀기·파일 복구·주석 한꺼번에 지우기)과 "편집·서명" 카드. 계획·약속은 `docs/plans/mobile-v1/T3.md`.

- **처리 코드는 PC와 같은 것**: `@genoffice/pdf-ops`(`packages/pdf-ops`)를 쓴다. 원본 GenOffice와 함께 쓰는 `apps/pdf/src/main/save-pdf.ts`·`read-text.ts`의 함수(병합·추출·회전·쪽 지우기·텍스트 읽기)는 pdf-ops의 거울 함수(`mirrorPageEngine`)로 부르고, 시험이 PC 원래 함수와 같은 바이트를 지킨다. 모바일 코드는 `apps/pdf/src/main/**`·`apps/shell/**`를 가져오지 않는다(시험이 지킴). 화면(`tools/` 엔진 밖)은 pdf-lib 없는 진입점(`@genoffice/pdf-ops/tool-ids`·`/tool-rules`·`/split-plan`·`/page-range`)만 가져와 pdf-lib이 화면 덩어리에 들어가지 않는다.
- **엔진**(`tools/engine/`): ES 모듈 Web Worker 하나에서 한 번에 작업 하나. `createPdfToolsEngine()`의 `inspect`·`run`·`findBlankPages`·`zip`·`stop`·`dispose`. PDFium·qpdf wasm은 앱 묶음의 자산 주소에서 처음 필요할 때만 불러온다(네트워크 없음). 입력은 하나씩 읽어 넘겨준다(복사하지 않음, `readBytes`는 부를 때마다 새 배열). [멈추기]는 워커를 끝낸다. 메모리 부족(워커 오류·`RangeError`)은 "이 기기에서 처리하기에 너무 큼"으로 알리고 고정 상한은 두지 않는다. 용량 줄이기·사진 JPEG 바꾸기는 워커의 `OffscreenCanvas`, 없으면(iOS 15~16.3) 화면 스레드의 `<canvas>`로 한다. 암호 걸기에서 막기를 고르지 않을 때의 주인 암호는 `crypto.getRandomValues` 32바이트.
- **화면**(`tools/`): `ToolsList`(홈 [도구] 탭 안, `home/ToolsTab.tsx`)와 전체 화면 `PdfToolsFlow`(`tools/link.ts`, 시작은 `menu`·`merge`·`imagesToPdf`·`tool`). 단계: 도구 → 파일(`<input type="file">` 시스템 선택 창, 권한 창 없음) → 옵션 시트(`tools/options/`, PC 창과 같은 기본값·문구) → 처리(막대·[멈추기], 처리 중 뒤로 가기는 확인 창) → 결과 시트. 빈 페이지는 찾기 → 축소판 검토(`tools/blank/`) → 지우기. 층마다 `useBackLayer`.
- **결과**: 메모리에만 둔다. [열기]는 `HomeHost.openUntitledCopy`(T6)로 이름 없는 문서로 열고, 그 함수가 없거나 그 확장자를 여는 편집기 종류가 없으면 숨긴다. [공유]·[다른 곳에 저장]은 `@genoffice/mobile-bridge/pdf-tools`(`sharePdfToolResult`, `savePdfToolResultCopy` → Rust `mobile_pdf_tools_share`·`mobile_pdf_tools_save_copy`, `commands/pdf_tools.rs`)로, 열린 문서 세션·최근 목록·복구 사본을 건드리지 않는다(PDF·텍스트·ZIP만). 분할처럼 여러 파일이면 조각마다 + "ZIP 하나로 모두". 저장도 공유도 안 한 결과를 버리기 전에 한 번 묻는다. 결과 이름은 PC 규칙 그대로(`원본-merged.pdf` 등).
- **암호 칸**은 `type="password"`·`autocomplete="off"`, 실행이 끝나면 비운다. 암호는 로그·오류·알림에 싣지 않는다.
- **문구**: `i18n/pdfTools/`. 도구 이름·설명·선택지·오류는 PC 도구 창 문구(`apps/shell/src/renderer/src/i18n/pdf-tools/`)를 그대로 가져온다(`tests/pdf-tools-i18n.test.ts`가 같음을 지킴). PC 전용 문장은 가져오지 않는다.
- **빌드**: `config/tracks/pdfTools.ts`는 워커 형식(`worker.format: 'es'`)만 정한다(`worker.plugins`는 다른 트랙 것). `src/env/pdfTools.d.ts`는 두 wasm의 `?url` 선언.
- **시험**: `tests/pdf-tools-engine.test.ts`(Node에서 실제 wasm으로 도구마다, PC 경로와 같은 바이트), `pdf-tools-engine-client.test.ts`(가짜 워커), `pdf-tools-flow.test.tsx`, `pdf-tools-options.test.tsx`, `pdf-tools-screen-fixes.test.tsx`, `pdf-tools-i18n.test.ts`, 다리 `packages/mobile-bridge/tests/pdf-tools.test.ts`(Rust 명령 인자 이름·등록과의 대조 포함). 엔진 시험은 화면 쪽(`tools/**`, `home/ToolsTab.tsx`)이 pdf-lib·PC 앱을 가져오지 않는지도 본다. PC 쪽은 `apps/shell/tests/pdf-tools-golden.test.ts`(PC 결과 기준선, 표는 고치지 않음).

### T4 HTML·마크다운 (1판)

HTML 보기·소스·글 고치기·지우기·AI·숨기기·워드·ODT 내보내기, 마크다운 바이트 그대로 저장·찾아 바꾸기·워드·ODT 내보내기·AI 숨기기. 계획과 결정 후보는 `docs/plans/mobile-v1/T4.md`.

- **구조**: 종류 `editors/html/kind.ts`(가벼움, `open()` 안에서 `htmlDocument.tsx`와 다리를 불러옴) → 문서 `htmlDocument.tsx`(원문·판·되돌리기, Workspace, [⋯]) → 미리보기 `htmlPreview.ts`(요소 지도, 미리보기 사본·내보내기 사본)·`HtmlPreviewFrame.tsx`(틀, 링크·양식 막기, 고름 상자)·`HtmlSourceView.tsx` → 요소 편집 `htmlElementEdit.ts`·`HtmlTextEditSheet.tsx` → AI `htmlAi.ts`·`htmlAiLocale.ts`, 숨기기 `htmlHide.ts` → 내보내기 `htmlExport.ts`·`htmlExportDriver.ts`·`htmlExportCaptures.ts`(+ 대역 `html2docxNode.ts`·`html2docxPacker.ts`). 마크다운은 `editors/markdownKind.tsx`·`MarkdownMobileEditor.tsx`·`markdownFind.ts`·`markdownFindSheet.tsx`·`markdownHideSheet.tsx`·`markdownOdtConfirmSheet.tsx`·`markdownToHwp.ts`(docx 단계 `markdownToDocx`를 한글·워드·ODT가 함께 씀). 다리 `packages/mobile-bridge/src/html/`(겉봉 `text-envelope.ts`, 세션별 겉봉 기록 `text-sessions.ts` — 마크다운도 씀, HTML 문서 `html-document.ts`, `saveNewFile`)와 `src/markdown/`(`index.ts` 스킬, `redaction.ts` 숨김). Rust `commands/html.rs`. PC 코드(`apps/html/src/renderer/document/`·`preview/`·`ai/`, `apps/markdown`, `packages/file-parse/src/markdown-redaction.ts`)는 상대 경로로 가져다 쓰기만 하고 고치지 않는다.
- **틀은 `sandbox="allow-same-origin"`만**(`PREVIEW_SANDBOX`, 내보내기 드라이버도 같은 값). `allow-scripts`는 어디에도 두지 않는다. 틀에 넣는 것은 미리보기 사본(요소 번호 `data-gx-sid`, `<head>` 처음의 CSP meta `script-src 'none'` 등, `meta refresh` 무력화)이고, PC `instrument.ts`가 붙이는 검사기 `<script>`는 뺀다. 미리보기·내보내기 사본은 저장·공유·복구 사본·AI에 쓰지 않는다. 틀 안 고르기·링크 막기는 부모가 틀 문서에 붙인 처리기로 한다. 고름 상자와 숨긴 요소 표시는 틀 위 겹침 층에 그리고 틀 문서는 바꾸지 않는다. http(s) 자원은 불러오고(Q4) 상대 경로 자산은 안 보인다.
- **편집은 모두 Patch 하나**: 글 고치기(`set_text`·`set_text_node`), 지우기(`remove`, `<html>`·`<head>`·`<body>` 거절), 숨기기·숨김 풀기, 소스 고침(원문 전체 바꾸기 하나), AI의 `apply_ops`가 모두 `htmlDocument.tsx`의 `applyPatches` 하나를 지난다(PC `ops.ts`의 `compileOps` → `patch.ts`). 원문을 파싱해 다시 쓰지 않는다. 고름은 시작 태그 위치 + 태그로 들고 Patch를 따라 옮긴다. 원문 범위에 태그 모양이 든 글 조각과 원문 글 요소(script·style 등)·빈 요소는 "소스에서 고치세요"로 보낸다.
- **겉봉과 바이트**: 읽을 때 BOM·줄 끝을 세션별로 기억하고(`parseTextEnvelope`), 저장·다른 이름으로 저장·공유·복구 사본 때 다시 입힌다(`serializeTextEnvelope`). 본문이 연 때와 같으면 연 때 받은 바이트를 그대로 쓴다. 섞인 줄 끝은 안 고쳤을 때만 바이트 그대로이고 고치면 많은 쪽으로 맞춘다(PC 규칙). UTF-8이 아니면 `editable: false` + 알림 띠, 공유는 원본. `markdown-adapter.test.ts`가 고정한 함수 모양(`readDocument(session) → { text }` 등)은 그대로다.
- **내보내기는 새 파일 명령**: `mobile_web_save_new_file(suggested_name, mime, bytes_base64) → { name }`(다리 `saveNewFile`). MIME은 docx·odt·hwpx 셋만. 저장 창과 `write_uri_bytes_atomic`만 쓰고 열린 세션·최근 목록·복구 사본·바뀜 상태를 건드리지 않는다(공용 `mobile_save_as_file_bytes`를 쓰면 Rust 쪽 열린 문서가 바뀐다). 마크다운 한글·워드·ODT와 HTML 워드·ODT가 모두 이 길이고, 알림에 [열기]는 없다. ODT는 docx를 `docxToOdt`로 바꾸고 `report`가 있으면 확인 시트. 변환기는 처음 쓸 때 불러오는 덩어리다.
- **숨긴 글은 모델에 가지 않는다**: 마크다운 span 모양은 PC와 같다(`<span class="redact-span" data-redaction="" data-label="…">`). 모델이 보는 글(`redactedMarkdownView`)은 부를 때마다 만들고 `redactMarkdownSource` 결과와 같을 때만 쓴다. 다르거나 오류면 아무것도 보내지 않고 오류를 던진다(T7 병합 전에는 보통 `Error`). 모델 편집은 `{{…}}` 목록(문서에 원래 있던 `{{x}}` 글자 포함)이 같은 차례·같은 글이고, 되돌린 원문을 다시 가렸을 때 같을 때만 받는다. 찾아 바꾸기는 표시 태그에 걸친 결과를 건너뛰고, 표시 태그 수를 바꾸거나 표시를 깨는 바꾸기를 거절한다. 미리보기는 숨김 표시를 안의 글로 바꿔 보인다(미리보기에만). HTML 숨김은 PC 규칙 그대로(`data-gx-redact`, PC `buildProjection`·`redact-guard.ts`·`redact-edit.ts`). 숨기기 단추는 `frame.aiEnabled`일 때만.
- **HTML AI 도구는 셋만**: PC `createDocumentSkill`을 감싸 `HTML_MOBILE_TOOLS`(`get_outline`·`read_source`·`apply_ops`)만 내놓고 부른다. PC가 나중에 더하는 도구도 저절로 빠진다. `file://` 그림을 쓰는 `apply_ops`는 PC 코드가 `window.htmlApi`에 닿기 전에 거절한다(`window.htmlApi`는 `src/env/web.d.ts`의 형 선언뿐, 값 없음). 그림 만들기 가용성은 늘 거짓. 한 실행은 실행 전 원문으로 되돌린다.
- **HTML 내보내기 드라이버**(`SandboxFrameDriver`): html2docx의 `BrowserDriver`를 화면 밖 스크립트 없는 틀(`srcdoc`) 위에 구현한다. 추출 코드는 부모에서 `new Function` + `with(틀 전역)`으로 돌리고 타이머는 부모 것을 쓴다(앱에 CSP를 넣으면 `'unsafe-eval'` 필요). 화면 찍기는 없어 부분 그림은 빠지고 알림이 말한다. 보통 `<img>`는 캔버스로 그린다. 찍지 못한 블록은 보이던 글을 남기고, 글도 없으면 `webExportPictureMissing`. `config/tracks/web.ts`의 플러그인 둘: `web-html-ai-locale`(PC HTML 렌더러 파일이 부르는 `i18n/locale`만 `htmlAiLocale.ts`로), `web-html2docx-browser`(html2docx `generate/page-settings.ts`의 `Buffer`·`node:zlib`, `generate.ts`의 `docx` `Packer`만 대역으로, 모양이 바뀌면 빌드 실패). `process.env.H2D_DEBUG_KPI`는 `define`으로 지운다.
- **시험**: 모바일 `tests/web-*.test.ts(x)`(HTML: `web-html-kind`·`-preview`·`-edit`·`-edit-app`·`-ai`·`-ai-hide`·`-export-driver`·`-export-kind`·`-export-chromium`(Playwright의 Chromium이 있을 때만), 마크다운: `web-markdown-bytes`·`-export`·`-export-kind`·`-find`·`-find-sheet`·`-find-kind`·`-hide`), 다리 `tests/web-*.test.ts`(`web-text-envelope`·`web-save-new-file`·`web-html-document`·`web-markdown-hwpx-export`·`web-markdown-redaction`), Rust `commands/html.rs`의 `#[cfg(test)]`(가짜 파일 다리). 웹 빌드는 `npm run studio -w @genoffice/hwp`를 먼저.

### T5 EPUB·PPT 읽기 (1판)

EPUB(`.epub`)과 PowerPoint(`.pptx`)를 **읽기만** 한다(고치기는 2판). 계획·결정·발견은 `docs/plans/mobile-v1/T5.md`.

- **종류**(`editors/readers/index.ts`의 `readersEditorKinds` = `epub/epubKind.tsx`·`pptx/pptxKind.tsx`): 둘 다 `editable: false`, `hasAi: false`, 저장·복구 사본·AI 실행이 없고 공유는 원본 그대로(`mode: 'original'`). 종류 파일은 Workspace·엔진·Konva·PC 코드를 정적으로 가져오지 않는다(앱 시작 덩어리에는 종류·문구·아이콘만). **여는 순서는 한글과 같다**: `open()`은 바이트만 읽고, 엔진은 `start()` 뒤 문서 안에서 돈다. 300ms가 넘으면 쪽 모양 자리표시, 엔진이 거절하면 알림(`readersErr…`) 뒤 `frame.onBack()`(그래서 거절된 파일도 최근 목록에 남는다). 열린 책·덱, `blob:` 주소, 읽던 자리는 문서 객체(`epubReader.ts`, `pptxDocument.ts`)에 있어 설정 화면에 다녀와도 그대로다.
- **엔진과 PC 코드는 고치지 않고 가져다 쓴다.** EPUB은 `@genoffice/epub-engine/core`만(패키지 루트는 번역·Node 모듈을 끌어온다), PC 읽기 순수 함수(`apps/epub/src/renderer/reader/`의 `parseChapter`·`sanitizeTree`·`markBlocks`·`navigation`·`book-search`·`view-prefs`·`preview-pages`·`links`). PPT는 `@genoffice/pptx-engine`(기본 진입점) + `@genoffice/pptx-render`(`buildRenderSlide`, 치수는 추정 `HeuristicMetrics`) + PC 그리기 부품 `apps/slides/src/renderer/SlideThumb.tsx`(Konva, `konva`·`react-konva`). 그림의 JPEG 방향 바로잡기는 PC 메인 쪽 파일 `apps/slides/src/main/jpeg-orientation.ts`를 가져다 쓴다(지금은 가져오기가 없는 순수 함수 — 그 파일에 Node 가져오기가 들어가면 모바일 묶음이 깨진다).
- **PPT 엔진의 Node 대역**(`editors/readers/build/`, `config/tracks/readers.ts`): Vite 플러그인이 **`packages/pptx-engine/src/` 아래 모듈에만** `node:crypto`(sha256 `createHash`·`randomUUID`, `@noble/hashes`)·`node:zlib`·`node:fs`·`node:stream/promises`를 대역으로 바꾸고 `Buffer`(`buffer` 패키지)를 가져오기로 넣는다. 범위는 설치된 패키지의 실제 경로(심볼릭 링크를 푼 경로)로 정한다. 읽기에 쓰지 않는 쓰기 함수는 부르면 "모바일 읽기에서는 쓸 수 없음" 오류다. T2의 PDF 대역과 따로 있다(범위가 겹치지 않음). `src/env/readers.d.ts`가 `bidi-js` 형 선언을 잇는다. `pptx-render`의 작은 선언이 아니라 그 상위 집합인 `pdf2docx`의 선언을 쓴다(T2도 같은 파일을 이어서, 둘이 다르게 선언되면 통합본 형 검사가 깨진다).
- **EPUB 장 그리기**(`epub/chapterView.ts`·`resources.ts`): PC와 같은 정리(스크립트·`on…`·`javascript:`·틀·`<base>` 지움) 뒤, 그림·스타일시트(`<style>`로 넣고 `url()`·`@import`도)·`style` 속성·글꼴을 책 zip 항목의 `blob:` 주소로 바꾼다. 경로는 엔진 `resolveHref`로만 풀고, zip 밖·원격 주소·없는 항목·스크립트 항목은 지운다. 감춘 글꼴은 `readForRendering`으로 풀어 쓴다. CSP는 `MOBILE_FRAME_CSP`(그림·글꼴 `blob: data:`, 스타일 `blob: data: 'unsafe-inline'`, 나머지 `'none'`). 장 틀은 `sandbox="allow-same-origin"`(스크립트 없음)이고 처리기는 부모가 붙인다. 장을 떠나면 그 장 주소를 거둔다(`release`). 찾기 글은 그리는 사본과 같은 정리를 거친 문서의 `buildTextIndex`라 찾은 위치가 틀 안 `rangeOf`와 맞는다.
- **EPUB 화면**(`epub/EpubWorkspace.tsx`·`EpubSheets.tsx`·`epubView.ts`): 쪽 넘기기(기본, PC 미리보기의 단 나누기 + 본문 `transform`)와 이어 읽기, rtl·세로쓰기 책은 넘기는 방향이 반대, `linear="no"`는 건너뜀. 목차·찾기(CSS 사용자 지정 강조)·읽기 설정(글자 크기·줄 간격 PC 단계, 바탕 [앱 따라·밝게·세피아·어둡게], 읽는 모양) 시트. 바탕 색은 PC와 같은 이름·값의 `--epub-*` 사용자 속성(`epubReader.css`). `href`가 있는 요소는 모두 링크로 다뤄 틀이 바깥으로 가지 않는다(WebKit의 MathML 링크). 찾기는 입력이 200ms 멈춘 뒤 시작한다. 바깥 링크는 확인 시트 → T6 다리가 있고 `https:`일 때만 [열기], 늘 [주소 복사]. 고정 배치 책은 한 항목이 한 쪽이고 글자 설정이 꺼진다.
- **PPT 화면**(`pptx/PptxWorkspace.tsx`·`PptxSlide.tsx`·`PptxShow.tsx`·`PptxSlideListSheet.tsx`·`PptxSearchSheet.tsx`·`slideGestures.ts`): 슬라이드 하나를 화면에 맞춰 넘기기(밀기·가장자리·단추), 두 손가락 확대(확대 중 끌기는 옮기기), 노트 칸(넓은 창은 오른쪽), 슬라이드 목록 격자(보이는 칸만 그림), 슬라이드 글·노트 찾기, 전체 화면 발표(숨긴 슬라이드 건너뜀, 끝 화면, 방향 잠금·애니메이션 없음). 그리기 데이터는 1280px 한 폭으로 만들고(PC `FIT_WIDTH`) 지금 슬라이드와 앞뒤만 두며 멀어지면 놓는다(`releaseSlide`). 그림은 슬라이드마다 `blob:` 주소(같은 그림은 개수를 센다)를 그림 지도로 읽어 `SlideThumb`에 넘긴다. EMF·WMF는 바꾸지 않고 빠진 그림으로 보인다. 슬라이드 그림에는 낭독기 이름과 숨긴 글이 붙는다.
- **읽던 자리·읽기 설정**: Rust `commands/readers.rs`(+ `commands/readers/store.rs`)가 앱 데이터 `readers/positions.json`에 문서 열쇠(`docKey`)별 자리와 기기 전체 설정 하나를 원자적으로 쓴다(최근 1,000개, 깨진 파일은 빈 상태로 읽음). 다리 `@genoffice/mobile-bridge/readers`의 `getReaderState`·`setReaderPosition`·`setReaderSettings`, 명령 `mobile_readers_get_state`·`mobile_readers_set_position`·`mobile_readers_set_settings`. 자리는 1초 모아 쓰고 닫을 때 쓴다.
- **T6과 잇는 곳**(`editors/readers/shared/`): 화면 꺼짐 막기는 `useReaderKeepScreenOn`이 `import.meta.glob`으로 `home/keepScreenOn.ts`의 `useKeepScreenOn`을 찾고(없으면 아무것도 안 함), 바깥 주소 열기는 `@genoffice/mobile-bridge/home`의 `openExternalUrl`이 있으면 쓴다. T6이 언제 합쳐져도 이 트랙 코드를 고치지 않는다. 읽는 화면·발표 화면이 보이는 동안 켠다.
- **다른 앱에서 열기**: Android `application/epub+zip`·`application/vnd.openxmlformats-officedocument.presentationml.presentation`(VIEW·SEND), iOS `org.idpf.epub-container`·`org.openxmlformats.presentationml.presentation`(Viewer, 시스템 UTI라 가져온 형식 선언 없음).
- 시험: `tests/readers-*.test.ts(x)`(빌드 규칙·EPUB 어댑터·EPUB 화면·PPT 어댑터·PPT 화면·T6 고리·등록), `packages/mobile-bridge/tests/readers.test.ts`, Rust `cargo test readers`. jsdom은 Konva를 그리지 못하고 `srcdoc`·배치를 재지 못해서 화면 시험은 `SlideThumb`·배치를 흉내 낸다. 실제 그림·넘기기는 미리보기와 실기기에서 본다.

### T6 홈·설정 (1판)

계획·결정 후보·발견은 `docs/plans/mobile-v1/T6.md`.

- **홈**: `components/HomeScreen.tsx`가 탭(`home/homeTabs.ts`, `visibleHomeTabs`)과 `home/frame/`(탭 막대·레일, 형식 카드, [+] 만들기 시트, 거르개 칩, 빈 상태, T3 도구 층)을 그린다. 형식 카드 항목 id와 순서·숨김 규칙은 `settings/sections/homeSettingsModel.ts` 하나에 있다(한글은 카드 하나 `hwp`가 `.hwp`/`.hwpx`를 대표). `host`가 없으면(시험) 탭 없이 최근 목록만 그린다. 기존 시험이 쓰는 testid(`home-new-hwp-btn`, `home-new-md-btn`, `home-open-file-btn`, `recent-expired-<id>` 등)는 기본 설정의 첫 그림에 있어야 한다.
- **파일 다루기**: 줄·메뉴·여러 개 고르기·막대·시트는 `home/actions/`(목록 종류는 `listKind`). 목록은 `useHomeFileActions`의 `element`를 한 번 그린다. 다리 답이 배열이 아니면 빈 목록이다(가짜 다리는 모르는 명령에 `{ok:true}`).
- **설정 값**: T6 칸(`editorsOff`, `homeKindsHidden`, `homeKindsOrder`, `keepScreenOnWhileReading`, `firstRunDone`, `tipsSeen`, `lastSeenVersion`)은 `home/prefsStore.ts`로 읽고 쓴다(App의 `prefs`는 옛 네 칸용). TS 칸은 모두 선택이고, 없으면 "보여 주지 않음" 쪽으로 읽는다(첫 실행·말풍선·바뀐 것). Rust는 `MobileHomePrefsPatch`로 따로 고친다(기존 통합 시험이 `MobileAppPrefsPatch`를 구조체 그대로 만든다).
- **앱 층**: `App.tsx`가 `home/HomeAppLayer.tsx`를 한 번 그린다(첫 실행, 말풍선, 받는 화면, 읽기 전용 띠와 [사본으로 편집], 꺼진 편집기 묻기, 바뀐 것). 앱 층이 `home/homeRuntime.ts`에 `HomeHost`와 열린 문서 키를 넣고, 설정 절처럼 client를 받지 않는 화면은 `useHomeRuntime()`으로 읽는다(시험에서는 null → 그 줄을 숨김). 말풍선·띠는 편집 화면 파일을 고치지 않고 testid와 "쪽 보기" 단추 이름으로 자리를 찾는다 — 셸의 그 이름을 바꾸면 `tests/home-layer.test.tsx`가 알린다.
- **받기**: `home/incoming.ts`의 `takeIncomingDocument`가 묶음(여러 개·사진)을 먼저 가져가 앱 층의 대기열에 두고, 하나짜리 문서는 전처럼 돌려준다(출처 `received` 기록). Android SEND 거르개에 `SEND_MULTIPLE`과 `image/*`가 있다(새 `<intent-filter>`를 만들지 않는다 — `native-config-slots` 시험).
- **다른 트랙 약속**: T3는 `home/pdfToolsLink.ts`의 `providePdfToolsLink({ Flow })`를 `ToolsTab.tsx`에서 부른다(없으면 T6이 단추를 숨김). T2·T5는 읽는 화면에서 `home/keepScreenOn.ts`의 `useKeepScreenOn(client, active)`를 부른다. 임시 파일은 앱 캐시 `ieum-tmp/<트랙>/`.
- **Rust**: `src/storage/home/`의 `HomeService`(관리 상태는 `lib.rs`의 `// T6 home state`), 명령 `commands/home.rs`(`mobile_home_*`). 화면에 문서 위치(URI·경로·책갈피)를 내보내지 않고 불투명한 id만 준다. 이름 바꾸기로 문서 키가 바뀌면 최근·즐겨찾기·복구 사본·원본 백업을 다시 묶는다. 예시 문서는 `storage/samples/welcome-{ko,en}.hwpx`를 `include_bytes!`로 넣어 앱 안 바이트로 세션을 만든다.
- **네이티브**: 플러그인 트레잇 `NativeFileBridge`의 T6 메서드(폴더·이름 바꾸기·복사·지우기·여러 파일 공유·받은 묶음·화면 켜 둠·바깥 주소)는 호스트 시험 구현 `HostFileBridge`에 같은 뜻으로 있다. iOS Swift는 빌드 확인이 안 된 코드다.

### T7 AI (1판)

계획·결정·공용 도구의 약속은 `docs/plans/mobile-v1/T7.md`. AI는 기본 꺼짐이고, 꺼져 있으면 AI 진입점이 자리째 없다.

- **키 제공자 연결(봉인 중계 + PC 프로토콜)**: 대화 요청은 PC의 프로토콜 코드(`streamOpenAiCompatible`·`streamAnthropic`·`streamGemini`, 그림 만들기는 `media-protocols.ts`)를 웹뷰에서 그대로 쓰고, 나가는 길만 Rust 중계로 바꾼다. `config/tracks/ai.ts`의 Vite 플러그인 `ieum-mobile-ai-fetch`(`mobileAiFetchPlugin`)가 `packages/ai-provider/src/` 안에서 `fetch` 모듈을 가져올 때만 `ai/net/providerFetch.ts`로 바꿔 끼운다(묶음과 시험 모두, PC 파일은 그대로). 이 모듈은 PC의 다시 보내기 규칙(503·529·무료 한도가 아닌 429)을 따르고 `mobileAiRelayFetch`로 보낸다. 다리는 `@genoffice/mobile-bridge/ai-bridge`(`createMobileAgentTransport`가 차례마다 설정을 읽어 키 제공자면 프로토콜+중계, 그 밖은 기존 `mobile_ai_stream_start`). 오류는 `free-limit`·`free-tier-model`·`credits`·`overloaded`·`auth`·`network`·`unknown`으로 나눠 AI 창 알림이 된다.
- **Rust 중계**(`src-tauri/src/ai/relay.rs`, 명령 `commands/ai/relay.rs`): `mobile_ai_relay_start`·`_cancel`, 이벤트 `mobile:ai-relay-event`(head·chunk·end·error, `seq`). 제공자별 https 호스트 허용표(PC 어댑터 표의 공식 주소), 표식은 머리글 값·질의 값에서만 바꾸고 다른 호스트·http·되돌려 보내기는 거절한다. 키는 오류·이벤트·응답 머리글에 실리지 않고, 응답 본문에 되돌아온 키는 가린다. 직접 운영 서버는 저장한 HTTPS 주소의 호스트·포트만(`mobile_ai_get/set/clear_custom_endpoint`, 키는 없어도 됨, 호스트는 제한하지 않음).
- **검색과 주소 읽기**(`src-tauri/src/ai/web.rs`, 명령 `commands/ai/web.rs`, 이벤트 `mobile:ai-web-event`): 검색은 정해 둔 호스트(`search.parallel.ai`, `html.duckduckgo.com`, `duckduckgo.com`, https 443)로만, 키·쿠키 없이, 되돌려 보내기를 따라가지 않는다. 주소 읽기·그림 받기(`mobile_ai_web_fetch_start`)는 http·https GET만, 이름을 한 번 풀어 그 주소에 붙고 공개 주소가 아니면 거절한다(사설·루프백·링크 로컬·CGNAT 등, 표는 `web.rs` 머리 주석). 되돌려 보내기는 다섯 번까지 매번 다시 검사, 10MB·30초. 웹뷰 쪽 규칙은 PC와 같다: 키 없는 검색은 Parallel MCP(JSON-RPC를 SDK 없이) 다음 DuckDuckGo, 그림 검색은 DuckDuckGo, 주소 읽기는 50,000자 나눠 읽기(`htmlToText`만 PC에서, 처음 쓸 때 불러오는 `readUrl` 덩어리).
- **공용 AI 도구**(`ai/tools/`, 약속은 T7.md 1절): `getMobileAiTools()`의 웹 검색·그림 검색·주소 읽기·그림 받기·그림 만들기(OpenAI·Gemini, 결과는 AI 결과 보관소 주소 `ai-result://…`)·사진 보기·붙인 사진. 던지지 않고 `{ error, errorCode }`로 답한다. 가용성은 `availability()`(`web`·`imageGeneration`·`pictureAnalysis`). 상태·도구 설정 캐시·붙인 사진 저장소는 첫 덩어리에 들어가도 되는 `ai/tools/state.ts`, 도구 본체 `ai/tools/index.ts`는 처음 쓸 때 불러오는 코드에서만 가져온다. 편집기 트랙은 자기 PC 스킬의 의존 자리에 얇은 변환으로 꽂는다(T7은 한글만 꽂았다). 실행을 멈추면(중지, `stopAllMobileAi`·AI 끄기, 문서 바꾸기, 숨김 때문에 멈춤) `useMobileAi`가 `abortMobileAiToolCalls()`(`state.ts`)를 불러 도는 도구 호출의 Rust 요청을 끊고, 그 호출은 `cancelled`로 답한다(멈춘 뒤 만든 그림은 보관소에 두지 않음). AI 창에 붙인 사진은 base64 한 벌만 쥔다(보낸 메시지와 `attachments()`가 같은 문자열, `bytes`는 읽을 때 풂).
- **인터넷 감싸개**(결정 0062, `ai/outbound.ts`, 시트 `ai/OutboundConfirmSheet.tsx`): `useMobileAi`가 모든 실행의 합친 스킬을 agent-core `guardOutbound`로 감싼다. "AI가 인터넷 도구 쓰기"가 꺼지면 막고, 대화에 나온 적 없는 주소는 AI 창 위 시트로 묻는다(기본 [막기], 뒤로 가기도 막기, AI 창이 닫혀 있으면 물을 수 없어 막기). 허용은 그 대화 동안만 기억하고 문서를 바꾸면 잊는다.
- **AI 창**(`components/AiSheetPanel.tsx`, `ai/ModelPickerSheet.tsx`, `ai/QueueStrip.tsx`): 모델 칩과 모델 시트(OpenRouter 무료 연결은 `:free`만), 중지, 대기열(끝나면 다음 것, 실패·중지는 대기열을 멈춤, 고치기·옮기기·빼기), 변경 카드(결정 0151, 바로 적용하고 마지막 차례만 되돌리기), 빠른 요청("쉬운 말로 풀기"·"번역"), 사진 붙이기(시스템 선택 창, 긴 변 2048px JPEG, 그림 못 보는 모델은 막음), 알림 종류별 카드. 메시지 목록은 끝에 있을 때 새 답을 따라 내려간다. `aiAvailable: false` 문서에서는 보내지 않는다.
- **막음 오류**(`ai/blocked.ts`): 편집기가 숨긴 부분을 가려내지 못하면 `MobileAiBlockedError('hidden-unverified')`를 던진다(`createAiRun`·`buildContext`·`executeTool`). AI 창은 연결 오류 대신 숨김 알림과 [다시 보내기]를 보이고, 메시지를 입력란에 되돌리며, 대기열을 멈추고, 그 뒤로 모델 요청을 보내지 않는다.
- **실행 상태**(`ai/runState.ts`, 아무것도 가져오지 않음): `mobileAiRunState()`(`running`·`queued`), `subscribeMobileAiRunState`, `stopAllMobileAi()`. 설정의 AI 끄기와 결과 보관소 지우기가 읽는다.
- **설정**(`settings/sections/AiSection.tsx`, 부품은 `ai/`): AI 켜기 줄 아래 한 줄 안내, 돌고 있는 작업이 있으면 끌 때 "멈추고 끌까요?"(`ai/AiConfirmSheet.tsx`). 연결 절에 직접 운영 서버 줄(`ai/CustomServerRow.tsx`), AI 도구 카드(`ai/AiToolsCard.tsx`: 인터넷 도구 기본 켬, 그림 만들기 기본 끔이고 키가 있는 OpenAI·Gemini와 그림 모델을 고른 때만 켜짐, OpenRouter로는 만들지 않음). 도구 설정은 Rust `ai-tool-settings.json`(`mobile_ai_get/set_tool_settings`). `AiStorageRows`는 저장 공간 절이 자기 카드 뒤에 그리는 AI 결과 보관소 카드(`ai/AiResultsRows.tsx`: 크기·파일 수, 실행 중에는 지우지 않음, `mobile_ai_results_size`·`_clear`, 보관소는 앱 데이터의 `ai-results/`이고 지금은 AI가 만든 그림만 둔다).
- **시험**: 웹뷰는 `tests/ai-*.test.ts(x)`(가짜 Rust 도우미 `ai-tools-fake.ts`·`ai-panel-fake.tsx`·`ai-settings-fake.tsx`, 대본 SSE: OpenAI 호환·Anthropic·Gemini), 다리는 `packages/mobile-bridge/tests/ai-relay-response.test.ts`, Rust는 `relay_tests.rs`·`web_tests.rs`·`tools_tests.rs`(루프백 시험 서버는 시험 주입으로만). 바깥 네트워크에 닿는 시험은 없고, 실제 키·구독으로 돌려 보지 않았다.
- **미리보기**: 저장소의 파일이 아니다. 미리보기 때만 가짜 다리(`mock-tauri.js`, mobile-ds 미리보기에서 복사)를 저장소 밖 임시 폴더(`F:\ieum-scratch\mobile-v1-t7\preview\`, 트랙이 끝나면 지움)에만 두고 중계 SSE 대본(글 답, 흘려 오는 도구 호출, 문서를 고치는 도구 호출), Parallel MCP·DuckDuckGo 검색 대본, 주소 읽기, 도구 설정·직접 운영 서버·결과 보관소 명령을 더해 390px에서 한 바퀴 돌았다. 저장소에서 찾지 않는다. 그림과 대본 설명은 T7 PR 본문에 있다.
