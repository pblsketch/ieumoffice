# 0168 — 편집기 탭 옆에 파일 목록 칸을 둔다

## 맥락

2026-11-26 의견: "홈 탭의 왼쪽 탐색기를 다른 편집기 화면에서도 열 수 있으면 좋겠다. 바로 열고 닫으면서 파일을 살펴보고 열 수 있으면 더 편하겠다." 지금은 문서를 고치다가 같은 폴더의 다른 파일을 열려면 홈 탭으로 돌아가거나 열기 창을 띄워야 한다.

다른 앱이 이 일을 어떻게 하는지 화면 모음(Pixlpin)에서 찾아봤다. 코드 편집기형(Shopify 테마 편집기, Lovable)은 문서 왼쪽에 접고 펼치는 폴더 나무를 두고, 지금 연 파일을 칠해 보이며, 칸 머리에 몇 가지 단추와 닫기를 둔다. 문서형(Notion, Claude의 스킬 화면)도 같은 자리에 나무를 두고, 문서와 칸 사이 경계를 끌어 너비를 바꾼다. 공통점은 셋이다. 문서를 가리지 않고 옆으로 민다. 지금 문서가 있는 자리가 먼저 보인다. 한 번 눌러 열고 닫는다.

이 앱에서 편집기 탭은 `WebContentsView`라 껍데기 화면(DOM) 위에 그려진다. 껍데기가 그린 칸은 편집기 화면 밑에 깔리므로 문서 위에 띄울 수 없다.

## 결정

- **칸은 문서를 민다.** 껍데기 뒷단(`TabManager.contentBounds`)이 칸 너비만큼 편집기 화면을 오른쪽으로 옮기고, 껍데기 화면이 빈 자리에 칸을 그린다. 너비 계산은 `shared/file-panel-api.ts`의 `filePanelInset` 하나를 양쪽이 같이 쓴다. 화면 배율을 따르고, 좁은 창에서는 문서에 360px을 남긴다. 화면 나누기는 칸 오른쪽 공간을 나눈다. 슬라이드 쇼처럼 창 전체를 덮는 화면은 그대로 창 전체다.
- **편집기 탭에서만 보인다.** 홈은 자기 왼쪽 칸이 있어 이 칸을 숨긴다. 떼어 낸 창에는 두지 않는다.
- **여는 길.** 탭 줄 왼쪽의 단추(누를 때마다 열기·닫기), 칸 머리의 닫기, 보기 메뉴의 "파일 목록" 체크 항목, 단축키 Ctrl+Shift+E(macOS ⇧⌘E). 코드 편집기에서 탐색기를 여는 키와 같아 익숙한 사람이 많고, 지금 이 키를 쓰는 편집기는 없다. 키는 껍데기의 `before-input-event`에서 받는다(빠른 전환 Ctrl+Shift+P와 같은 자리). Windows의 메뉴 단축키는 편집기 화면보다 먼저 키를 가져가고 떼어 낸 창에서도 동작하므로, 메뉴 항목은 키를 보여 주기만 한다. 한글 탭에서는 한컴식 연속 키(Ctrl+N·K·Q·M·G 다음 글쇠)의 둘째 키를 편집기에 넘긴다. Ctrl을 떼지 않고 Ctrl+N 다음 Shift+E를 눌러 미주를 넣어도 칸이 열리지 않는다. 길게 눌러 반복되는 키는 한 번만 친다. 홈 탭에서는 키를 가로채지 않는다. 단추의 말풍선에 키를 함께 적는다.
- **칸의 내용.** 위에서부터 "이 문서가 있는 폴더"(지금 문서의 형제 파일과 하위 폴더, 지금 문서를 칠함), "폴더"(홈 폴더 나무와 같은 뿌리), "최근 문서" 20개. 위쪽 찾기 칸은 불러온 폴더와 최근 문서에서 이름으로 찾고, 홈 파일 검색 색인의 결과를 뒤에 붙인다. 다른 탭에 열린 파일에는 점을 찍는다. 파일은 한 번 눌러 연다(이미 열린 파일은 그 탭으로 간다). 오른쪽 클릭 메뉴(열기, 탐색기/Finder에서 보기, 경로 복사, 폴더 목록에 추가)는 문서 화면에 잘리지 않도록 네이티브 메뉴다.
- **읽어도 되는 폴더.** 홈 폴더 나무의 뿌리 안쪽, 그리고 열린 문서가 있는 폴더와 그 아래만 새 통로(`file-panel:list-document-folder`)가 목록을 준다. 열린 문서 곁의 파일을 열어도 된다는 기존 규칙(`isBesideOpenDocument`)과 같은 범위다. "탐색기에서 보기"도 뒷단이 같은 범위를 확인한 뒤에 한다.
- **저장.** 열림 여부와 너비를 `app-settings.json`의 `filePanel`(`{ open, width }`)에 둔다. 뒷단이 켤 때 읽어 첫 편집기 화면을 그리기 전에 적용하므로, 열어 둔 채 끈 뒤 다시 켜도 문서가 옆으로 튀지 않는다. 펼친 폴더와 접은 칸은 껍데기 화면의 `localStorage`에 둔다.

## 택하지 않은 것

- **문서 위에 뜨는 서랍.** 편집기 화면이 껍데기 DOM 위에 그려져서 불가능하다. 칸이 뜨는 동안 편집기 화면을 감추는 방법은 문서를 보면서 고르는 흐름을 깬다.
- **편집기마다 칸을 넣기.** 편집기 11개에 같은 칸을 넣으면 고칠 곳이 많아지고 원본과의 차이가 커진다. 껍데기 한 곳에서 한다.
- **홈 칸을 그대로 옮기기.** 홈의 나무는 폴더만 보이고 파일은 오른쪽 표에 보인다. 좁은 칸에서는 폴더와 파일을 한 나무에 보이는 편이 낫다. 아이콘과 폴더 목록 통로는 홈의 것을 같이 쓴다.
- **빠른 미리보기(스페이스바).** 홈의 미리보기는 홈 화면 안의 겹친 창이라 편집기 탭 위에 띄울 수 없다. 따로 창을 띄우는 방법은 다음에 본다.
