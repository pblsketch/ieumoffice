# 0171 — 스캔 PDF 자동 OCR의 40페이지 상한을 없애고, 보고 있는 쪽부터 낮은 우선순위로 끝까지 인식한다

## 맥락

원본(GenOffice #1799)은 스캔 PDF를 열 때 도는 자동 OCR에 40페이지 상한(`AUTO_OCR_PAGE_CAP`)을 두고, 40쪽이 끝나면 "40페이지 한도에 도달해 인식을 중단했습니다" 알림과 "계속" 단추를 띄웠다. 그 상한이 필요했던 이유는 OCR 도우미(`win-ocr.exe`·`vision-ocr`)를 Electron 메인 프로세스에서 `spawnSync`로 불러, 인식이 도는 동안 스크롤과 입력이 쪽마다 수 초씩 멈췄기 때문이다.

사용자는 이 알림을 "이 프로그램이 40페이지까지만 지원한다"는 제한으로 받아들였다. 메인 프로세스 OCR을 비동기 `spawn`과 단일 동시성 대기열로 바꾸어 스크롤·입력 막힘을 없앤 뒤에는, 40쪽마다 멈춰 사용자의 확인을 요구할 이유가 사라졌다.

## 결정

- **고정 페이지 상한을 없앤다.** 자동 OCR 패스(`runAutoOcr`)는 문서 안의 모든 스캔 페이지를 백그라운드에서 끝까지 인식한다. `AUTO_OCR_PAGE_CAP`, `'cap'` 중단 상태, 상한 알림(`ocrPageCap`), "계속"(`ocrContinue`) 흐름을 제거한다. 진행 알림(`ocrRunning` + 취소)과 사용자가 취소했을 때의 알림(`ocrStopped`)은 유지한다.
- **보고 있는 쪽을 먼저 인식한다.** 패스는 다음 쪽을 고르기 직전마다 사용자가 지금 보고 있는 쪽(`fromPage()` / `currentOrigIdxRef`)을 확인한다. 사용자가 다른 쪽으로 이동하면 그 쪽(또는 그 뒤의 아직 인식하지 않은 첫 스캔 쪽)을 바로 다음 차례로 인식하고, 거기서부터 뒤로 이어 가다 끝에서 처음으로 감아 돈다. 이미 인식한 쪽은 다시 인식하지 않는다. 500쪽 스캔 문서에서 300쪽으로 건너뛰어도 앞의 299쪽을 기다리지 않고 한 쪽 시간 안에 300쪽의 검색·선택이 가능해진다.
- **백그라운드 작업을 조용하게 둔다.** OCR 도우미 프로세스는 띄운 직후 우선순위를 `PRIORITY_BELOW_NORMAL`로 낮추고(`os.setPriority`, 실패는 무시), 앱 전체에서 한 번에 하나만 실행한다(`apps/pdf/src/main/ocr.ts`).

## 버린 대안

- **상한 숫자만 100·200페이지 등으로 높인다.** 결국 그 숫자에서 임의로 멈추므로 사용자 눈에는 똑같이 제한이 있는 프로그램으로 보인다.
- **40페이지 상한과 "계속" 단추를 남긴다.** 긴 스캔 문서를 읽거나 검색할 때마다 사용자가 알림을 지켜보며 여러 번 눌러야 한다.
- **화면이 보고 있는 쪽만 필요할 때(on-demand) 인식한다.** 사용자가 열어 보지 않은 쪽은 글자 층이 비어 있어 문서 전체 검색과 AI 읽기가 앞뒤 쪽의 내용을 놓친다.

## 결과

- `apps/pdf/src/renderer/ocr-layer.tsx`는 원본에서 받은 코드이므로, 앞으로 원본 변경을 받아올 때 #1799의 40페이지 상한(`AUTO_OCR_PAGE_CAP`)을 되살리지 않도록 `apps/pdf/AGENTS.md`에 적어 둔다.
- `apps/pdf/src/renderer/i18n/strings.ts`의 22개 언어에서 더 이상 쓰지 않는 `ocrPageCap`·`ocrContinue`를 제거한다.
- 단위 테스트(`apps/pdf/tests/ocr-layer.test.ts`, `apps/pdf/tests/ocr-main.test.ts`)가 무상한 전체 인식, 이동한 쪽 우선 인식·중복 방지, `PRIORITY_BELOW_NORMAL` 설정을 지킨다.
