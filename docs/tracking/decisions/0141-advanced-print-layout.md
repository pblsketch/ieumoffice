# 0141 — 고급 인쇄는 앱이 인쇄할 PDF를 만들어 쪽을 다시 놓고, 쪽 그림으로 프린터에 보낸다

상태: 구현됨(2026-11-14). 실제 프린터와 빌드한 앱에서의 확인이 남았다. 계획은 [`docs/plans/advanced-print.md`](../../plans/advanced-print.md).

## 맥락

모든 문서 편집기에 홀수 쪽만·짝수 쪽만, 역순, 한 장에 여러 쪽(2·4·6·9·16), 소책자, 포스터, 라벨, 회색조, 용지에 맞춰 줄이기, 그림 해상도 고르기, 선택한 부분만 인쇄를 넣으려 한다. 2026-11-13에 지금의 인쇄 경로와 Electron의 인쇄 선택지를 조사했다.

- **지금 인쇄하는 법.** 만든 PDF를 인쇄하는 편집기는 없다. 워드·엑셀·슬라이드·한글·마크다운·HTML·마인드맵·다이어그램은 인쇄용 HTML(워드는 자기 화면)을 시스템 인쇄 창으로 보낸다. PDF 편집기는 쪽을 200dpi 그림으로 바꿔 `window.print()`를 부른다. 워드·엑셀에서 macOS로 앱 안 프린터를 골랐을 때만 PDF를 만들어 `lp`로 보낸다. EPUB에는 인쇄가 없다.
- **Electron 43의 인쇄 선택지.** 소스와 이슈를 읽어 확인했다. 실제로 인쇄해 보지는 않았다.
  - `pagesPerSheet`는 세 운영체제 모두에서 아무 일도 하지 않는다. 한 장에 여러 쪽을 놓는 변환은 Chrome의 인쇄 미리 보기에만 있고, Electron은 그것을 싣지 않는다.
  - Windows 시스템 인쇄 창은 앱이 넘긴 값을 쪽 범위 말고는 쓰지 않고, 프린터 기본값에서 시작한다. 사용자가 고른 값으로 설정을 다시 만든다.
  - macOS는 쪽 범위를 첫 구간 하나만 받는다. 홀수 쪽만 같은 여러 구간은 넘길 수 없다.
  - `color:false`는 드라이버가 정한다. 가상 프린터는 무시할 수 있다.
  - 숨은 창에 PDF를 띄워 인쇄하는 길은 예전 판에서 빈 쪽이 나왔다(#30947, #43309에서 고침). PDF 보기가 준비된 때를 알리는 공개 사건이 없다.

## 결정

- **편집기는 인쇄할 쪽을 PDF로 만들고, 공용 모듈이 쪽을 다시 놓는다.** 범위·선택과 편집기 자기 배치(슬라이드 유인물, 엑셀 배율 등)는 편집기가 PDF를 만들 때 반영한다. 한 장에 여러 쪽·소책자·포스터·라벨·홀짝·역순·용지 맞춤은 새 패키지 `@genoffice/print-layout`이 그 PDF에서 한다. 글자는 글자로 남는다.
- **홀짝·역순은 종이 면에 건다.** 배치를 마친 뒤의 면에서 홀수 면만·짝수 면만·역순으로 찍는다. 양면 기능 없는 프린터에서 앞면을 찍고 뒤집어 뒷면을 찍는 일이 모아찍기·소책자에서도 그대로 된다. 모아찍기를 안 하면 면은 문서 쪽과 같다.
- **회색조는 앱이 쪽을 회색 그림으로 바꿔 한다.** 드라이버의 컬러 끄기에 맡기지 않는다. 그래서 인쇄물과 저장한 파일 모두 회색이고, 파일에서 확인할 수 있다.
- **프린터로는 쪽 그림을 보낸다.** 배치한 PDF의 쪽을 하나씩 그림 파일로 만들어 숨은 창에서 인쇄한다. 시스템 인쇄 창과 편집기에 이미 있는 앱 안 프린터 고르기를 그대로 쓴다. macOS에서 앱 안 프린터를 고른 경우만 지금처럼 PDF를 `lp`로 보낸다. 해상도는 자동(지금 PDF 편집기의 규칙)·150·300·600에서 고르고, 고른 값을 몰래 낮추지 않는다.
- **가로 면은 인쇄할 때만 돌린다.** 2쪽 모아찍기·소책자처럼 가로로 눕힌 면은 프린터로 보내는 그림에서만 90° 돌려 세로 종이에 담는다. Windows 시스템 인쇄 창이 세로로 시작해도 결과가 같다. 미리 보기와 저장 파일은 가로 그대로다.
- **기본값 인쇄는 지금 경로 그대로다.** 공용 칸에서 아무것도 고르지 않으면 편집기의 지금 인쇄가 그대로 돈다. 하나라도 고르면 새 길로 간다.
- **화면은 공용 "쪽 배치" 칸 하나를 기존 인쇄 창에 붙인다.** 인쇄 창이 없는 HTML·마인드맵·다이어그램에는 범위와 이 칸만 든 작은 인쇄 창을 새로 둔다. 인쇄 창은 열 때마다 기본값이다. 배치를 켜면 편집기의 원래 미리 보기 자리에 종이 위 쪽 번호를 그린 배치도가 보이고, "결과 미리 보기"로 실제 결과를 본다. 고급 선택지를 고르면 배치한 결과를 PDF로 저장하는 단추가 보인다.
- **겹치는 선택지는 편집기 칸과 앱 칸이 정한다.** 슬라이드는 "전체 슬라이드"일 때만 배치 방식을 고른다. 엑셀·마크다운처럼 용지·맞춤 칸이 이미 있는 편집기에는 공용 칸의 용지·맞춤을 두지 않는다. 쪽 범위와 배치는 앱 인쇄 창에서만 정한다. 워드의 앱 안 양면은 홀수만·짝수만이면 꺼지고, 소책자면 짧은 쪽 넘김이 된다.
- **소책자는 같은 종이에 반 크기 책이다.** A4 문서면 A4 종이에 두 쪽씩, 접으면 A5 책이다. A3을 고르면 A4 책이다.
- **포스터는 장 수(가로×세로)로, 라벨은 반복과 차례 두 방식으로 정한다.** 라벨 규격은 흔한 A4 칸 배치를 칸 수와 mm로 보이고, 직접 적은 규격은 앱이 기억한다. 화면에 라벨 회사 이름이나 제품 번호를 적지 않는다.
- **선택한 부분만 인쇄**는 워드·마크다운(고른 글만 첫 쪽부터 다시 쪽을 나눔), 엑셀(지금 그대로), 슬라이드(고른 슬라이드), PDF(고른 페이지)에 둔다. 워드는 문서 엔진을 고치지 않고, 고른 내용만 담은 docx를 임시 폴더에 쓴 뒤 숨은 워드 창에서 쪽을 나눈 PDF로 만든다.
- **PDF 편집기의 "주석 포함"은 지금 인쇄와 같은 뜻이다.** 켜면 사본에서 주석을 쪽에 굽고(입력란 포함), 끄면 입력란까지 모든 주석을 뺀다. 배치는 주석 객체를 옮기지 않기 때문에 굽지 않으면 사라진다.
- **배치한 쪽 그림을 인쇄하는 숨은 창은 그림 파일만 읽는다.** 그림은 작업마다 따로 만든 임시 폴더에 두고 끝나면 지운다. 다이어그램은 자기 세션이 앱 주소만 열어 주므로 이 창만 기본 세션의 샌드박스 창으로 띄운다(다이어그램 내용을 PDF로 만드는 창은 다이어그램 세션 그대로). 마인드맵은 내보내기 세션이 인쇄하는 동안에만 그 인쇄의 임시 폴더 바로 안의 파일을 읽게 한다.
- **권한 제한이 걸린 PDF에서는 배치한 결과를 PDF로 저장할 수 없다.** 인쇄는 지금처럼 된다. 저장하면 원본에 걸린 제한이 없는 사본이 생기기 때문이다(2026-11-14 저장소 주인 결정).

## 뺀 것과 까닭

- **EPUB**: 인쇄 기능이 없다. 기본 인쇄를 새로 만드는 일은 이번 범위 밖이다.
- **한글의 선택 인쇄**: 엔진에 문서 일부만 그리는 기능이 없다. 고른 글을 복사해 새 문서에 붙여 쪽을 나누는 길은 있지만, 붙여넣기가 못 옮기는 것이 생길 수 있어 이번에는 하지 않는다. 한글의 다른 고급 선택지는 넣는다.
- **마인드맵·HTML·다이어그램의 선택 인쇄**: 고른 가지·요소·도형만 떼어 찍는 뜻이 편집기마다 흐리고, HTML은 요소를 바깥 틀에서 떼면 모양이 바뀔 수 있다. 다른 고급 선택지는 넣는다.
- 편집기의 보통 PDF 내보내기, 터미널 명령어와 MCP 도구, PDF 편집기의 "페이지 모아찍기"(새 파일 만들기)는 바꾸지 않는다.

## 택하지 않은 것

- **Electron 인쇄 선택지(`pagesPerSheet`, `pageRanges`, `color`, `duplexMode`)에 맡기기.** 위의 조사대로 운영체제마다 무시되거나 아예 하지 않는다.
- **배치한 PDF를 숨은 창에 띄워 바로 인쇄하기.** 글자가 더 선명하지만, 실제 프린터 없이 확인할 수 없고 예전 판에서 빈 쪽이 나왔다. 쪽 그림 길은 PDF 편집기가 이미 사용자에게 쓰고 있다.
- **운영체제 인쇄 명령으로 PDF 보내기(Windows).** Windows에는 PDF를 바로 인쇄하는 기본 명령이 없다. 설치된 PDF 프로그램에 기대거나 다른 프로그램을 함께 실어야 한다.
- **문서 쪽 기준 홀짝.** 손으로 양면 인쇄할 때 앞뒤가 맞지 않는다.
- **모든 편집기의 인쇄 창을 새 공용 창 하나로 바꾸기.** 편집기마다 있던 선택지를 다시 옮겨야 하고, 원본에서 받아오는 인쇄 창과 많이 달라진다.
- **원본의 모아찍기 함수(`apps/pdf/src/main`)를 공용 패키지로 옮기기.** 원본을 받아올 때마다 충돌한다. 계산이 겹쳐도 새 패키지에 따로 쓴다.
- **고른 선택지를 다음 인쇄 때 기억하기.** 한 번 소책자로 찍은 뒤 다음 인쇄가 뜻밖에 소책자로 나온다.

## 결과

- 코드: `packages/print-layout`(선택지·면 계획 `./plan`, 배치 `arrange.ts`, 쪽 그림·회색조 `raster*.ts`·`grayscale.ts`), `packages/electron-utils/src/print-arranged.ts`(인쇄·미리 보기·저장, `registerPrintLayoutIpc`, `ensurePrintLayoutIpc`)·`print-layout-bridge.ts`·`print-layout-worker.ts`, `packages/ui/src/print-layout/`(쪽 배치 칸, 배치도, 결과 미리 보기, 작은 인쇄 창)과 `strings-print-layout/`(22개 언어), 편집기 아홉의 인쇄 창과 `src/main/print-layout.ts`.
- 시험: `packages/print-layout/tests`가 시험 안에서 만든 PDF를 배치하고 PDF.js로 면 수·면 크기·칸마다의 쪽 표식·재단선을 읽어 판정한다(소책자 8쪽 [8|1] [2|7] [6|3] [4|5] 등). 회색조는 결과 PDF의 그림이 DeviceGray 하나뿐이고 글자가 남지 않는지 본다. `packages/electron-utils/tests/print-arranged.test.ts`가 가짜 창으로 가로 면 돌리기, 시스템 창·앱 안 프린터 값, macOS `lp` 길, 취소·실패 때 아무것도 보내지 않고 임시 폴더가 남지 않는지를 본다. 편집기마다 `print-*layout*.test.ts`가 기본값 인쇄가 지금과 같은 인수로 불리는지 지킨다.
- 앱 안 프린터(워드·엑셀)로 보낼 때 용지는 인쇄 창의 용지가 아니라 첫 면의 크기다. 배치한 면은 고른 용지와 크기가 다를 수 있기 때문이다(소책자를 A3에, 포스터 조각 등). 면 크기가 섞인 작업은 `docs/tracking/findings.md`에 적었다.
- 확인하지 못한 것: 실제 프린터에서의 결과. 드라이버가 쪽 그림 인쇄를 어떻게 받는지, 돌린 가로 면을 짧은 쪽으로 양면 인쇄했을 때 뒷면 방향, macOS `lp`가 회전 표시를 따르는지는 사용자 보고로 확인한다(`docs/tracking/findings.md`).
