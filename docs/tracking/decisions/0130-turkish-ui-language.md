# 0130 — 화면 언어에 튀르키예어를 더한다(22개)

튀르키예에서 사업하는 사용자가 자기 직원들이 쓰게 해 달라고 요청했다(2026-11-10). 화면 언어 목록(`LANGS`)에 `tr`을 더하고, 저장소의 모든 사전 조각·도움말·검사 기준을 22개 언어로 맞춘다.

## 맥락

- 화면 문구는 `packages/i18n`의 `Lang`·`LANGS`가 정하고, 모든 사전 조각이 `zh`의 키 집합을 `satisfies Record<keyof typeof zh, string>`으로 강제받는다. 언어 하나를 더하면 빠진 번역이 실행 중 대체가 아니라 형 오류로 드러난다.
- 언어를 더하는 일은 `packages/i18n`만의 변경이 아니다. 40개의 `i18n/<영역>/<언어>.ts` 조각, 앱마다 하나씩 있는 `strings.ts` 집계, 메인 프로세스의 인라인 사전, `packages/ui`의 공용 문자열, 앱 안 도움말 24개 항목, 그리고 언어 수를 세는 검사들이 함께 움직여야 한다.
- `normalizeLang`은 `LANGS`를 돌며 접두사를 보므로 `tr`·`tr-TR`·`tr_TR`이 저절로 `tr`로 정규화된다. `htmlLang`은 `tr-TR`이다.
- 제품 이름은 튀르키예어에서도 `IeumOffice`다. `LOCALIZED_PRODUCT_NAMES`에는 한국어만 있으므로 따로 넣지 않는다.

## 결정

- `Lang`·`LANGS`·`HTML_LANGS`에 `tr`을 더하고, 사전이 있는 모든 자리에 `tr` 조각·블록을 넣는다. 번역은 `en`을 기준으로 하고, `zh`의 키 집합을 그대로 지킨다.
- 앱 안 도움말은 `topics/<id>.tr.md` 24개를 더한다. 구조(제목·표 행·목록·번호 단계·코드 울타리·그림·`help://` 링크)는 영어판과 같아야 하고, `NO_HAN` 목록에 `tr`을 넣는다.
- `settings-integrations`의 "21 UI languages" 목록을 22개로 고치고 모든 언어판 끝에 튀르키예어를 더한다.
- 언어 수를 세는 검사(`toHaveLength(21)`)를 22로 올린다. 문구를 세는 검사가 아니라 "모든 언어가 채워졌는가"를 보는 검사다.
- 릴리스 본문·README·소개 문서의 "21개 언어"를 22개로 고친다. 지난 결정 기록과 계획 문서의 "21개 언어"는 그때의 사실이므로 그대로 둔다.

## 택하지 않은 것

- **영어를 그대로 채워 넣고 나중에 번역한다.** `docs/standards.md`가 금지한다. 키는 맞지만 화면에는 영어가 남고, 검사도 그것을 잡지 못한다.
- **`LANGS`에만 넣고 사전을 비워 둔다.** 형 검사가 모든 앱에서 실패한다. 반쪽 상태로는 빌드도 실행도 되지 않는다.
- **번체 중국어처럼 별도 코드(`tr-TR`)를 `Lang`으로 쓴다.** 튀르키예어는 변형이 하나뿐이라 기본 코드 `tr`로 충분하고, `normalizeLang`이 `tr-TR`을 받아 준다.

## 결과

- 화면 언어 목록과 설정의 언어 선택에 `Türkçe`가 나온다. 처음 실행이 시스템 로캘 `tr-TR`을 읽으면 튀르키예어로 시작한다.
- 번역은 기계 번역으로 채웠고 튀르키예어 원어민의 검수를 거치지 않았다. README의 번역 고지와 같은 한계다. 오류가 보이면 그 조각만 고친다.
- 언어를 하나 더할 때는 이 기록의 목록(조각·집계·인라인 사전·도움말·언어 수 검사·문서)을 그대로 따라야 한다.
