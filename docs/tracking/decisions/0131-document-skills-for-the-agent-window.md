# 0131 — 공개 문서 스킬 넷을 원본 그대로 싣고, 에이전트 창에서만 쓴다

스킬 고도화 계획(`docs/plans/skills-v2.md`) 7단계 "기본 스킬 넓히기"의 첫 부분이다. 결정 0048의 "유명한 문서 스킬(docx·pptx·xlsx·pdf)은 넣지 않는다"를 바꾼다.

## 맥락

- 결정 0048은 이 스킬 넷을 두 가지 까닭으로 넣지 않았다. 재배포가 허용되지 않는 라이선스였고, 파일을 자체 스크립트로 만드는 방식이라 앱이 문서를 고치는 방식과 겹쳤다.
- 2026-11-06에 원 저장소가 이 넷을 Apache-2.0으로 바꿨다(커밋 `2c5958ec`). 폴더마다 `LICENSE.txt`가 Apache-2.0 전문이고, 저장소 소개 글도 "open source (Apache 2.0)"라고 적는다. 2026-11-11에 다시 확인했다. 첫째 까닭은 사라졌다.
- 둘째 까닭은 남아 있다. 네 스킬의 본문은 Python·Node 스크립트, LibreOffice, pandoc, Poppler를 명령으로 실행해 파일을 만들고 고치는 절차다. 일반 AI 창은 구독 프로그램을 도구 0개로 띄우고 스크립트를 실행하지 않는다(규칙 3, 결정 0048). 이 본문을 일반 창에 넣으면 AI가 할 수 없는 절차를 읽게 된다.
- 에이전트 창(결정 0032)은 사람이 고른 프로젝트 폴더에서 명령을 실행하고, 스킬 폴더를 스크립트까지 묶어 프로그램에 준다. 스크립트가 든 스킬이 온전히 도는 곳은 여기뿐이다.
- 저장소 주인이 라이선스를 확인한 뒤 기본 스킬로 넣자고 했다(2026-11-11).

## 결정

- **네 스킬(`docx`, `pptx`, `xlsx`, `pdf`)을 원본 바이트 그대로 싣는다.** 커밋 `2c5958ecac7cee2b583967a2c4981d0f4a75c579`의 네 폴더 전체(182개 파일, 약 3.9MB)다. `LICENSE.txt`를 그대로 두고, `NOTICE`와 `builtin-skills.json`에 출처·경로·커밋·라이선스를 적는다. `modified: false`다. 커밋한 내용이 원 저장소의 blob과 같은지 대조했다.
- **에이전트 창 전용이다(`agentOnly: true`).** 일반 AI 창과 홈 AI 질문의 `/` 목록, 스스로 쓰기 목록에는 나오지 않는다. `find-skills`와 같은 길이다. 일반 창의 요청 길이와 한도는 늘지 않는다.
- **다른 기본 스킬처럼 켜진 채 시작한다.** 설정 → 스킬에서 끄거나 숨길 수 있다.
- **실행 환경은 사용자 PC의 것을 쓴다.** 앱은 Python이나 LibreOffice를 싣지 않고 설치해 주지도 않는다. 없으면 그 단계가 실패하고, 프로그램이 그 사실을 알린다(결정 0032의 "스킬이 기대는 실행 환경은 사용자 PC에 있어야 한다"). 한 줄 설명과 도움말에 "이 PC에 Python 같은 프로그램이 설치되어 있어야 합니다"를 적는다.
- **열린 문서는 지금처럼 앱 도구로만 고친다.** 에이전트 창은 탭에 열린 파일을 프로그램의 파일 도구로 쓰려는 요청을 거절한다(결정 0032). 이 스킬들이 고치는 것은 프로젝트 폴더의, 탭에 열려 있지 않은 파일이다.
- **일반 창에서 쓰는 문서 종류별 스킬은 따로 쓴다.** 이 넷의 본문을 편집기 도구에 맞게 고쳐 싣지 않는다. 편집기마다 도구가 달라 고친 글은 원본과 다른 글이 되고, 원본이 바뀔 때 받아오기도 어렵다. 한글·마인드맵·다이어그램·HTML처럼 원본에 없는 종류의 스킬은 결정 0132에서 이 프로젝트의 글로 새로 쓴다.

## 택하지 않은 것

- **일반 창에도 보이기(`agentOnly: false`).** "스크립트 포함 · 에이전트 창에서 완전히 동작" 표시가 붙지만, AI가 스스로 골라 읽으면 실행할 수 없는 명령을 따라 하려 한다. 워드·엑셀·슬라이드 편집기의 AI는 이미 자기 도구와 지시문을 갖고 있다.
- **스키마 폴더(`scripts/office/schemas`)를 빼고 싣기.** 약 3MB가 줄지만 `validate.py`의 XSD 검사가 돌지 않고, 원본과 다른 사본이 되어 `modified: true`와 고친 내용 기록이 필요하다.
- **본문에 "이음오피스에서는" 절을 덧붙이기.** `find-skills`는 그렇게 했다. 여기서는 본문이 가정하는 환경(미리 설치된 패키지, 격리된 실행 환경)과 사용자 PC가 다르다는 것을 설명과 도움말에서 알리는 것으로 충분하다고 봤다. 실제로 써 보고 프로그램이 헤매면 다시 본다.
- **앱이 Python·LibreOffice를 싣거나 내려받기.** 설치본이 수백 MB 커지고, 배경에서 스스로 내려받지 않는다는 규칙과 맞지 않는다.

## 결과

- 기본 스킬이 7개에서 11개가 된다. 설치본의 `resources/builtin-skills`가 약 3.9MB 커진다.
- 설치본에 `.py` 파일 32개와 XSD 스키마가 자료로 들어간다. 앱은 이 파일을 실행하지 않는다. 실행은 에이전트 창에서 프로그램이 권한 요청을 거쳐 한다(허락 방식은 결정 0032 그대로).
- 에이전트 세션을 시작할 때 묶음 폴더로 복사하는 양이 약 3.9MB, 파일 182개 늘어난다. 스킬 하나의 한도(64MB, 5,000개)보다 훨씬 작다.
- 스키마 파일(ISO/IEC 29500-4:2016, OPC, Microsoft Office 확장 스키마)이 처음으로 설치본에 들어간다. 지금까지 이 저장소의 같은 스키마 사본(`tools/ooxml-validate/schemas`)은 시험에만 쓰고 싣지 않았다. 원 저장소는 이 파일들을 스킬 폴더의 Apache-2.0 `LICENSE.txt` 아래에 두고 따로 고지하지 않는다. `NOTICE`에 이 파일들이 들어 있다는 것을 적었다.
- 사람이 확인할 것(`docs/tracking/status.md`): Python이 있는 PC와 없는 PC의 에이전트 창에서 `docx` 스킬로 새 파일을 만들어 본다. 실제 구독의 한도를 쓴다.
- 원본이 바뀌면 받아오는 방법: 원 저장소의 네 폴더를 줄바꿈 변환 없이 받아 덮어쓰고, `builtin-skills.json`과 `NOTICE`의 커밋을 고친다. `.prettierignore`가 이 폴더의 서식 변경을 막는다.
- 고친 문서: `NOTICE`, `docs/business-rules.md`("스킬"), `docs/plans/skills-v2.md`(7단계), 결정 0048(머리의 알림), 도움말 "스킬"(21개 언어).
- 시험: `packages/ui/tests/builtin-skills-strings.test.ts`(목록과 문구가 같은 이름을 갖는지, 네 스킬이 에이전트 창 전용·고치지 않음으로 적혔는지, 21개 언어 설명).
