# 0164 — AI 질문 카드는 A2UI v1.0 메시지로 주고받는다

## 맥락

2026-11-24 사용자가 [A2UI](https://github.com/a2ui-project/a2ui)(Google이 관리하는 Apache-2.0 규격, v1.0 안정판)를 이음오피스에 어떻게 붙일지 근거를 들어 분석해 달라고 했다. A2UI는 AI가 화면을 코드가 아닌 JSON 데이터로 보내면 앱이 미리 정한 부품 목록(카탈로그) 안에서만 그리는 규격이다.

- 구독 프로그램은 앱 도구의 이름만 받는 "한 차례 답" 두뇌이고, 도구는 화면 쪽 앱이 실행한다(결정 0082). A2UI를 AI와 주고받는 통로로 들이면 이 잠금에 닿는다. 앱 도구 하나가 받는 입력 형식으로 붙이면 닿지 않는다.
- main에는 PR #620으로 공용 `ask_questions` 도구와 공용 카드 `AiQuestionCard`가 이미 열한 편집기와 홈에 있었다. HTML·슬라이드에는 옛 도구 `ask_clarification`과 그 카드가 따로 남아 있었다.
- 그래서 "두 벌을 한 벌로"의 이득은 이미 얻은 상태였다. 사용자는 이 사실과 "질문 형식을 바꾸면 매 차례 실리는 도구 설명이 커진다"는 설명을 듣고, 표준 형식을 까닭으로 질문 형식 자체를 A2UI로 바꾸기로 했다.

## 결정

- **`ask_questions` 도구의 입력은 A2UI v1.0 `createSurface` 메시지 하나다.** 부품과 초기 값을 그 안에 모두 담는다. 결과는 A2UI v1.0 `action` 메시지 JSON이다. 보내기는 `name: "submit"`, `sourceComponentId: "ieum_submit"`, `context.answers`(입력 id → 값, "알아서 정해 줘"가 아닌 모든 칸)와 `context.decideForMe`(id 목록)다. 건너뛰기·멈춤·새 메시지로 닫힘은 `name: "skip"`, `sourceComponentId: "ieum_skip"`, `context: {}`다. 도구 이름이 그대로라 구독 프로그램의 형식 스키마와 잠금은 바뀌지 않는다.
- **카탈로그 `ieumoffice.com:question-card/v1`** 은 A2UI 기본 카탈로그 v1(커밋 `c26be2dd`)의 부분집합이다. Column, Text, ChoicePicker, CheckBox, TextField, Slider와 함수 `required`만 두고, 정의를 바꾸지 않으며 이음오피스만의 속성을 덧붙이지 않는다(사용자 선택 "표준 부품만"). 지금 카드의 "기타 직접 입력 켜기"와 "최대 선택 수"는 표준에 없어서 없앴다. 직접 입력이 필요하면 모델이 TextField를 따로 둔다. 기본값은 `dataModel`, 필수는 `@checks`의 `required`로 나타낸다.
- **정해진 틀.** 모델은 root Column 밑의 제목·설명·질문 칸만 쓴다(중첩 없음, 입력은 1개 이상 5개 이하, 선택지는 1개 이상 7개 이하, 모든 입력에 라벨). 배치와 단추("보내기", "건너뛰기"), 고르는 질문마다 붙는 "알아서 정해 줘"는 앱이 22개 언어 문구로 붙인다(사용자 선택). 검사는 `validateQuestionSurface` 한 함수가 하고, 어긴 곳을 `<위치>: <까닭>` 줄로 모델에 돌려준다. 형식 오류는 "이미 물었다"로 세지 않는다.
- **렌더러는 직접 만든다.** `@a2ui/*` 패키지를 들이지 않는다. 런타임 의존성은 늘지 않았다. 시험에서만 A2UI 공식 JSON 스키마(`packages/agent-core/tests/fixtures/a2ui-v1_0/`)와 `ajv`·`ajv-formats`(개발용)로 우리가 내고 받는 메시지가 진짜 A2UI인지 확인한다. 카탈로그 정의 파일의 출처는 `NOTICE`에 적었다.
- **도구를 못 쓰는 모델**은 같은 카드를 답 글 끝의 `<a2ui-json>` 블록(A2UI Direct JSON, 메시지 배열)으로 쓴다. 지금까지 `<question-form>`을 쓰라는 안내가 어디에도 없어 그 길이 쓰이지 않았으므로, 질문 기능이 든 실행이 도구를 못 쓸 때만 짧은 안내를 붙인다(`AgentSkill.toolsOffSystemPrompt`). 화면 없는 반복에는 붙지 않는다. 옛 `<question-form>` 블록은 예전 대화를 보여 줄 때 읽기 전용 카드로만 그린다. 글 속 카드의 답은 사람 메시지로 들어가므로 읽기 쉬운 `질문: 답` 줄로 보낸다.
- **카드 동작.** 카드는 대화 안에 뜨고 입력칸은 살아 있다. 답을 기다리는 동안 실행 시간이 멈춘다. 실행 중에 메시지를 대기열에 넣거나 새 메시지를 보내면 카드는 닫히고 `skip`이 돌아간다. 새 대화와 대화 바꾸기는 카드 상태를 비운다.
- **다시 열기.** 열한 편집기와 홈은 `ask_questions` 도구 활동의 입력과 출력을 저장하고(저장소의 16,000자 한도 안), 대화를 다시 열면 그 자리에 읽기 전용 카드를 그린다. 새 모양, 예전 `ask_questions` 모양, 예전 `ask_clarification` 모양을 모두 읽고, 질문이 저장되지 않은 예전 기록은 남은 답만 보인다(사용자 선택). 프로젝트 대화를 다른 편집기에서 열면 그 편집기의 도구는 지금처럼 "도구 n개" 한 줄이다(결정 0088, 사용자 선택). `packages/project-store`는 고치지 않았다.
- **HTML·슬라이드의 `ask_clarification`을 없앤다.** 두 편집기도 공용 `ask_questions`를 쓴다. 언제 묻는지는 공용 규칙 하나다(목적에 맞춘 만들기 스킬을 쓰거나 방향이 정말 애매할 때만, 실행에 한 번). 슬라이드의 "새 발표 자료는 먼저 반드시 묻는다"와 질문 뒤 다음 단계 안내를 없앴고, HTML 글 쓰기에서도 애매하면 물을 수 있다(사용자 선택). HTML 기획안 작성기는 질문 호출을 JSON 대신 `질문: 답` 줄로 옮겨 적는다.
- **원본과의 갈라짐.** 원본(GenOffice)에는 `ask_clarification`이 남아 있다. 이 파일들은 이미 원본과 수백 줄씩 달라 늘어나는 부담은 작다. 원본을 받아올 때 이 도구와 카드를 다시 들이지 않는다(`docs/operations.md`, 사용자 선택).

## 버린 대안

- **`@a2ui/react`를 들인다.** 0.16.x로 판마다 호환이 깨지고(BREAKING 항목이 0.13·0.15·0.16마다 있음), 0.13부터 기본 부품이 Lit 웹 컴포넌트라 우리 토큰·22개 언어·오른쪽→왼쪽 언어 규칙과 따로 논다.
- **호환 층만 둔다**(모델 형식은 그대로, 변환기만). 처음 추천이었으나 사용자가 표준 형식을 원했다.
- **자유 배치**(모델이 줄·칸·단추까지 짠다). 도구 설명이 커지고 단추가 빠지거나 연결이 끊긴 화면이 나올 수 있다.
- **표준 이름에 우리 속성을 덧붙인다.** 다른 A2UI 렌더러에서는 덧붙인 기능이 사라진다.
- **옛 이름 `ask_clarification`을 얇게 남긴다.** 하나로 합치기로 했다.
- **A2UI Express 형식**(토큰이 더 적은 별도 문법). 해석기가 따로 필요하고, 우리 차례는 도구 입력 JSON으로 받는다.
- **A2UI를 AI 통로로 들인다**(답 글 안의 태그를 해석해 실행). 결정 0082가 글 속 가짜 호출을 실행하는 길을 이미 버렸다.

## 결과

- **도구 설명 크기.** 도구 설명·스키마·지시문 구역의 글자 수 합은 바꾸기 전 1,342자, 바꾼 뒤 4,608자다(설명 2,773, 스키마 1,026, 지시문 809. 첫 판은 4,006자였고 실제 구독 확인 뒤 고친 문장이 더해졌다). 6,000자 상한을 시험이 지킨다. 스키마는 한 파일 안에서 끝나고 `@`로 시작하는 속성 이름을 선언하지 않는다(어느 제공자 하나가 거부하면 모든 요청이 실패하기 때문). Gemini 스키마 변환은 그대로 통과한다.
- **실제 구독 확인**(빌드한 앱을 임시 데이터 폴더로 띄움, Claude `haiku`, Codex `gpt-6-luna`, 워드·한글·슬라이드·HTML·엑셀).
  - 1차: 10번 중 6번 통과(Claude 1/5, Codex 5/5). Claude가 한글·엑셀에서 카드 대신 글로 묻고, 워드·슬라이드에서 카드 뒤에 빠진 주제를 글로 다시 물었다.
  - 고친 것: 도구 설명과 지시문에 "묻는 것은 이 카드로만, 답 글로 묻지 않는다", "일에 필요한 질문은 주제까지 한 카드에", "답 뒤에는 다시 묻지 않고 빈 곳은 기본값으로 채워 말한다"를 넣었다. 기본 스킬 `hwp-document`·`html-document`의 "한 질문으로 물어라"를 "`ask_questions` 카드 하나로"로 고쳤다.
  - 2차(사용자 승인): 10번 중 9번 통과(Claude 4/5, Codex 5/5). 10번 모두 카드로 물었고 형식 오류 재전송은 없었다. 실패한 Claude 한글은 시험 규칙상 모든 글 칸에 같은 문장을 넣은 탓에, 모델이 "실제 정보가 없다"며 넣은 내용을 되돌리고 다시 물었다.
  - 3차(사용자 승인, 1번): Claude 한글을 칸에 맞는 답으로 다시 재서 통과했다. 형식 오류 재전송 1번(첫 호출에 인자가 비었음) 뒤 카드가 떴다. 2차의 나머지 9번과 합쳐 기준(10번 모두)을 채웠다. 다만 이 한 번만 칸에 맞춘 답을 넣었다.
  - 띄운 앱과 하위 프로세스(`claude`, `codex` 포함)는 매번 남지 않았다.
- 남은 일: 형식 오류로 첫 호출이 한 번 버려지는 일이 Claude에서 가끔 있다(허용된 재전송 안에서 회복). 슬라이드·HTML은 한도를 아끼려고 답한 뒤 몇 차례에서 멈춰 결과물 완성까지는 보지 않았다.
- 다음에 할 것: 사용자 MCP 서버가 도구 결과로 보낸 A2UI 화면(`application/a2ui+json`)을 같은 렌더러로 그린다(`docs/plans/a2ui-question-card.md`).
