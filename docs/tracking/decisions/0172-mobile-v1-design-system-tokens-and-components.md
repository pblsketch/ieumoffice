# 0172. 모바일 1판 디자인 시스템의 토큰 층·공용 부품과 화면 통일 규칙

- 날짜: 2026-11-26
- 상태: 모바일 1판(배포 전), 주인 승인(2026-11-26)

## 맥락

결정 [0165](0165-mobile-scope-and-design-system.md) 이후 트랙 여섯을 390·820·1280px, 밝게·어둡게 화면으로 점검한 결과, 색·글자·간격 토큰은 잘 지켜졌으나 같은 역할의 화면 조각이 트랙마다 갈라져 있었다. 고른 것 표시가 5가지, 선 아이콘 크기가 15가지(14~38px), 빈 상태가 4모양, 보기 도구와 쪽 표시가 3가지였고, 누를 영역이 48px에 못 미치는 곳이 6군데 있었다. 설정 탭은 별도 화면으로 열려 태블릿에서 레일이 사라졌고, 넓은 창에서 본문과 목록 폭 제한이 없었다.

## 결정

1. **주 동작 색과 강조색 역할 분리(주인 승인 2026-11-26).** 채움 단추·켜진 스위치·`[+]`·빈 상태 주 단추는 PC와 같은 진한 색(`--m-primary`)을 쓰고, 파랑(`--m-accent`)은 지금 위치(탭·레일·목차 현재 장)와 바 안 글 단추에만 쓴다. 결정 0165의 편집기별 강조색은 1판에 넣지 않고 모든 편집기가 `--m-accent` 하나를 쓴다.
2. **보기 모드 아래 도구 통일(주인 승인 2026-11-26).** 한글·PDF·EPUB·PPT 모두 아래쪽 떠 있는 원형 묶음(`FloatingTools`, 오른쪽)과 같은 줄 왼쪽 쪽 표시 알약(`PageIndicator`)을 쓴다. 셸과 트랙이 서로 다른 파일에서 그리더라도 `--m-floating-*`·`--m-z-floating` 토큰으로 자리를 맞춘다.
3. **넓은 창 폭 제한(주인 승인 2026-11-26).** 창 너비 840px 이상(`expanded`·`large`)에서 본문 글은 최대 `--m-measure`(40rem), 목록·설정·도구 화면은 최대 `--m-content-max`(720px)로 가운데에 둔다.
4. **설정 탭 위치(주인 승인 2026-11-26).** 홈에서 들어가는 설정은 홈 탭 안에 그려 태블릿 레일과 아래 탭이 남도록 한다. 편집 화면에서 들어올 때만 뒤로 가기 화면으로 연다(뒤 단계 적용).
5. **토큰 파일 분할, 공용 부품 `ds/`, 자동 검사.** `styles/mobile-tokens.css`를 원래 순서 그대로 11개 파일의 가져오기 목록으로 나누고(`shell/*.css` 포함, 주인 승인 2026-11-26), 선 아이콘 4단계(`s`/`m`/`l`/`xl`), 고른 상태 2모양(바탕+글 / 안쪽·바깥 고리), 그림자 4단계(`--m-elev-0`~`3`), 공용 부품(`apps/mobile/src/renderer/ds/`)을 둔다. `apps/mobile/tests/ds-guard.test.ts`가 선 아이콘 숫자 크기, 직접 `z-index`·그림자, 고른 상태 색 위반을 검사하며, 기존 위반 파일은 허용 목록에서 단계적으로 걷어낸다.

## 버린 대안

- **확정 시스템 3.6의 편집기별 강조색을 1판에 함께 넣기:** 세 테마 값을 새로 정해야 하고 공용 `packages/ui`에 닿아 1판 범위가 커진다.
- **EPUB·PPT만 별도 하단 읽기 막대로 두기:** 한글·PDF와 조작 위치가 달라져 보기 모드 화면이 갈라진다.
- **규칙을 문서로만 관리하기:** 트랙이 나란히 작업하는 구조에서는 문서 규칙만으로 아이콘 크기와 선택 표시의 일관성을 유지하기 어렵다.

## 결과

- 앞 단계(토큰 층, 11개 CSS 파일 분할, 공용 부품 `ds/`, `ds-guard.test.ts`)가 `feat/mobile-v1-design`에 구현되었고, CSS 분할 전후 빌드 바이트는 같다.
- 뒤 단계(각 트랙 화면을 공용 부품과 새 토큰으로 갈아끼우고 허용 목록을 비우기)는 트랙 PR(T2~T7)이 바탕 가지에 합쳐진 뒤 진행한다.
- 편집기별 강조색 부재는 미해결 항목으로 남긴다.
