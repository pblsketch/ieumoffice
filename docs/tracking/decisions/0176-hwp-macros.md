# 0176 — 한글 키 매크로·제한된 스크립트 매크로와 호환 객체

날짜: 2026-11-27

## 맥락

논문과 보고서를 한글 문서(`.hwp`, `.hwpx`)로 작성할 때는 글자·문단 서식 일괄 적용, 스타일 변경, 표 삽입, 반복 찾아 바꾸기처럼 똑같은 편집 절차를 여러 차례 되풀이하는 일이 잦다. 키 입력을 기록해 단축키로 다시 실행하는 키 매크로와 직접 편집·공유할 수 있는 스크립트 매크로가 필요했다. 동시에 외부에서 가져온 매크로 파일이나 잘못된 스크립트가 임의 JavaScript를 실행하거나 무한 반복·메모리 소진·개체 유실로 앱과 문서를 망가뜨리는 위험을 근본적으로 차단해야 했다.

## 결정

1. **제한된 동기 스크립트 해석기(`studio-plugin/macro-interpreter.mjs`)**:
   - `eval`, `Function`, 동적 `import`, `with`, `vm` 모듈, 숨은 창 JavaScript 실행을 일절 쓰지 않고, 부분 JavaScript 문법을 직접 어휘·구문 분석하고 평가하는 동기 해석기를 둔다.
   - 스크립트는 앱이 명시적으로 넘긴 얼린 문서 API(`studio-plugin/macro-host.mjs`)와 기존 매크로 스크립트 꼴 호환 객체(`studio-plugin/macro-compat.mjs`, `HAction`·`HParameterSet`) 및 소수의 얼린 내장 보조 함수만 접근할 수 있다. 호스트 전역(`window`, `globalThis`, `document`)과 파일·네트워크·클립보드·타이머·IPC는 노출하지 않는다.
   - 스크립트 안에서 만든 객체와 전달 레코드는 모두 프로토타입 없는 빈 객체(`Object.create(null)`)로 만들고, 금지 속성(`constructor`, `__proto__`, `prototype`, `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`, `__lookupSetter__`, `caller`, `callee`, `arguments`)은 점 접근과 계산 속성 접근(`obj[key]`) 모두에서 차단한다.
   - 실행 시간(기본 30초), 걸음 수(기본 100,000걸음), 함수 호출 깊이(64), 문자열 길이(1,000,000자), 배열·객체 크기(50,000항목), 도달 가능 메모리 회계(`maxMemoryBytes`, 기본 64 MiB; 긴 문자열은 생성 단위 정체성으로 추적해 같은 문자열을 여러 곳에서 참조해도 한 번만 센다), 스크립트 크기(256 KiB) 상한을 강제하고, 방향 제어·폭 없는 문자를 구문 검사에서 차단한다. 정규식 검색(`{ regex: true }`, `HFindReplace.FindRegExp`)은 역추적이 없는 선형 시간 엔진(Thompson NFA / Pike VM)과 걸음·시간 계량으로 돌리며, 역참조(`\1`·`\k<...>`)와 전방·후방 탐색, 1,000을 넘는 `{n,m}` 반복 횟수를 명시적으로 거절한다(`.*x|a`처럼 앞선 갈래가 끝까지 탐색한 뒤 실패하는 비고정 패턴은 일치 횟수에 따라 제곱 비용이 들 수 있으나 JS `RegExp`와 같으며, 시간·걸음 한도에 걸리면 즉시 중단·롤백하고 정규식 시간 초과 안내를 띄운다).
2. **단일 실행 취소와 개체·메모 보호(`studio-plugin/macro-host.mjs`, `macro-compat.mjs`)**:
   - `runMacro`는 `own = true`로 감싼 단일 `host.transaction('macro', ...)` 안에서 실행되어 실행 취소 한 단계가 되며, 바뀐 내용이 없으면 `tx.markNoOp()`으로 실행 취소 단계와 저장 안 됨 표시를 남기지 않고, 실행이 성공하고 실제로 문서가 바뀌었을 때(`result.ok && result.changed`)만 `foreign += 1`을 올린다. `agent-plugin.mjs`의 `keepingObjects` 래퍼 대신 매크로 호스트 자체의 실행 전·후 개체·메모 스냅샷 비교 검사(`captureProtectionSnapshot`)를 같은 트랜잭션 안에서 수행한다.
   - 문법·실행 오류, 미지원 동작(`Undo`·`Redo` 포함), 한도 초과, 개체·메모 손실이 발생하면 트랜잭션을 통째로 되돌리고 오류 줄·칸(실행 끝 검사 실패와 정규식 시간 초과는 별도 안내) 또는 미지원 동작 이름을 알린다. 매크로 실행 중 편집기 명령(`automation.execute`)을 호출하지 않고 엔진 호출만 사용한다.
   - `setCharFormat`을 선택 없이 부르면 다음 `insertText`에 대기 서식으로 적용된다. `selectUp`/`selectDown`은 문서 첫 줄·마지막 줄 경계에서도 문서 처음·끝까지 선택을 확장하며, `deleteBackward`/`deleteForward`는 키 매크로 기록기와 동일한 보호 개체·메모 삭제 판정 함수를 공유해 문단 안 인접 개체뿐 아니라 문단 경계를 넘어 합쳐지는 삭제(예: 표 앞 문단 끝 `Delete`, 표 뒤 문단 처음 `Backspace`)까지 일치하게 막는다. 호환 객체에서 `HParaShape` 여백·들여쓰기·문단 간격은 ParameterSet Table `ParaShape` 및 HWP 5.0 표 43 기준의 짝수 URC 정수(`HWPUNIT = 1/7200 in = 1/100 pt`, URC bit 0 = 0일 때 `2 × HWPUNIT = 200/pt`)만 받으며 홀수 URC 값과 `0`(백분율) 이외의 `LineSpacingType`은 거절한다. `HCharShape.TextColor`는 BGR 정수 또는 `#RRGGBB` 문자열을 받으며, `HFindReplace`는 `FindRegExp`를 쓰고 `UseWildCards`·`RegExp`는 거절한다.
3. **로컬 매크로 저장소와 평문 `.ieummacro` 주고받기(`src/main/macros.ts`, `src/main/macros-ipc.ts`)**:
   - 매크로는 앱 데이터 폴더의 `<userData>/hwp-macros.json`(최대 2 MiB)에만 저장하고, 동기 임시 파일(`wx`, `flush`) 교체로 원자적으로 쓴다. 저장 파일이 손상되었거나 용량 상한을 넘으면 원본을 건드리지 않고 `.corrupt-<시각>` 백업을 남긴 뒤 모든 쓰기를 거절한다.
   - 모든 `hwp:macros-*` IPC 창구는 `hwpViews.has(e.sender.id)`를 확인한다. 평문 텍스트 파일(`.ieummacro`, 최대 256 KiB) 내보내기·가져오기 경로는 메인 프로세스의 파일 대화상자에서만 정하고 렌더러는 경로를 넘기지 못한다. 가져오기 시 스크립트 전문(숨은 제어 문자는 `[U+XXXX]`로 표시)과 구문 검사 결과를 먼저 보여 주고 사람이 확인한 뒤에만 저장하며, 저장 전에는 실행할 수 없고 `@slot` 헤더는 무시해 항상 `slot: null`로 저장한다.
   - 문서 파일(`.hwp`, `.hwpx`) 안에 들어 있는 매크로는 읽지도 실행하지도 않는다.
4. **키 매크로 기록과 11개 단축키 슬롯(`studio-plugin/macro-recorder.mjs`, `workpane-menu.mjs`, `src/renderer/macro/`)**:
   - 도구 메뉴 항목과 단축키(`Alt+Shift+H` 기록 시작/끝, `Alt+Shift+X` 기록 끝, `Alt+1`–`Alt+9`·`Alt+0`·`Alt+-` 11개 실행 슬롯)를 제공한다. macOS에서는 Option 조합 키가 문자 입력에 쓰이므로 Option 단축키를 가로채지 않고 **도구 > 매크로** 메뉴로만 접근한다.
   - 기록하는 동안 편집기 상단에 기록 중 표시와 중지 단추를 띄운다. 글자 입력, 커서 이동, 서식·스타일·표 삽입 등 지원하는 편집 동작을 사람이 읽고 고칠 수 있는 스크립트 줄로 누적하며, 미지원 명령·마우스 클릭·본문 문단 밖 편집(표 칸·글상자·각주·머리말 등)·이동 전·후 위치 중 하나라도 본문 밖인 키 이동(본문 밖으로 들어가거나 빠져나오는 이동)·매크로 문서 API와 같은 판정 함수로 걸러낸 보호 개체·메모 삭제(문단 안 인접 개체 및 문단 경계를 넘어 합쳐지는 `Backspace`/`Delete` 포함)가 들어오면 스크립트에 넣지 않고 즉시 알린 뒤 기록을 마친 뒤 건너뛴 항목 목록을 보여 준다.
5. **선택 기능 "AI에게 쓰게 하기"(`src/renderer/macro/`)**:
   - AI가 켜져 있을 때만 매크로 편집 창에 표시되며, 공용 AI 창구·제공자 선택 규칙·보내기 문지기를 그대로 따른다(요금이 나가는 경로로 스스로 바뀌지 않는다).
   - 사용자가 입력한 작업 설명과 매크로 문법·API 안내만 전송하며, 열려 있는 문서 본문은 보내지 않는다. 생성된 초안은 편집 창의 스크립트 입력 칸에만 들어가며 자동으로 저장하거나 실행하지 않는다. AI 끄기 상태에서는 기능을 숨긴다.

## 버린 대안

- **진짜 JavaScript 격리 실행(`vm` 모듈·숨은 창)**: 프로토타입 체인 탈출, 비동기 타이머, 전역 객체 누수 위험이 크고, 동기 단일 트랜잭션·정확한 줄/칸 오류 보고·개체 손실 롤백을 보장하기 어렵다. 제한된 동기 AST 해석기가 공격 표면을 최소화한다.
- **실행 중 멈춤 단추를 위한 비동기 분할 실행**: 매크로를 여러 틱으로 쪼개 실행하면 그사이 사람의 입력이 끼어들거나 실행 취소 한 단계·오류 시 통째 되돌리기 보장이 깨진다. 대신 동기 실행에 시간·걸음·깊이·크기 상한을 엄격히 걸었다.
- **편집기 명령(`automation.execute`)이나 외부 제어 도구 재사용**: 편집기 UI 명령은 내부적으로 별도 실행 취소 단계나 대화상자를 열어 단일 트랜잭션과 개체 보호를 깨뜨린다. 엔진 호출만 감싼 전용 문서 API와 호환 계층을 두었다.
- **문서 파일에 포함된 매크로 읽기·자동 실행**: 외부에서 받은 문서가 악성 매크로를 실어 나를 수 있는 전형적인 공격 경로다. 문서 내부 매크로는 아예 다루지 않고 로컬 저장소와 사용자 확인을 거친 `.ieummacro` 파일만 허용한다.

## 결과

- AI 없이도 키 매크로 기록, 11개 단축키 슬롯, 스크립트 직접 작성, 기존 매크로 스크립트 꼴(`HAction`·`HParameterSet`) 실행, `.ieummacro` 내보내기·가져오기를 모두 로컬에서 안전하게 쓸 수 있다.
- 모든 매크로 실행은 단일 실행 취소 단계와 개체·메모 보호, 실패 시 통째 되돌리기를 보장한다.
- 터미널 명령어와 MCP에는 매크로 실행을 열지 않는다.
- 작업창(결정 0172), 차례·색인·제출본(결정 0174), 참고문헌(결정 0175)에 이어 한글 논문 작성 4개 묶음이 모두 마무리된다. 22개 언어 모달 화면 넘침과 실제 AI 제공자 연결에서의 초안 작성 확인은 사람 확인 항목으로 남긴다.
