# 0176. 모바일 1판 HTML 편집기와 마크다운: 무스크립트 미리보기·내보내기, 숨기기 검증, 바이트 보존

- 날짜: 2026-11-26
- 상태: 모바일 1판(배포 전), 주인 승인(2026-11-26·2026-11-27)

## 맥락

모바일 1판(T4)은 HTML 편집기를 새로 넣고, 기존 마크다운 편집기에 바이트 그대로 저장, 찾아 바꾸기, 워드·ODT 내보내기, AI 숨기기(가리기)를 더해야 했다. 모바일에는 PC처럼 스크립트를 켠 격리 Electron 창(결정 [0142](0142-isolate-html-conversion-window.md))이 없고, 기존 마크다운→한글 내보내기는 공용 "다른 이름으로 저장" 명령을 써서 열린 마크다운 세션을 새 `.hwpx`로 덮어쓰는 문제가 있었다. 또한 기존 모바일 마크다운 AI는 숨긴 글을 가리지 않고 원문 전체를 모델에 보내는 빈틈이 있었다.

## 결정

1. **세션을 바꾸지 않는 새 파일 내보내기 명령(주인 승인 2026-11-26).** 마크다운·HTML의 워드·ODT·한글(`.hwpx`) 내보내기는 열린 문서 세션·최근 목록·복구 사본·바뀜 상태를 건드리지 않는 `mobile_web_save_new_file`(허용 MIME 셋만)로 쓴다. 새 파일은 최근 목록에 넣지 않으므로 마크다운→한글 완료 알림의 `[열기]`는 뺀다(결정 [0175](0175-mobile-v1-pdf-tools-and-shared-ops.md)의 세션 비변경 원칙과 같음).
2. **스크립트 없는 HTML 미리보기와 내보내기(주인 승인 2026-11-26).** HTML 미리보기와 워드·ODT 내보내기는 모두 스크립트를 못 돌리는 틀(`sandbox="allow-same-origin"`)을 쓴다. 미리보기는 PC와 같은 모습을 위해 `http(s)` 그림·스타일·글꼴을 불러오며(주인 승인 2026-11-26), 미리보기·내보내기 사본에서는 `<meta http-equiv="refresh">`를 무력화한다. 내보내기에서 스크립트가 그리는 내용이나 화면 캡처가 필요한 요소(복잡한 SVG·그라디언트 등)는 빠지며 알림으로 알리고, 찍지 못한 블록은 보이는 글을 회색 문단으로 남기거나 글이 없으면 `"[옮기지 못한 그림]"`(22개 언어)을 둔다.
3. **HTML 1판 편집 범위와 AI 도구 범위(주인 승인 2026-11-26·2026-11-27).** 1판 HTML 편집은 요소 글 고치기, 요소 지우기, 소스 직접 편집으로 좁힌다. 서식·옮기기·복제·그림 도구·스타일 패널은 2판으로 미룬다(디자인 시스템 5.6의 HTML 줄과 다름). 1판 HTML·마크다운 AI는 공용 웹·그림 도구를 연결하지 않고 문서 도구(`get_outline`·`read_source`·`apply_ops` 등)만 제공한다(주인 승인 2026-11-27).
4. **마크다운·`.txt` AI 숨기기 닫힌 쪽 검증.** PC 마크다운과 같은 `<span class="redact-span" data-redaction="" data-label="…">` 형식을 쓴다. 모델이 보는 글은 매번 공용 `redactMarkdownSource`와 한 글자도 다르지 않을 때만 보내고, 다르거나 오류면 아무것도 보내지 않는다. 모델 편집은 `{{…}}` 목록의 순서·글 일치와 재가림 일치를 통과할 때만 적용한다. 찾아 바꾸기는 숨김 표시가 있는 문서에서 `<span`·`</span`·`data-redaction` 개수를 바꾸거나 가림 오류를 내는 바꾸기를 거절하고, 숨기기는 `<`가 없으며 새 span에 꼭 맞는 선택만 받는다. `.txt`에도 같은 규칙을 건다.
5. **바이트 그대로 저장과 비-UTF-8 읽기 전용.** 마크다운·`.txt`·HTML은 읽을 때 BOM과 줄 끝(CRLF/LF)을 기억해 저장 시 되입히며, 고치지 않은 문서는 원본 바이트 그대로 쓴다. UTF-8이 아닌 파일은 글자 깨짐을 막기 위해 그 문서만 읽기 전용으로 연다.

## 버린 대안

- **저장소(`src/storage/**`)에 "세션 유지 + 최근 목록 추가" 새 함수 추가:** T6과 같은 파일에서 충돌한다.
- **HTML 내보내기에서 문서 스크립트 실행:** 모바일 웹뷰에는 별도 격리 세션이 없어 앱 셸과 같은 출처·권한 위험이 생긴다.
- **비-UTF-8 파일의 임의 인코딩 추정 저장:** 잘못된 인코딩으로 덮어쓰면 원본 글자가 복구 불가로 깨진다.

## 결과

- 마크다운 AI가 숨긴 글을 모델에 보내던 경로를 막았고(배포 전), PC와 모바일 사이에서 마크다운 숨김 표시가 그대로 호환된다.
- Android 16 에뮬레이터에서 HTML `<script>` 미실행 격리와 편집·저장, 390px 미리보기에서 마크다운 찾아 바꾸기·워드 내보내기·숨기기가 확인되었다.
- 통합 수정에서 `<svg><head>` CSP 우회·문자 참조 refresh 우회·Windows Rollup 경로 정규화·T7 `MobileAiBlockedError` 연결을 마무리하며, 디자인 시스템 5.6 HTML 줄 정리와 `.txt` 숨기기 유지 여부는 추후 확정한다.
