# 0173 — 파일 목록 칸에서 스페이스바로 빠른 미리보기 창을 띄운다

## 맥락

결정 0168에서 편집기 탭 옆에 파일 목록 칸을 넣을 때, 홈 화면의 스페이스바 빠른 미리보기는 다음 과제로 미뤄 두었다. 편집기 탭은 `WebContentsView`라 껍데기 화면(DOM) 위에 그려지므로, 홈처럼 껍데기 DOM 안에 겹치는 카드를 띄우면 편집기 화면 밑에 깔려 보이지 않는다.

반면 껍데기 앱에는 이미 Windows 탐색기·바탕화면용 독립 미리보기 창(`src/main/quick-look/quick-look-window.ts`, 화면은 홈과 같은 `QuickLookView`)이 있다. 문서를 열기 전에 파일 목록 칸에서 `Space`로 내용을 훑어보고 `↑`/`↓`로 넘기다 원하는 문서만 `Enter`로 열 수 있으면, 탭을 불필요하게 여닫지 않아도 된다.

## 결정

- **기존 독립 미리보기 창 하나를 재사용한다.** 새 창 종류를 만들지 않고 `quick-look-window.ts`의 `BrowserWindow`를 그대로 쓴다. 홈 미리보기·파일 목록 칸 미리보기·탐색기 미리보기 세 곳 모두 같은 `QuickLookView` 화면과 디자인 토큰(`packages/ui/src/tokens.css`)을 써서 한 제품처럼 보이고, 파일을 바꿀 때도 같은 창에 내용만 바꿔 보내 깜빡이지 않는다.
- **창 위치·크기와 움직임.** 파일 목록 칸에서 열 때는 화면 가운데가 아니라 **칸 바로 오른쪽, 문서 영역 위**에 띄운다(`computeFilePanelQuickLookBounds`). 칸 오른쪽 가장자리에서 12px 간격을 두고 문서 영역 높이에 맞춰 세로 가운데에 놓으며, 작업 영역(`workArea`) 밖으로 나가지 않게 자른다. 모서리는 12px, 그림자는 기존 토큰을 쓰고, 열고 닫을 때는 140ms 안팎으로 투명도와 왼쪽에서 4px 미끄러짐을 준다(`prefers-reduced-motion`이면 움직임 없음). 이미 칸 모드로 열려 있을 때 다음·이전 파일로 넘기면 창의 위치·크기를 다시 바꾸지 않고 본문만 바꿔 깜빡임과 높이 출렁임을 막는다. 탐색기에서 열 때는 기존처럼 화면 가운데(812×652)에 띄운다.
- **미감과 머리 줄.** 미리보기 창 머리 줄은 형식 배지 + 파일 이름(굵게, 말줄임)과 그 아래 옅은 한 줄("형식 · 크기 · 고친 날짜")을 두고, 오른쪽에 칸 목록 안 위치("3 / 12"), ↑↓ 단추, 옅은 폴더 보기 단추, 주 행동 채움 단추("이음오피스에서 열기") 하나, 닫기 단추를 둔다. 파일 목록 칸에서 미리보기 중인 줄은 왼쪽 색 막대(강조 띠) 없이 옅은 배경 토큰(`--bg-hover-strong`)으로만 표시한다. 파일 줄의 눈 모양 미리보기 단추는 마우스를 올리거나 포커스가 있을 때만 보이고, 말풍선은 칸 밖으로 잘리지 않게 네이티브 `title`을 쓴다. 밝게·어둡게 두 테마 모두 디자인 토큰(`packages/ui/src/tokens.css`)만 쓴다.
- **여는 길과 초점.**
  - 파일 목록 칸의 모든 파일 줄(이 문서가 있는 폴더, 폴더 나무, 최근 문서, 찾기 결과)에서 동작한다.
  - 파일 줄에 초점이 있을 때 `Space`를 누르면 미리보기를 열고, 같은 파일이면 닫는다. 칸 안(입력란·단추가 아닌 자리)에 초점이 있고 파일 줄에 마우스가 올라가 있을 때도 `Space`로 그 파일을 미리 본다. 파일 줄에 마우스를 올렸을 때만 보이는 작은 미리보기 단추와 오른쪽 클릭 메뉴의 "빠른 미리보기" 항목에서도 같은 창을 연다.
  - 미리보기 창은 `showInactive()`로 띄워 키보드 초점을 파일 목록 칸에 남긴다. 그래서 곧바로 `↑`/`↓`로 칸의 표시 중인 파일 줄을 따라 넘기고, `Enter`로 탭에 열고(이미 열린 파일이면 그 탭으로 전환), `Space`/`Esc`로 닫을 수 있다.
  - 사용자가 스크롤이나 시트·썸네일 전환을 위해 미리보기 창 안을 클릭해 초점이 창으로 옮겨간 뒤에도, 창의 `↑`/`↓`(및 헤더의 이전·다음 단추)·`Enter`·`Space`/`Esc`가 똑같이 동작한다. 창에서 `↑`/`↓`를 누르면 껍데기가 칸에 이동을 요청(`file-panel:quick-look-step`)해 칸의 초점·표시와 미리보기 내용을 함께 맞춘다. 창이 닫히면 초점을 본 창과 해당 파일 줄로 돌려준다.
  - 홈 화면(`Home.tsx`)은 편집기 탭이 열린 뒤에도 숨긴 채 DOM에 남아 있으므로, 숨겨진 동안에는 홈의 전역 `Space` 키 처리기가 동작하지 않게 막는다.
- **편집기 입력과 겹치지 않게 한다.** `Space`는 파일 목록 칸 DOM의 키 처리에서만 받고, 편집기 `WebContentsView`의 `before-input-event`에서는 가로채지 않는다. 찾기 입력란에 글자를 치는 동안에도 `Space`는 그대로 공백 입력으로 둔다.
- **자동으로 닫히는 조건.** 칸에서 연 미리보기 창은 칸을 닫거나 홈 탭으로 바꾸거나, 사용자가 편집기 본문을 클릭하거나, 다른 프로그램으로 창 전환하거나, 본 창을 최소화·닫을 때 저절로 닫혀 문서나 다른 앱 위에 남지 않는다.
- **읽기 범위 제한.** 파일 목록 칸이 요청한 미리보기 경로는 뒷단이 기존 칸 범위 검사(`isPanelAllowedPath`: 폴더 뿌리 안쪽, `isRevealablePath`, `isBesideOpenDocument`, 열린 문서 폴더와 그 아래)를 통과한 일반 파일만 허용한다. 범위 밖 경로는 거절한다.
- **설정과의 관계.** `app-settings.json`의 `quickLook.explorerSpacePreview`는 Windows 탐색기·바탕화면 전역 후크용 스위치다. 홈의 앱 안 미리보기와 마찬가지로, 파일 목록 칸 미리보기는 이 스위치에 묶지 않고 모든 운영체제에서 항상 동작하게 둔다. 탐색기 스위치를 끌 때는 탐색기에서 연 창만 닫는다.

## 택하지 않은 것

- **파일 목록 칸 전용 별도 `BrowserWindow`를 하나 더 만들기.** 창 코드와 preload가 중복되고, 미리보기 창 두 개가 동시에 뜰 수 있다. 단일 창을 출처(`explorer` | `file-panel`)로 나누어 관리하는 편이 단순하다.
- **문서 영역을 한 번 더 밀어내 옆 칸으로 그리기.** 좁은 창에서 편집 중인 문서 폭이 지나치게 줄어들고, 잠깐 훑고 닫는 용도에서는 문서 위에 가볍게 떴다 사라지는 편이 덜 거슬린다.
- **단일 클릭을 미리보기로 바꾸기.** 결정 0168에서 파일 한 번 클릭은 바로 열기로 정했다. `Space`·호버 단추·오른쪽 클릭 메뉴로 미리보기를 분리해 기존 열기 흐름을 깨지 않는다.
- **탐색기 설정(`explorerSpacePreview`)으로 칸 미리보기까지 끄기.** 그 설정은 Windows 전용 전역 후크 스위치이고 macOS·Linux에는 보이지 않는다. 홈 미리보기와 기준을 맞춘다.
- **화면 전체 어두운 가림막과 강조 띠.** 가림막은 왼쪽 파일 목록을 가려 연속 탐색 흐름을 끊고, 줄 왼쪽의 강조 띠는 목록을 과하게 돋보이게 해 기존 칸과 어울리지 않는다.
