# 0134 — 회사가 정책 값 하나로 바깥 연결을 끊고, 로컬 AI만 남긴다

상태: 정함(2026-11-11), 구현 전. 계획은 [`docs/plans/org-offline-policy.md`](../../plans/org-offline-policy.md)에 있다.

## 맥락

- 회사에서 쓰는 사람들에게서 같은 문의가 거듭 들어왔다. AI가 기본으로 들어 있고 누구나 켤 수 있어서, 회사가 허락하지 않은 AI에 직원이 문서를 보낼 수 있다. 그래서 AI가 없거나 막힌 판을 따로 달라고 했다.
- 사용자의 설정 파일(`ai-settings.json`)에는 이미 AI의 인터넷 도구를 끄는 값(`internetTools`)이 있다. 하지만 데이터 폴더에 있어 사용자가 고칠 수 있고, AI 연결 자체와 Google 드라이브 같은 다른 연결은 끄지 못한다.
- Windows 설치 파일은 관리자 권한 없이 사용자 폴더에 깔린다. 회사가 깔아 준 판을 직원이 일반판으로 덮어 깔 수 있다.
- 바깥으로 나가는 연결은 PRIVACY.md의 표에 40가지가 넘게 적혀 있고, 표에 없는 것(Linux의 맞춤법 사전 받기, 문서 속 바깥 그림)도 있다. 뒷단에서 `fetch`를 부르는 파일만 21개다.

## 결정

- **설치 파일은 하나다.** 회사 관리자가 사용자가 고칠 수 없는 곳에 정책 값을 넣는다. Windows는 `HKLM\SOFTWARE\Policies\IeumOffice`의 `BlockExternalConnections`(DWORD 1), macOS는 관리되는 환경설정, Linux는 `/etc/ieumoffice/policy.json`이다. 앱과 터미널 명령어가 시작할 때 읽는다.
- **정책이 켜지면 바깥으로 나가는 연결을 모두 끊는다.** 구독, ChatGPT 직접 연결, 키 제공자, 무료 연결, 에이전트 창, 웹 검색·읽기, 이미지 생성, Google 드라이브, GitHub에서 스킬 받기, 의견 보내기, 사이트 안내, 마크다운 그림 올리기, 파일 검색 다시 순위 매기기, 링크 미리보기가 모두 든다.
- **로컬 AI는 남긴다. 이 PC와 사내망까지다.** 루프백, 사설 IP, 실제로 사설 IP로 풀리는 이름 주소를 허용하고 공인 주소는 거절한다. PDF·EPUB의 AI 작업과 스킬은 로컬 AI로 돈다.
- **업데이트 확인만 예외다.** 이 저장소의 GitHub 릴리스를 읽고 받는 요청만, 업데이트 세션과 업데이트 전용 받기 함수에서만 통과한다. 업데이트도 직접 배포하려는 회사를 위해 `AllowUpdateCheck`(없으면 1)를 둔다.
- **MCP 서버는 모두 막는다.** 원격 서버도, 이 PC에서 프로그램을 띄우는 서버도 띄우거나 부르지 않는다. 띄운 프로그램이 앱과 상관없이 인터넷에 닿을 수 있어 앱이 지킬 수 없기 때문이다. 앱 자신이 여는 루프백 MCP 서버는 그대로다.
- **세 층으로 막는다.** 입구를 감추고, 제공자 선택을 로컬 AI로 좁히고, 앱의 모든 네트워크 길목(Electron 세션 전부, 뒷단의 Node 요청, 자식 프로세스 띄우기)에서 한 판정 함수로 거절한다. 앞 층이 빠뜨린 것은 뒤 층이 막는다.
- **정책 값을 읽지 못하면 켜진 것으로 본다.** 키는 있는데 값을 읽지 못한 경우다. `reg.exe`가 막히면 PowerShell의 레지스트리 읽기로 한 번 더 읽고, 둘 다 안 되면 켜진 것이다. 키가 없으면 지금과 같다.
- **문서 속 링크는 사용자의 브라우저로 그대로 연다.** 앱이 스스로 여는 바깥 페이지(의견 보내기 양식, 소개 사이트의 안내)만 감춘다.
- **회사용 파일 묶음은 릴리스 자산으로 낸다.** `.reg`, 그룹 정책 서식, 구성 프로파일 예시를 zip 하나로 묶고, 소개 사이트에는 짧은 안내와 링크를 둔다.
- **저장된 키·로그인·드라이브 연결은 지우지 않는다.** 정책이 켜진 동안 쓰지 않을 뿐이고, 풀리면 그대로 돌아온다.
- **이 정책은 보안 경계가 아니라고 회사에 알린다.** 앱이 스스로 지키는 장치이고, 확실히 막으려면 회사 네트워크에서 막아야 한다.

## 버린 대안

- **AI 없는 판을 따로 빌드한다.** 직원이 일반판을 덮어 깔면 소용이 없고, 릴리스마다 만들고 확인할 설치 파일이 두 배가 된다.
- **사용자 설정 파일에 끄는 값을 둔다.** 사용자가 고칠 수 있어 회사가 기대는 장치가 되지 못한다.
- **기능 하나하나만 막는다.** 표에 없는 연결을 놓친다. 이미 Linux 맞춤법 사전 받기가 표에서 빠져 있었다.
- **로컬 AI를 이 PC로만 좁힌다.** 회사들은 사내 서버에 모델을 올려 두는 경우가 많아, 이 PC만으로는 쓰기 어렵다.
- **업데이트도 끊는다.** 회사 IT가 배포해야만 보안 수정을 받게 된다. 원하는 회사는 `AllowUpdateCheck`로 끈다.
- **PC 안에서 띄우는 MCP 서버는 허용한다.** 그 프로그램이 바깥에 닿는지는 앱이 알 수 없다.

## 결과

- PRIVACY.md의 모든 줄에 "정책이 켜지면"이 하나씩 정해진다. 새 바깥 연결을 더할 때는 정책이 켜진 경우의 처리도 같이 정해야 한다. `docs/standards.md`에 그 규칙을 더한다.
- `docs/contracts.md`에 정책 값과 새 오류 종류 `blocked-by-policy`가 약속으로 들어간다.
- 회사에 건넬 파일(`.reg`, 그룹 정책 서식, 구성 프로파일 예시)과 안내 문서가 생긴다.
- Mac·Linux의 정책 읽기는 주인이 확인하지 못하고 사용자 보고로 확인한다.
