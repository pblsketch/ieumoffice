# 0136 — 새 문서를 통째로 만드는 요청에서는 그 편집기의 스킬을 먼저 읽게 한다

결정 0132(네 편집기의 문서 작성 스킬)와 결정 0122(쓰는 곳)에 이어진다.

## 맥락

- 결정 0132로 한글·마인드맵·다이어그램·HTML 편집기에 문서 작성 스킬을 하나씩 실었다. 처음 상태는 "스스로 쓰기"다. 스킬의 이름과 설명이 지시문의 목록에 실리고, AI가 `use_skill`로 본문을 읽는다.
- 2026-11-12에 실제 구독으로 확인했다. 스킬을 칩으로 붙이면 네 편집기 모두 본문대로 했다(쓰고 다시 읽기, 지어낸 항목 없음, 점검). 칩 없이 새 문서를 만들어 달라고 한 여섯 번(haiku 다섯, Sonnet 하나)은 한 번도 `use_skill`을 부르지 않고 바로 쓰는 도구를 불렀다. 스킬 설명을 "Use this skill whenever…"로 시작하게 바꿔도 같았다.
- 목록의 머리말은 "Skills you may use on your own"이었다. 편집기 지시문은 "새 지도는 `write_map`으로 한 번에"처럼 쓰는 법을 바로 가르친다. 써도 된다는 목록보다 쓰는 법이 앞섰다.
- 스스로 쓰이지 않으면, 스킬을 아는 사람이 칩으로 붙일 때만 쓰인다. 기본 스킬로 실은 뜻이 거의 없다.
- 스킬을 읽으면 그 요청의 입력이 늘어난다. 저장소 주인은 "새 문서를 처음부터 만드는 요청에만" 걸리게 좁혀 고치기로 했다(2026-11-12).

## 결정

- **스스로 쓰기 목록을 둘로 나눈다.** 그 편집기를 쓰는 곳으로 적은 스킬(`ieum-editors`가 "모든 편집기"가 아닌 것)을 앞에 따로 묶고, 나머지는 예전 머리말 아래에 둔다(`autoSkillsSection`, `packages/agent-core/src/user-skills-skill.ts`).
- **앞 묶음의 머리말이 규칙이다(`EDITOR_SKILLS_HEADING`).** 사람이 새 작업물 전체(문서, 지도, 다이어그램, 페이지)를 처음부터 또는 준 자료로 만들어 달라고 하면, 첫 도구 호출은 맞는 스킬의 `use_skill`이고 그다음에 쓰는 도구를 부른다. 쓰는 법을 알아도 그렇다. 이미 있는 것을 고치는 요청과 질문에는 걸리지 않는다.
- **같은 조건을 `use_skill` 도구 설명에도 적는다.** 머리말만 바꾼 첫 문구로는 마인드맵에서만 됐고 다이어그램과 한글에서는 건너뛰었다. 머리말을 "Rule: … your first tool call is use_skill …"로 고치고 도구 설명에 한 문장을 더한 뒤 네 편집기 모두에서 됐다.
- **기본 스킬만의 규칙이 아니다.** 사람이 자기 스킬의 쓰는 곳을 한 편집기로 정하면 그 스킬도 앞 묶음에 실린다. 쓰는 곳을 그렇게 좁혔다는 것이 "이 편집기의 일에 쓰라"는 뜻이기 때문이다. "모든 편집기" 스킬은 예전과 같다.
- **목록의 상한은 그대로다.** 두 묶음을 합쳐 설명 300자, 설명 붙는 줄 100개, 이름만 싣는 줄의 상한을 센다. 편집기용 스킬이 먼저 자리를 얻는다.
- **홈 AI 질문과 에이전트 창은 바뀌지 않는다.** 편집기가 없는 창에서는 묶음을 나누지 않고 예전 목록 하나를 싣는다.

## 택하지 않은 것

- **편집기 지시문마다 "먼저 스킬을 읽어라"를 넣기.** 편집기 열 곳의 지시문을 따로 고쳐야 하고, 사람이 그 스킬을 끄거나 "부를 때만"으로 바꿨을 때 없는 스킬을 가리키게 된다. 목록은 켜진 스킬만 싣는다.
- **앱이 요청 글을 보고 스킬 본문을 미리 붙이기.** "새로 만들기"인지를 앱이 낱말로 가려야 하는데, 21개 언어의 요청을 낱말로 가릴 수 없다. 틀리면 작은 수정에도 본문이 실린다.
- **스킬 본문을 지시문에 늘 싣기.** 모든 요청이 그만큼 한도를 쓴다(결정 0132가 버린 길).
- **모든 스스로 쓰기 스킬에 같은 규칙.** "모든 편집기" 스킬(회의록, 공지 쓰기 등)은 새 문서를 만드는 요청마다 맞는 것이 아니다. 예전처럼 AI가 고른다.
- **수정 요청에도 걸기.** 글자 하나를 바꾸는 요청이 스킬 본문만큼 입력을 더 쓴다.

## 결과

- 실제 구독으로 본 것(2026-11-12, 모두 haiku, 칩 없음, 9번). 최종 문구에서 새로 만들어 달라는 요청은 네 편집기 모두 `use_skill`이 첫 호출이었다: 마인드맵(`use_skill` → `write_map` → `read_map`), 다이어그램(`use_skill` → `apply_diagram_ops` → `read_diagram`), 한글(`use_skill` → `insert_paragraphs` → `format_paragraph` 세 번 → `read_document`), HTML(`use_skill` → `plan_page` → `get_outline`). 대화에는 "〈이름〉 스킬을 썼습니다"가 보였다. 마인드맵의 작은 수정 요청("중심 주제 이름을 바꿔 줘")은 두 문구 모두에서 `read_map` → `edit_map`으로 스킬을 부르지 않았다. 첫 문구의 세 번은 마인드맵에서 됐고 다이어그램과 한글에서 건너뛰었다.
- 한도. 스킬을 읽는 요청은 입력이 는다. 본문이 한 차례 실리고, 스킬의 점검 절대로 다시 읽는 차례가 더 생기기 때문이다. 같은 요청의 입력 합계가 마인드맵 21.6k → 52.2k, 다이어그램 17.6k → 47.2k 토큰이었다. 수정 요청은 그대로다(마인드맵 33.3k).
- 확인하지 않은 것: Codex 구독과 키 제공자, haiku 밖의 모델로 한 최종 문구 확인, 수정인지 새로 만들기인지 애매한 요청("이 문서를 보고서로 다시 써 줘")에서 어느 쪽으로 가는지. 한도를 쓰므로 더 돌리지 않았다. `docs/tracking/status.md` 30번에 남긴다.
- 사람이 스킬을 읽게 하고 싶지 않으면 설정 → 스킬에서 그 스킬을 "부를 때만"으로 바꾸거나 끈다. 그러면 목록에서 빠지고 규칙도 걸리지 않는다.
- 같은 확인에서 스킬과 상관없이 찾은 두 가지를 `docs/tracking/findings.md`에 적었다: HTML 편집기의 브리프 작성이 haiku에서 빈 답으로 끝나는 것, 자동 조작으로 띄운 창에서 `check_pages`가 답하지 않는 것.
- 고친 문서: `docs/business-rules.md`("스킬"의 "AI가 스스로 쓰기"), `packages/agent-core/AGENTS.md`, `docs/tracking/status.md`(30번).
- 시험: `packages/agent-core/tests/user-skills-skill.test.ts`(편집기용 스킬이 머리말 아래 먼저 실리는지, 다른 편집기와 편집기 없는 창에서는 목록 하나인지, 두 묶음이 상한을 함께 세는지, 머리말과 도구 설명의 조건 문장).
