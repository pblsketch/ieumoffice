# 0179. 모바일 1판 AI: PC 프로토콜 재사용과 Rust 봉인 중계, 공용 도구·주소 확인·결과 보관소

- 날짜: 2026-11-26
- 상태: 모바일 1판(배포 전), 주인 승인(2026-11-26·2026-11-27)

## 맥락

1차 모바일 프로토타입의 Rust AI 스트림은 `AgentMessage`를 제공자 형식으로 바꾸지 않고 그대로 보내며 응답의 도구 호출도 읽지 않아, 실기기에서 문서를 고치는 AI가 동작할 수 없었다(가짜 다리 대본에서만 가려졌다). 또한 모바일 1판(T7)은 기본 꺼짐(결정 [0165](0165-mobile-scope-and-design-system.md))을 유지하면서 키 제공자·OpenRouter 무료 연결(`:free` 전용)·직접 운영 서버, 웹·그림 검색, 주소 읽기, 사진 보기, 키 방식 그림 만들기, 대기열, 변경 카드(결정 [0151](0151-one-ai-changes-card-and-marks.md)), 숨김 차단 알림을 갖춰야 했다.

## 결정

1. **PC 프로토콜 코드 재사용과 Rust 봉인 중계(주인 승인 2026-11-26).** PC의 `streamOpenAiCompatible`·`streamAnthropic`·`streamGemini`와 그림 생성 코드는 Node 전용 의존이 없으므로 고치지 않고 웹뷰에서 그대로 쓰고, 모바일 빌드(`config/tracks/ai.ts`)에서 `ai-provider/src/fetch.ts`만 모바일 판으로 바꿔 끼운다. 웹뷰는 키 자리에 `__sealed__:<제공자>` 표식만 넣고, Rust 중계(`src-tauri/src/ai/relay.rs`)가 그 제공자의 정해진 HTTPS 호스트(직접 운영 서버는 저장한 HTTPS 주소의 호스트)로 나가는 요청에서만 봉인 저장소의 실제 키로 치환한다. 다른 호스트·`http`·리다이렉트는 거절한다.
2. **키 없는 검색과 모바일 공개 주소 판정(주인 승인 2026-11-26).** 검색은 키 없는 길만 둔다(웹 검색 Parallel → DuckDuckGo, 그림 검색 DuckDuckGo; Serper 등 검색 키 설정은 1판 제외). 주소 읽기·그림 받기는 Rust 공개 주소 요청(`src-tauri/src/ai/web.rs`)으로 사설·루프백·링크 로컬을 거절하고 리다이렉트는 5회까지 매번 재검사한다. IPv6 전용 휴대폰 망 호환을 위해 NAT64(`64:ff9b::/96`)와 6to4(`2002::/16`)는 내부 IPv4로 판정하며, `198.18.0.0/15`는 DNS 응답일 때만 VPN fake-ip로 허용한다.
3. **인터넷 스위치·주소 확인 시트와 그림 만들기 스위치(주인 승인 2026-11-26).** 결정 [0062](0062-outbound-tools-switch-and-address-check.md) 규칙(인터넷 도구 기본 켬, 대화에 없던 주소 확인)을 그대로 따르되 운영체제 창 대신 AI 창 위 시트로 묻는다. 그림 만들기는 설정에서 따로 켜며(기본 끔), 1판 제공자는 base64로 답하는 OpenAI·Gemini 둘만 두고 OpenRouter 무료 연결은 제외한다.
4. **변경 카드 즉시 적용·마지막 차례 되돌리기와 1판 제외 항목(주인 승인 2026-11-26).** AI 편집은 PC(결정 0151)와 같이 바로 적용하고 변경 카드로 마지막 차례만 되돌린다(디자인 시스템 6.5의 미리 보기 후 적용과 다름). 선택한 글 인용(6.4)과 한글 노란 표시는 1판에서 뺀다.
5. **AI 결과 보관소, 연결 방식, 가리기·편집기 도구 범위(주인 승인 2026-11-26·2026-11-27).** 앱 데이터 폴더 `ai-results/`를 AI 결과 보관소로 두고 설정에서 크기 확인·삭제를 제공한다(실제 구현은 AI가 만든 그림만 보관소에 쓰고, 웹 그림과 붙인 사진은 웹뷰 메모리에만 두어 승인 문구보다 좁혔다). 설정의 AI 결과 보관소 카드는 AI가 켜져 있거나 보관된 파일이 있을 때만 보인다(주인 승인 2026-11-27, 통합 수정 PR에서 반영). OpenRouter 무료 연결은 키 붙여넣기를 유지하고(PKCE 로그인은 후속), 직접 운영 서버는 HTTPS 주소만 허용하며 키는 선택이다. 선택 영역 숨기기(가리기)는 편집기 몫(마크다운·HTML은 T4)으로 두고, T7은 공용 차단 오류(`MobileAiBlockedError('hidden-unverified')`)와 차단 알림·대기열 정지를 맡는다. 1판 편집기 AI는 문서 도구만 쓰며(T2·T4 방식), T7이 이미 연결한 한글 AI의 공용 웹·그림 도구는 유지한다(주인 승인 2026-11-27).

## 버린 대안

- **Rust에 공급자별 메시지 변환과 도구 호출 파서를 새로 작성:** PC와 같은 프로토콜 코드를 두 벌 유지해야 하고, PC 오류 분류·수정 사항이 모바일에 자동 반영되지 않는다.
- **웹뷰에 API 키 원문을 내려보내 직접 `fetch`:** 웹뷰 메모리나 스크립트 계층에 키 원문이 노출된다(보안 규칙 위반).
- **NAT64(`64:ff9b::/96`) 일괄 거절(PC와 동일):** IPv6 전용 이동통신 망에서 IPv4 전용 사이트의 주소 읽기가 전부 막힌다.

## 결과

- 메시지 변환, 도구 호출 읽기, 오류 분류(`free-limit` 등), 실행 중지 시 Rust 도구 요청 취소가 PC와 같은 규칙으로 동작하며, 새 npm·Rust 의존을 추가하지 않았다.
- 한글 AI(`hwpAgent.ts`)의 공용 웹·그림 도구 연결은 유지하고, PDF(T2)·HTML/마크다운(T4) 등 나머지 1판 편집기 AI는 문서 도구만 쓰기로 확정되었다(2026-11-27). AI 결과 보관소 카드의 조건부 노출은 통합 수정 PR에서 반영한다.
- 실제 키·구독·외부 네트워크 확인은 하지 않았으며(대본 SSE·검색으로 검증), 실기기 Keystore/Keychain 봉인 중계와 IPv6 망 검증이 남아 있다.
