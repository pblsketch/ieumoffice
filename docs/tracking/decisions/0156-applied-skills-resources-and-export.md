# 0156 — 적용한 스킬만 리소스와 내보내기로 내주고, 본문은 이름으로 읽을 때만 준다

## 맥락

이슈 #558(따라오기·발행): MCP로 붙은 코딩 에이전트가 사람이 이음오피스에서 적용한(켜 둔) 스킬을 따라 읽을 수 있어야 하고, 사람은 적용한 스킬을 표준 스킬 폴더로 내보내 발행할 수 있어야 한다. 검토에서 동의가 새는 자리가 나왔다. `SKILL.md`를 그대로 읽어 폴더 밖으로 나가는 링크를 따라갈 수 있었고, 스킬 켜고 끈 상태를 설치본 프로필에서만 읽어 개발용(뜯어 설치하지 않은) 셸에서 끈 스킬이 나갈 뻔했다. 계약서가 약속한 배제(끈 스킬·숨긴 기본 스킬·밀린 스킬)에는 시험이 없었다.

## 결정

- **동의는 적용이다(consent = applied).** 적용한 스킬만 `ieumoffice://skills` 리소스와 `skill export`로 나간다. 끈 스킬, 숨긴 기본 스킬, 에이전트 창 전용 기본 스킬, 읽을 수 없는 스킬, 같은 이름에 밀린 스킬은 목록·본문·내보내기 어디에도 나오지 않는다. 켜고 끈 상태는 앱과 같은 설정 파일에서 읽고, GENOFFICE_USER_DATA가 없으면 설치본과 개발용 셸의 프로필을 함께 읽어 실행 중인 셸의 상태를 따른다. 어느 셸이 살아 있는지 모르면 한쪽이라도 꺼 둔 스킬은 끈 채로 둔다. 이름을 알아도 끈 스킬의 본문에는 닿지 못한다(없는 이름과 같은 오류).
- **점진적 공개(progressive disclosure).** `ieumoffice://skills`는 이름과 설명만 한 줄에 하나씩 준다. `ieumoffice://skills/<이름>`는 그 스킬의 `SKILL.md` 하나만 통째로 준다. 본문을 처음부터 모두 내주지 않고, 읽을 때 필요한 것만 읽게 한다.
- **리소스 주소.** 목록은 `ieumoffice://skills`, 본문 하나는 `ieumoffice://skills/<이름>`다. 없는 이름은 적용한 이름 목록을 담은 오류로 답하고, 깨진 이스케이프(`%zz`)도 같은 오류로 답한다. 스킬 폴더를 읽을 수 없으면 본문이 없는 것과 구분해 서버 오류로 알린다.
- **발행(내보내기).** `ieumoffice skill export <이름> --out <폴더>`는 적용한 스킬을 표준 스킬 폴더(`SKILL.md`와 부가 파일)로 쓴다. 깃허브 출처 기록(`.ieum-source.json`)은 들어가지 않는다. `<폴더>`는 새로 만들거나 비어 있어야 한다. 거절은 종료 코드 2 `output_exists`(비어 있지 않은 폴더, 쓰는 도중 다른 파일이 생김), 종료 코드 2 `file_not_found`(읽을 수 없는 스킬 폴더, `SKILL.md`가 하나도 복사되지 않음), 종료 코드 2 `resource_limit`(너무 큰 스킬 폴더)와 종료 코드 1 `invalid_argument`(적용하지 않은 스킬, 쓸 수 없는 `--out`)다. 이름이 같은 스킬이 여러 개면 밀리지 않고 고른 스킬 하나가 내보내진다. 쓰는 도중 실패하면 부분으로 남기지 않고 지우고, `SKILL.md`가 하나도 복사되지 않았으면 빈 "표준 스킬 폴더"로 끝나지 않고 오류로 알린다. `SKILL.md`는 폴더 안의 파일 목록에서 찾아 읽어, 폴더 밖으로 나가는 링크는 읽히지 않는다. 양식 문서(`metadata.ieum-template`이 가리키는 `assets/`의 문서 사본)는 기본으로 빠지고 `--include-template`을 줄 때만 들어가며, 어느 쪽이든 결과가 알린다(경고 `template_left_out`·`template_included`, `detail.template_included`). 스킬 파일을 읽지 못한 실패는 쓰기 실패와 구분해 읽기 오류(`file_not_found`)로 알린다.

## 택하지 않은 것

- **모든 스킬의 본문을 한 번에 내주기.** 읽지 않을 본문까지 컨텍스트를 쓰고, 사람이 켜지 않은 스킬도 함께 나간다.
- **끈 스킬도 이름을 알면 읽히게 두기.** 이름을 아는 것이 동의가 아니다.
- **밀린 스킬을 식별자로 내보내게 하기.** 고른 스킬 하나로 단순하게 유지하고, 계약서에 그대로 적는다.
- **설정을 설치본 프로필에서만 읽기.** 개발용 셸에서 끈 스킬이 나가는 문제가 남는다(검토에서 지적).
- **`SKILL.md`를 폴더 경로에서 직접 읽기.** 심리크를 바꿔 끼우면 원하지 않는 파일이 나간다. 목록에서 찾은 파일만 읽는다.

## 결과

- MCP 클라이언트는 리소스 두 개로 따라오고(이름·설명 목록, 본문 하나), `skill export`로 발행한다. 끈 스킬·숨긴 기본 스킬·에이전트 창 전용·밀린 스킬은 세 길 어디에도 나오지 않는다. 발행 폴더에는 양식 문서가 기본으로 들어가지 않는다.
- `packages/cli/tests/applied-skills.test.ts`가 위 배제와 이름으로 못 들어가는 끈 본문, 개발용 프로필의 꺼짐, 실행 중인 셸 프로필 우선, 내보내기 거절(`output_exists`·`invalid_argument`)과 도중 실패 시 정리, `SKILL.md` 없는 폴더 거절, 양식 문서의 기본 제외와 `--include-template` 포함을 지킨다.
