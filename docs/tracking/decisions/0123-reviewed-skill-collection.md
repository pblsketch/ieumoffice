# 0123 — 검토한 스킬 모음을 사람이 열 때만 둘러보고, 좋아요는 계정 없이 앱에서 누른다

## 맥락

저장소 주인이 스킬을 쉽게 만들고 관리하고 남과 나눠 쓰게 하자고 했다. 계획은 [스킬 고도화 계획](../../plans/skills-v2.md)에 있다. 그 가운데 남과 나누기에서 저장소 주인이 물었다. 누구의 스킬이든 올라오는 공개 목록처럼 하면 어떤가, 순위는 분류와 사용자 좋아요 수로 하면 어떤가.

결정 0048은 스킬 장터 화면을 두지 않았다. 앱이 그 공급망을 떠안기 때문이다. 공개 장터 조사에서 3,984개 중 13.4%가 치명적 문제였고, 76개가 악성이었다(Snyk, 2026-02-05).

공개 목록의 설치 수 순위는 앱이 설치를 서버에 알려야 만들 수 있다. 깃허브 이슈의 👍로 좋아요를 세면 우리 서버가 필요 없지만, 누르려면 깃허브 계정이 있어야 한다. 저장소 주인은 계정이 필요한 것은 받아들이기 어렵다고 했다. 이음오피스 사용자는 대부분 깃허브 계정이 없다.

소개 사이트는 이미 서버 함수를 쓴다. 질문 도우미(`api/ask.js`, IP별 요청 제한)가 있고, Apps Script를 거쳐 시트에 기록을 쓰는 길이 있다. 앱 설치 파일의 받은 횟수도 깃허브 릴리스에서 읽는다(`api/stats.js`).

## 결정

- **누구 것이든 올라오는 목록이 아니라, 검토한 모음을 둔다.** 깃허브에 스킬 모음 저장소를 하나 두고, 스킬은 PR로 받는다. CI가 형식, 스크립트 없음, 위험 문구, 라이선스를 검사한다. 저장소 주인이 읽고 병합한다. 지시문만 있는 스킬만 받는다. 저장소 주인이 물은 공개 목록 대신 이 방식을 제안했다.
- **앱의 설정 → 스킬에 [둘러보기]를 둔다.** 사람이 열 때만 모음의 `index.json`을 받는다. 설치는 지금의 깃허브 가져오기 미리보기를 거친다. 커밋을 고정해 받으므로, 모음 쪽이 바뀌면 "새 판 있음"만 보인다. 사람이 차이를 보고 받기 전에는 이전 판을 쓴다.
- **순위는 분류 안에서 좋아요 수로 한다.** 저장소 주인이 정했다. 처음에는 수가 적으므로 저장소 주인의 추천 표시를 맨 위에 둔다.
- **좋아요는 계정 없이 앱에서 바로 누른다.** 앱이 소개 사이트의 서버 함수(`api/skill-like.js`)에 보낸다. 보내는 것은 스킬 이름, 좋아요인지 취소인지, 이 PC에서 처음 누를 때 만든 무작위 값 하나다. 무작위 값은 한 PC가 같은 스킬을 두 번 세지 않게 하는 데만 쓴다. 누를 때만 보낸다. 사이트의 스킬 쪽에서도 누를 수 있고, 같은 수에 더해진다. 저장소 주인이 2026-11-10에 이 정도의 전송은 받아들였다.
- **부풀리기는 가볍게 막는다.** 같은 무작위 값의 같은 스킬은 한 번만 센다. IP별로 요청 수를 제한한다. 사이트 쪽 단추에는 사람 확인을 붙인다. 수는 시트에 쌓이고, 이상한 수는 저장소 주인이 지운다. 무료 스킬의 줄 세우기라 더 무겁게 막지 않는다.
- **설치 수는 깃허브가 센다.** 모음의 스킬을 릴리스 첨부 zip으로 올리고 앱의 설치가 그 파일을 받는다. 깃허브가 첨부 파일마다 받은 횟수를 공개한다. 앱은 설치에 필요한 요청 말고는 더 보내지 않는다.
- **좋아요 말고 쓰는 모습은 보내지 않는다.** 어떤 스킬을 몇 번 불렀는지, 무엇을 설치했는지 같은 값은 앱이 보내지 않는다.

## 택하지 않은 것

- **누구 것이든 올라오는 목록과 설치 수 순위.** 공급망 위험을 앱이 떠안는다. 설치 수를 세려면 사용 통계를 보내야 한다.
- **깃허브 이슈의 👍로 좋아요 세기.** 우리 서버가 필요 없지만, 누르려면 깃허브 계정이 있어야 한다.
- **사이트에서만 좋아요 누르기.** 앱이 아무것도 보내지 않는 원칙은 남지만, 앱에서 브라우저로 갔다가 돌아와야 한다. 저장소 주인이 앱에서 바로 누르는 쪽을 골랐다.
- **앱의 좋아요에도 사람 확인 붙이기.** 그 확인 화면이 앱 창에서 뜨는지 확인하지 못했다. 무작위 값과 IP 제한으로 충분하다고 봤다.

## 결과

- 결정 0048의 "스킬 장터 화면은 두지 않는다"가 "검토한 모음을 사람이 열 때만 둘러본다"로 바뀐다. 누구 것이든 올라오는 목록과 자동 설치를 두지 않는 것은 그대로다.
- 앱이 이음오피스 쪽(소개 사이트)으로 무언가를 보내는 첫 길이 생긴다. 구현할 때 함께 고친다. `PRIVACY.md`의 첫 문단과 전송 표, `AGENTS.md`·`CLAUDE.md`의 "서버, 회원 계정, 사용 통계가 없다", 사이트의 개인정보 쪽(`public/privacy.html`)이다.
- 설치 파일을 받는 릴리스 파일 저장 주소를 깃허브 허용 주소에 하나 더한다. 그때 `docs/security.md`의 "사용자 스킬"과 PRIVACY.md의 깃허브 줄을 고친다.
- 모음의 검토가 저장소 주인 한 사람에게 간다. CI가 기계적인 검사를 덜어 주지만, 읽는 일은 남는다.
