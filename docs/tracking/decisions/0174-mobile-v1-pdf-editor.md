# 0174. 모바일 1판 PDF 편집기: PC 저장 코드 재사용, 글꼴·펜 구분·편집 범위

- 날짜: 2026-11-26
- 상태: 모바일 1판(배포 전)

## 맥락

모바일 1판 PDF 편집기(T2)는 PC PDF 편집기와 저장 결과가 바이트 수준으로 같아야 하고, 모바일 웹뷰의 메모리 한도 안에서 수백 쪽 문서를 안정적으로 열어야 했다. 또한 PC PDF 저장 코드(`apps/pdf/src/main/save-pdf.ts`)는 Electron 메인 프로세스용 Node 모듈을 참조하지만, 모바일에서는 웹 워커에서 실행해야 한다.

## 결정

1. **PC `save-pdf.ts` 무수정 재사용.** PC PDF 저장 코드를 고치지 않고, 모바일 빌드 설정(`config/tracks/pdf.ts`)의 Node 대역 부품으로 웹 워커에서 직접 호출한다. 증분 저장은 PC와 같이 하지 않으며, 바뀐 것이 있을 때만 통째로 다시 쓴다.
2. **글꼴은 앱 번들 글꼴 셋만 사용.** 앱 크기를 지키기 위해 전체 한글 글꼴을 추가로 싣지 않는다. 넣을 수 없는 글자는 입력을 막고, 문서 글꼴이 모자라면 앱 글꼴로 대체한 뒤 사용자에게 알린다.
3. **펜·손가락 자동 구분과 스위치.** 스타일러스 펜을 한 번 사용하면 펜은 그리기, 손가락은 화면 이동으로 자동 구분하고 기기에 기억한다. "손가락으로도 그리기" 스위치를 함께 둔다.
4. **편집 막대 4개 유지와 1판 편집·AI 범위.** 편집 막대는 디자인 시스템 5.6의 `[펜][형광펜][글상자][서명]` 넷을 유지하며, `[글상자]`가 새 글자 넣기와 문서 글자 고치기까지 맡는다. 링크 넣기, 다른 이름으로 저장 시 주석 굽기·빼기, 새 PDF 만들기도 1판에 넣었다. AI 범위는 읽기·주석·양식·쪽 작업으로 두고, AI 글자 고치기와 읽기 도우미 화면(구절 카드·대역 보기·개요)은 제외한다.
   - 참고: 원래 범위 문서(`docs/plans/mobile-scope.md`)에서 2판이던 PDF 글자 넣기·고치기는 조율 세션 판단으로 1판에 당겨 구현했으며(`features/text/`), 범위 문서·디자인 시스템 5.6 반영 여부는 저장소 주인의 최종 확인을 기다린다.

## 버린 대안

- **T3 공용 패키지(`@genoffice/pdf-ops`)로 저장 코드까지 빼기:** T3 범위가 커지고 T2가 T3을 기다려야 하며 같은 파일에서 충돌한다. T3 병합 뒤 통합 여부는 추후 판단한다.
- **모바일에서 `pdf-lib`로 저장 로직을 새로 작성:** PC와 저장 결과가 갈라질 위험이 크다.
- **전체 한글 글꼴 추가 번들링:** 모바일 앱 설치 크기가 크게 늘어난다.

## 결과

- PC와 모바일의 PDF 저장 결과 34가지 비교 시험이 바이트까지 일치하며, Android 16 에뮬레이터에서 400쪽 PDF 탐색(PSS 162~169 MB)과 펜·형광펜·양식·글상자 저장 왕복이 확인되었다.
- PDF 글자 편집을 1판에 유지할지와 암호 해제 PDF의 `aiAvailable` 정책, 공용 AI 웹·그림 도구 연결 여부는 저장소 주인 확인 항목으로 남는다.
- S펜·Apple Pencil 팜 리젝션과 대용량 PDF 저장 메모리·시간은 실기기 확인이 필요하다.
