# 0167 — Mac과 Linux 배포판에서 베타 표시를 뗀다

## 맥락

Mac판(Apple Silicon·Intel)과 Linux판(x64)은 처음 공개할 때부터 베타로 표기해 왔다(결정 0031, 0065). 저장소 주인이 Windows에서만 직접 확인할 수 있었고, 초기에는 Mac의 수동 업데이트·경로 탐색과 Linux의 glibc 호환·파일 열기 한도(1024)·네트워크 폴더 저장 등 운영체제별 결함이 컸기 때문이다.

그동안 Mac은 자체 zip 교체 업데이트(결정 0097), 앱 메뉴·단축키(결정 0149), GUI 앱의 CLI 경로 탐색 보강이 자리 잡았고, Linux는 `glibc 2.28` 하한 고정과 Ubuntu 20.04/24.04 컨테이너 검증, open-file 한도 상향 런처, gvfs 저장 대응이 들어갔다. GitHub Actions 빌드 검사도 두 플랫폼 모두 안정적으로 통과하고 있다.

## 결정

- **표시.** README, 앱 안 설치 도움말(22개 언어), 릴리스 절차, 소개 사이트(5개 언어)에서 Mac과 Linux에 따로 붙어 있던 "베타" 표시를 뗀다. Windows·Mac·Linux 세 플랫폼을 동등하게 안내한다.
- **앱 전체의 0.x 표기는 건드리지 않는다.** 릴리스 전체 버전의 베타 표시와 앱의 "베타 버전" 업데이트 채널(프리릴리스 수신)은 그대로 둔다.
- **사실 안내는 유지한다.** Mac의 Apple 개발자 서명 없음(처음 1회 "그래도 열기")과 Linux `deb`·`rpm`의 수동 업데이트, 그리고 Mac·Linux 실기 동작은 개발자가 직접 확인하지 못하고 사용자 보고로 확인한다는 점은 문서와 도움말에 그대로 남긴다.

## 택하지 않은 것

- **앱 전체의 베타 표시까지 함께 뗀다.** 이번 결정은 Mac·Linux에만 붙어 있던 플랫폼 차별 표시를 걷는 데 한정한다.
- **Apple 개발자 서명·공증 도입.** 연 99달러 비용을 들이지 않는 방침(결정 0031, 0097)은 그대로 유지한다.

## 결과

- 결정 0031과 0065의 "베타" 표기 부분은 이 결정으로 대체된다. ad hoc 서명, Intel 동시 빌드, 자체 zip 업데이트(결정 0097)는 그대로다.
- `README.md`의 절 제목이 `Mac (베타)`·`Linux (베타)`에서 `Mac`·`Linux`로 바뀌므로, 소개 사이트에서 그 앵커를 가리키던 링크도 함께 맞춘다.
