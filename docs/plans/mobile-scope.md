# 이음오피스 모바일 기능 범위 (PC판과 맞추기)

상태: **확정**(2026-11-24). 결정 [0165](../tracking/decisions/0165-mobile-scope-and-design-system.md). 화면 설계는 [mobile-design-system.md](mobile-design-system.md).

원칙: **PC판 기능을 모바일에도 두는 것이 기본이다.** 아래 세 가지만 예외로 따로 적는다.

- **B. 가져오지 않는 것**: 모바일에서 기술적으로 불가능하거나, 스토어 규칙에 걸리거나, 모바일에서는 뜻이 없는 것.
- **C. 다르게 가져오는 것**: 목표는 같고 모바일 방식으로 바꿔 만드는 것(맞춘 것으로 친다).
- **D. 모바일에만 만드는 것.**

PC 기능 목록의 근거는 origin/main의 도움말 28개 주제(`apps/shell/src/renderer/src/i18n/help/topics/*.ko.md`)와 `docs/tracking/status.md`다.

모바일이 처한 조건:

- Tauri 웹뷰라서 다른 프로그램을 실행하거나 셸을 쓸 수 없다.
- Rust 코드는 별도 프로세스로는 못 띄우지만, 앱 안에 넣어 Tauri 명령으로 부를 수는 있다.
- 파일은 운영체제가 허락한 범위(SAF, Files 앱)에서만 다룬다.
- iPhone의 웹뷰 메모리 한도는 약 1.5~2GB다.

### A-1. PDF 도구 (11-24 추가)

PC의 "PDF 도구"는 홈 카드에서 여는 별도 창이다. 결과는 늘 새 파일이고 원본은 바뀌지 않는다. AI를 쓰지 않고 PC 안에서만 처리한다. 도구는 모두 PC 메인 프로세스에서 돈다(`apps/shell/src/main/pdf-tools/tools.ts` → `apps/pdf/src/main/*`). 대부분 바이트를 받아 바이트를 돌려주는 함수이고, pdf-lib·qpdf·PDFium(WASM)을 쓴다.

**모바일에서도 같은 약속을 지킨다.** 새 파일로만 저장하고, 기기 안에서만 처리하며, AI를 쓰지 않는다. 편집기 고르기에서 "PDF 도구"를 켜고 끄는 것도 PC와 같다.

| 묶음           | 도구                                                                 | 시기                 | 모바일에서 할 일                                                                                                                                                                      |
| -------------- | -------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 페이지 정리    | 병합, 분할, 페이지 추출, 역순 정렬, 모두 회전, 빈 페이지 찾아 지우기 | 1판                  | 같은 함수를 웹 워커로 옮김                                                                                                                                                            |
| 변환           | 이미지로 PDF 만들기, 텍스트로 저장                                   | 1판                  | 이미지는 사진 선택 창에서 여러 장 고름(권한 창 없음)                                                                                                                                  |
| 용량·보안      | 용량 줄이기, 암호 걸기, 암호 풀기, 파일 복구                         | 1판                  | 용량 줄이기의 그림 다시 압축이 Electron `nativeImage`를 쓰므로(`image-recode.ts`) 웹뷰의 `OffscreenCanvas`·`createImageBitmap`으로 바꾼다. 큰 파일은 쪽 단위로 처리(상한은 두지 않음) |
| 정리하기       | 주석 한꺼번에 지우기                                                 | 1판                  | 그대로                                                                                                                                                                                |
| 인쇄 준비      | 양면 인쇄 맞추기, 페이지 모아찍기, 페이지 크기, 페이지 분할          | 2판                  | 그대로. 휴대폰 인쇄가 드물어 뒤로                                                                                                                                                     |
| 꾸미기         | 배경 겹치기                                                          | 2판                  | 그대로                                                                                                                                                                                |
| PDF 편집기에서 | 워터마크·머리글, 자르기, 이미지 내보내기, 변환, 편집·서명·가림       | PDF 편집기 판을 따름 | PC처럼 카드를 누르면 PDF 편집기로 연다                                                                                                                                                |

**모바일 방식으로 바꾸는 것(C)**

- 별도 창 대신 **도구 화면**을 쓴다. 홈 [+] 만들기 시트의 "PDF 도구" 줄에서 연다. 제안: 홈 아래 탭을 [최근][폴더][도구][설정] 넷으로 늘려 [도구]에서도 바로 연다(휴대폰에서 PDF 합치기·줄이기·사진→PDF는 자주 쓰는 일이다). 정해지면 디자인 시스템 5.10을 고친다.
- 흐름은 도구 고르기 → 파일 고르기(시스템 선택 창, 여러 개) → 옵션(시트) → 처리(진행 막대·[멈추기]) → **결과 시트 [열기][공유][다른 곳에 저장]**이다. PC의 "폴더 열기"는 [공유]·[다른 곳에 저장]으로 바꾼다.
- 원본과 같은 위치·이름으로는 저장하지 않는다. 결과 이름은 PC 규칙(`원본이름-병합.pdf` 등)과 같게 한다.
- 도구 함수는 PC와 모바일이 같은 코드를 쓰도록 `apps/pdf/src/main`에서 Node 의존(fs, Buffer, Electron)이 없는 부분을 공용 모듈로 뺀다. PC 동작은 그대로 둔다.

**모바일에만 있는 길(D)**

- 홈 목록에서 PDF 여러 개를 고르면 아래 막대에 [합치기], 사진 선택에서 여러 장을 고르면 [PDF로 만들기]가 나온다.
- 다른 앱에서 공유로 받은 PDF·사진 여러 개는 받는 화면에서 바로 [합치기]·[PDF로 만들기]를 할 수 있다.
- PDF 스캔 도구(D-1, 2판)도 같은 도구 화면에 들어가고, 결과는 같은 결과 시트로 낸다.

> **판단 필요 — ChatGPT 바로 연결(결정 0081) 모바일판**
> PC판에서 앱 이름으로 등록한 OAuth를 모바일 앱에서도 써도 되는지 약관을 확인하지 못했다(11-01부터 보류). 1차 구현에 들어간 모바일 OAuth 경로(`mobile.md`의 "모바일 클라이언트 ID + App Links")를 켜는 일은 새 경로로 구독을 쓰는 일이라 **저장소 주인의 약관 판단이 먼저다.** 판단 전까지 모바일 AI는 키 방식과 무료 연결만 쓴다.

## D-1. PDF 스캔 도구 (2판, 모바일 전용, 11-24 결정)

PC판에는 없는 도구다. 종이 문서와 책을 휴대폰 카메라로 찍어 깨끗한 PDF로 만든다. 참고한 방향은 "문서 스캔 앱"(모서리 찾기·자동 촬영·보정·글자 인식)과 "책 스캔 앱"(휜 쪽 펴기·두 쪽 나누기·손가락 지우기)이다. 화면·그림·이름은 따라 하지 않고 기능 패턴만 참고한다.

**약속(PDF 도구와 같다)**: 기기 안에서만 처리하고 사진을 밖으로 보내지 않는다. AI를 쓰지 않는다(글자 인식도 기기 안 모델). 결과는 새 파일이다.

### 두 모드

| 모드                | 하는 일                                                                                                                                                                              | 만드는 방법                                                                                                                                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **문서** (2판 앞쪽) | 한 장씩 또는 여러 장 연속. 모서리 찾기, 자동 촬영, 원근 바로잡기, 자르기 다시 맞추기, 필터(원본·흑백 문서·회색·선명하게), 그림자·얼룩·손가락 지우기, 쪽 순서 바꾸기·다시 찍기·지우기 | **OS 문서 스캐너를 쓴다.** Android는 ML Kit 문서 스캐너(Google Play 서비스, 앱에 카메라 권한이 필요 없음, 자동 촬영·얼룩·손가락 지우기, PDF·JPEG 결과, 앱 크기 약 300KB 증가). iOS는 VisionKit 문서 카메라(모서리 찾기·원근 보정·보정 필터 내장, 화면은 바꿀 수 없음, 카메라 사용 설명 문구 필요 여부는 확인할 것) |
| **책** (2판 뒤쪽)   | 펼친 책을 찍으면 휜 쪽을 평평하게 펴고, 왼쪽·오른쪽 쪽을 나누고, 책을 누른 손가락을 지운다. 쪽을 넘기면 자동으로 다음 장을 찍는다                                                    | OS 스캐너에 없는 기능이라 **직접 만든다.** 기기 안 영상 처리(휜 면 펴기·쪽 경계 찾기·손가락 영역 메우기)를 Rust나 WASM으로 넣는다. 카메라 화면도 직접 만들어야 하므로 카메라 권한이 필요하다. 먼저 시제품으로 품질을 확인한다                                                                                      |

### 공통 뒷부분 (두 모드 모두)

1. **글자 인식(선택, 기본 켜짐)**: iOS Vision, Android ML Kit 글자 인식(기기 안, 한국어 포함). 인식한 글자를 보이지 않는 글자 층으로 PDF에 넣어 찾기·복사·AI 읽기가 된다.
2. **저장 모양**: PDF(기본), 쪽마다 JPEG, 글자만(.txt·마크다운). 이름은 "스캔 2026-11-24 14-03.pdf"처럼 날짜·시각.
3. **결과 시트**: [열기][공유][다른 곳에 저장] + [이어 찍기]. 열면 PDF 편집기로 간다(서명·주석·페이지 작업이 바로 됨).
4. **스캔한 PDF를 나중에 고치기**: PC의 "스캔 PDF 글자 편집"(그림을 덮어 고치는 방식)을 쓴다.

### 들어가는 곳

- 홈 [도구] 탭의 맨 위 카드(권장안 2 참고), [+] 만들기 시트, 앱 아이콘 길게 누르기 바로가기 "스캔".
- PDF 편집기의 "쪽 넣기 → 스캔해서 넣기".
- 편집기 고르기에서 "PDF 도구"를 끄면 스캔도 같이 숨는다.

### 권한 (디자인 시스템 5.14와 맞춤)

- 문서 모드(Android)는 권한 창이 없다. iOS와 책 모드는 [스캔]을 처음 누를 때 카메라 권한을 묻는다(첫 실행에서 묻지 않는다). 거절해도 앱은 막히지 않고 스캔 카드에 "카메라를 허락하면 스캔할 수 있어요" + [사진에서 가져오기](사진 선택 창 → 이미지로 PDF)를 보여 준다.

### 먼저 확인할 것

1. Tauri 2에서 ML Kit 문서 스캐너·VisionKit을 부르는 플러그인을 직접 만들어야 하는지(공개 플러그인 유무).
2. Google Play 서비스가 없는 Android 기기(일부 중국판 등)에서는 문서 모드를 쓸 수 없다 → 그때는 사진에서 가져오기만 보인다.
3. 책 모드의 휜 쪽 펴기 품질: 오픈소스 방법과 모델의 라이선스(허용 목록 안인지)를 먼저 조사한다.
4. 보이지 않는 글자 층을 넣은 PDF가 PC 편집기·다른 PDF 프로그램에서 찾기·복사가 되는지.

### 엑셀 1판의 위험 (먼저 시제품으로 볼 것)

   - 11-24 확인: Univer에 **모바일 UI 플러그인이 오픈소스(Apache-2.0)로 들어 있다** — `UniverMobileUIPlugin`(`@univerjs/ui`), `UniverSheetsMobileUIPlugin`(`@univerjs/sheets-ui`), `UniverDocsMobileUIPlugin`, 그리고 정렬·필터·표시 형식·찾기·표·메모 UI의 `mobile-plugin`. 우리가 쓰는 0.25.1에도 이미 들어 있다(설치된 패키지에서 확인). 시제품은 PC의 Univer 설정을 이 모바일 플러그인 묶음으로 바꿔 띄우는 데서 시작한다. 모바일 플러그인이 어디까지 되는지(범위 손잡이, 수식 편집과 가상 키보드)는 실기기에서 본다.

3. **Rust 엔진 빌드.** 크레이트를 고치지 않고 모바일 대상으로 빌드되는지(Android NDK·iOS), 앱 크기가 얼마나 느는지.
