## 1. 설계 원칙

1. **문서가 주인공.** 틀(바·막대·시트)은 문서를 가리는 면적을 최소로. 아래쪽에는 한 번에 막대 하나만.
2. **보기로 열고, 단추 하나로 편집.** 실수로 원본을 바꾸지 않는다.
3. **저장을 믿을 수 있게.** 저장 상태가 늘 보이고, 복구 사본이 늘 있다. "날아감"은 품질 기준 1순위.
4. **엄지 영역.** 자주 쓰는 동작은 화면 아래 1/3, 드물고 위험한 동작은 더보기 안.
5. **폰과 태블릿은 같은 기능, 배치만 다르게.** 창 너비로 판단한다(기기 이름으로 판단하지 않는다).
6. **한글 입력이 끊기지 않게.** 막대 단추를 눌러도 조합 중인 글자가 깨지거나 키보드가 닫히지 않는다.

## 3. 토큰

### 3.1 세 층

```
① 원시   packages/ui/src/tokens.css 의 값 (색 램프·반지름) + 모바일 원시(간격 4px 단위, 시간)
   ↓  이름만 붙여 가리킴
② 의미   --surface, --text, --accent, --danger … (데스크톱 이름 그대로)
         + 모바일 의미: --m-space-*, --m-type-*, --m-radius-*, --m-motion-*, --m-hit
   ↓
③ 부품   --m-appbar-h, --m-kbbar-h, --m-sheet-radius, --m-fab-size …
```

- 새 이름의 앞머리는 `--m-`(지금의 `--mobile-*`를 옮긴다). 데스크톱 의미 토큰과 같은 뜻이면 새로 만들지 않는다.
- 덮어쓰기 축은 셋이고, ②·③ 층에만 건다.
  - `data-theme="light|dark"`(+시스템 따르기): 색만. 데스크톱과 같은 세 묶음.
  - `data-window="compact|medium|expanded|large"`: 배치 토큰(여백, 패널 폭, 시트 최대 폭)만.
  - 사용자 접근성 설정(`prefers-reduced-motion`, `prefers-contrast: more`, `prefers-reduced-transparency`): 움직임·대비·투명도만.
- **`data-platform`은 토큰을 바꾸지 않는다**(D2). 동작 코드만 읽는다.

| -------------- | ---- | -------------------------------------- |
| `--m-space-1`  | 4px  | 아이콘과 글 사이                       |

### 3.3 글자

UI 글꼴은 데스크톱과 같은 방식으로 OS 시스템 글꼴 묶음을 쓴다(`--gs-font-sans`, 한글은 각 OS 기본 한글 글꼴). 문서 안 글꼴은 문서 자료라 건드리지 않는다.

| 토큰               | 크기/줄 간격 | 굵기 | 쓰임                    |
| ------------------ | ------------ | ---- | ----------------------- |
| `--m-type-title-l` | 22/28        | 700  | 홈·설정 화면 제목       |
| `--m-type-title-m` | 17/24        | 600  | 상단 바 제목, 시트 제목 |
| `--m-type-body`    | 16/24        | 400  | 본문, 목록 첫 줄        |
| `--m-type-body-s`  | 14/20        | 400  | 목록 둘째 줄, 설명      |
| `--m-type-label`   | 14/20        | 600  | 단추 글, 탭 이름        |
| `--m-type-caption` | 12/16        | 500  | 배지, 시간, 보조 표시   |

- 모두 `rem` 기준. 루트 글자 크기 = 16px × OS 글자 크기 배율(iOS는 `-apple-system-body`로, Android는 네이티브가 넘긴 `fontScale`로; 기기 확인 항목). 200%까지 깨지지 않게: 넘치면 말줄임 대신 줄 바꿈, 가로 배치는 세로로 쌓는다.
- 11px 이하 글자는 쓰지 않는다.

### 3.6 색 (데스크톱 이어 쓰기)

- 면·글·선·위험·성공은 데스크톱 의미 토큰(`--surface`, `--surface-subtle`, `--text`, `--text-muted`, `--border`, `--danger`, `--success` …) 그대로.
- 강조색: 껍데기(홈·설정)는 `--color-brand-secondary`, 편집기는 데스크톱 그 편집기의 `--accent`와 같은 값(`data-kind="hwp"` 등으로 고름).
- AI 동작 색은 데스크톱의 `--color-ai-action` 그대로. 단, compact 도구 막대에서는 알약이 아니라 원형 아이콘 단추로 둔다(문서 도구보다 앞서 보이지 않게).
- 새로 필요한 것(세 묶음 모두 정의): `--m-scrim`(시트 뒤 어둡게), `--m-surface-raised`(시트·막대 면), `--m-system-bar`(상태 표시줄·제스처 막대 뒤 색 = 상단 바·아래 막대 면과 같게).
- 반투명 면은 쓰지 않는다(겉모습 하나 원칙, 저사양 기기 성능, 투명도 줄이기 대응 부담).

## 4. 화면 크기 구분

| `data-window` | 창 너비  | 홈                    | 편집 화면                                    |
| ------------- | -------- | --------------------- | -------------------------------------------- |
| compact       | < 600    | 아래 탭               | 한 칸. 서식은 하단 시트, AI는 하단 시트      |
| medium        | 600–839  | 왼쪽 레일             | 한 칸. 시트 최대 폭 640px 가운데             |
| expanded      | 840–1199 | 왼쪽 레일             | 문서 + 오른쪽 패널(서식 또는 AI, 폭 360px)   |
| large         | ≥ 1200   | 왼쪽 레일 + 목록 넓게 | 문서 + 오른쪽 패널, 외장 키보드 전제 도구 줄 |

- 판단은 웹뷰 창 너비(`ResizeObserver`)로. 분할 화면·폴더블 펼침에서 바로 바뀐다.
- 높이 < 480(가로 폰): 상단 바 48px, 시트를 오른쪽 패널처럼(폭 360px).

## 5. P0 부품 (design-system extend 틀, 줄여 씀)

### 5.1 앱 껍데기 `MobileFrame`

**문제** safe-area·키보드 높이·창 크기·뒤로 가기를 화면마다 따로 처리하면 어긋난다.
**하는 일**

- CSS 변수로 내보냄: `--m-safe-top/bottom/left/right`, `--m-kb`(키보드 높이), `data-window`, `data-platform`.
- 키보드 높이: 네이티브 알림 값 우선, 없으면 `visualViewport`로 계산(`innerHeight - vv.height - vv.offsetTop`). `100dvh`로 키보드를 다루지 않는다.
- 뒤로 가기 쌓기(5.11)의 주인.
- 시스템 막대 색을 `--m-system-bar`로 맞춘다(Android edge-to-edge).
  **접근성** 화면 바뀜마다 제목을 낭독기에 알린다.

### 5.2 상단 바 `AppBar`

**문제** 지금은 [완료][저장] 두 알약이 이름을 밀어낸다.
**모양**

```
보기 모드   [‹]  [형식 아이콘] 문서 이름 ▾   [공유] [편집]  [⋯]
편집 모드   [‹]  문서 이름 ▾  ● 저장 안 됨      [↶][↷]  [완료]
            (편집 모드의 공유는 문서 메뉴 ▾ 안)
```

| 속성        | 값                                                                                  |
| ----------- | ----------------------------------------------------------------------------------- |
| `mode`      | `view` / `edit`                                                                     |
| `saveState` | `saved` / `dirty` / `saving` / `error`                                              |
| `title`     | 문서 이름(누르면 문서 메뉴: 이름 바꾸기·다른 이름으로 저장·내보내기·공유·문서 정보) |
| **규칙**    |

- 오른쪽 주 단추는 하나뿐: 보기 모드는 [편집], 편집 모드는 [완료]. 완료는 편집을 끝내고 보기로 돌아간다(저장은 아래 상태 표시 규칙을 따른다).
- 저장은 단추 대신 **이름 옆 상태 점과 글**로 보인다. `dirty`일 때 상태를 누르면 바로 저장. 실패는 빨간 점 + "저장 못 함 · 다시" (색만으로 알리지 않는다).
- 실행 취소/다시 실행은 편집 모드의 상단 바에 고정(compact에서도).
- 이름이 길면 가운데 말줄임(확장자는 남김).
  **접근성** 상태 글은 `aria-live="polite"`. 단추마다 동작 이름.

### 5.3 문서 영역 틀 `DocViewport`

**문제** 너비 맞춤 A4는 폰에서 본문이 약 6pt로 읽을 수 없다(D3).

| 속성     | 값                                                              |
| -------- | --------------------------------------------------------------- |
| `layout` | `page`(쪽) / `flow`(흐름) — 형식이 흐름을 지원할 때만 전환 보임 |
| `zoom`   | 맞춤 / 쪽 너비 / 직접 배율(두 손가락)                           |
| **규칙** |

- 한글은 **compact에서 흐름 보기가 기본**, medium 이상은 쪽 보기가 기본. 마지막으로 고른 값을 문서별로 기억.
- 흐름 보기: 화면 폭에 맞춰 글을 다시 흘리고, 글자 크기 조절(−/+)이 있다. 쪽 모양(여백·쪽 나눔)에 닿는 편집은 쪽 보기로 넘기며 알린다.
- 아래 막대와 키보드 높이만큼 아래 여백을 둔다(커서가 가려지지 않게 자동 스크롤).
- 화면 가장자리 24px 안에는 끌기 손잡이를 두지 않는다(뒤로 가기 손짓과 다툼).
- 보기 모드에서 두 번 누르면 그 자리로 편집 진입.

### 5.4 키보드 보조 막대 `KeyboardBar`

**문제** 키보드가 떠 있으면 아래 도구 막대가 가려지거나 밀린다.
**모양** `bottom: var(--m-kb)`, 높이 `--m-kbbar-h`. 가로 밀기 한 줄 + 오른쪽 끝 고정 칸.

```
[B][I][U][목록][제목▸][표▸] …(밀기)…  │ [Aa] [⌄]
```

- `[Aa]`: 서식 판 열기(키보드 자리를 같은 높이의 서식 판으로 바꿔 낌; 키보드 높이를 기억해 화면이 튀지 않게).
- `[⌄]`: 키보드 내리기.
- AI 단추는 이 막대에 두지 않는다(6절).
  **규칙**
- 단추는 `pointerdown`에서 기본 동작을 막아 초점을 지킨다. 명령 전에 한글 조합을 마무리(`compositionend` 기다리기)한다.
- 켜짐 상태(굵게 등)는 선택 위치를 따라 바뀐다.
- 항목은 형식마다 다르다(5.6 표).
  **접근성** `role="toolbar"`, 토글은 `aria-pressed`.

### 5.5 하단 시트 `Sheet`

| 속성      | 값                                                                            |
| --------- | ----------------------------------------------------------------------------- |
| `modal`   | `true`(뒤를 막음, 어두운 막) / `false`(뒤 문서를 계속 만질 수 있음 — 서식 판) |
| `detents` | `['medium','large']` 기본, medium = 화면 높이 50%                             |
| `title`   | 선택                                                                          |
| **규칙**  |

- 손잡이를 끌어 높이 바꿈, 아래로 밀어 닫기, 막을 누르면 닫기(modal).
- 뒤로 가기 쌓기에 올라간다(Android 뒤로 = 시트 닫기).
- medium 이상 창에서는 같은 내용을 가운데 시트(최대 640px) 또는 오른쪽 패널로 연다(4절).
- 열릴 때 초점은 시트 첫 조작부로, 닫히면 연 단추로 돌아간다.
- 키보드가 뜨면 시트는 키보드 위로 올라간다(`--m-kb`).

### 5.6 편집 도구 막대 `EditToolbar` (키보드 없을 때)

아래 고정, 높이 `--m-toolbar-h`. 묶음 단추 → 누르면 그 묶음의 시트(non-modal)가 열린다.

| 형식           | 도구 막대(키보드 없음)                                           | 보조 막대(키보드 있음)                                                                                              |
| -------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 한글           | [글자][문단][표][삽입] · [AI]                                    | B I U · 목록 · 글자 크기 · 표▸ · [Aa]                                                                               |
| 마크다운       | [제목][목록][삽입] · [AI]                                        | # · B · I · 목록 · 할 일 · 링크 · 코드 · 그림                                                                       |
| HTML           | 한글과 같은 문서형                                               | 마크다운형 기호 줄                                                                                                  |
| PDF            | 보기 기본. 편집 = [펜][형광펜][글상자][서명] 떠 있는 막대 · [AI] | (글상자 입력 시) B · 크기 · 색                                                                                      |
| 엑셀(1판)      | [셀 서식][행·열][정렬·필터][삽입] · [AI]                         | 수식 입력줄이 보조 막대 자리에 붙는다: [=][Σ][( )][,][:][$] · [취소][확인] · 숫자 입력이면 숫자 키보드(`inputmode`) |
| 마인드맵(2판)  | 고른 노드 옆 [+ 하위][+ 같은 단계] · 아래 [개요][서식] · [AI]    | 해당 없음                                                                                                           |
| EPUB·PPT(읽기) | 아래: 목차 · 찾기 · 읽기 설정 · [AI]                             | —                                                                                                                   |

- 엑셀 격자 전용 규칙: 한 번 누르면 칸 고르기, 두 번 누르면 칸 편집. 고른 칸 모서리 손잡이를 끌어 범위를 넓힌다. 행·열 머리글을 누르면 줄 전체를 고르고 길게 누르면 줄 메뉴(넣기·지우기·숨기기·너비)를 연다. 맨 위 행·첫 열 틀 고정은 보기 메뉴에 둔다.
- `[AI]`는 막대 오른쪽 끝 원형 단추, `aiVisible`이 거짓이면 빠지고 나머지가 그대로 왼쪽 정렬(6절).
- 보기 모드에는 이 막대가 없다(5.2의 [편집]만).

### 5.8 메뉴·확인 창 `ActionMenu` / `ConfirmDialog`

- 더보기·길게 누르기 메뉴는 compact에서 modal 시트 목록, medium 이상에서 붙은 메뉴.
- 확인 창은 되돌릴 수 없는 일에만. 되돌릴 수 있는 일은 바로 하고 토스트로 되돌리기를 준다.
- 확인 창 단추 글은 동작 이름("지우기", "저장 안 하고 나가기"), "예/아니오" 금지. 단추 순서는 플랫폼 관례를 따른다(7절, 모양은 같음).

### 5.9 토스트 `Toast`

- 아래 막대 위에 뜬다(막대·키보드 높이를 피함). 한 번에 하나.
- 글만: 4초. 동작(되돌리기 등) 있음: 8초, 초점·누르고 있는 동안 멈춤.
- `role="status"`(오류는 `alert`).

### 5.10 파일 목록·새 문서 `DocList` / `CreateSheet`

- 홈 구조(compact): 아래 탭 [최근][폴더][도구][설정] + 오른쪽 아래 [+] 떠 있는 단추. [도구]는 PDF 도구와 2판의 스캔(편집기 고르기에서 PDF 도구를 끄면 탭째 숨김). medium 이상은 같은 넷이 왼쪽 레일로.
- [+] → **만들기 시트**: 형식 타일 격자(켜 둔 형식만), 그 아래 "파일 열기", "PDF 도구"(켜 둔 경우), "서식으로 시작"(나중). 형식이 늘어도 홈이 무너지지 않는다.
- 목록에서 여러 개를 고르면 아래 막대: [공유][지우기][⋯]. 모두 PDF면 [합치기]가 더해진다.
- **도구 화면 `ToolFlow`**(PDF 도구 등): 도구 목록(묶음별) → 파일 고르기 → 옵션 시트 → 진행(막대·[멈추기]) → 결과 시트 [열기][공유][다른 곳에 저장]. 결과는 늘 새 파일이다.
- 목록 항목: 형식 아이콘 · 이름(첫 줄) · 형식·시간·위치(둘째 줄) · [⋯]. 높이 64.
- 빈 상태: 설명 한 줄 + [파일 열기] + [새로 만들기].

### 5.11 뒤로 가기 쌓기 `BackStack`

껍데기가 하나의 쌓기를 가진다: 시트 → 서식 판 → 선택 해제 → 편집 끝(보기로) → 화면 나가기. 한 번에 한 단계씩.

- Android: 시스템 뒤로(예측형) 하나를 여기에 잇는다.
- iOS: 왼쪽 가장자리 밀기와 [‹] 단추가 같은 쌓기를 쓴다.
- 저장 안 된 채 나가기만 확인 창(5.8).

### 5.12 진행·상태 `Progress` / `InlineNotice`

- 문서 열기: 300ms 안에 끝나면 아무것도 안 보이고, 넘으면 문서 자리에 쪽 모양 자리표시 + 진행 글.
- AI 작업·내보내기: 시트 안 진행 막대와 [멈추기].
- 문서 위 알림(읽기 전용 등): 이유 + 푸는 길 단추를 함께("읽기 전용 · 사본으로 편집").

### 5.13 공유 `ShareSheet` (D5)

**문제** 모바일에서 문서를 끝내는 가장 흔한 동작이 "보내기"인데, 더보기 안에 숨으면 찾지 못한다.
**들어가는 곳**

- 보기 모드 상단 바 [공유] 아이콘(5.2). 편집 모드는 문서 메뉴 ▾ 안 "공유".
- 홈 목록 항목 [⋯] → 공유. 길게 눌러 여러 개 고른 뒤 아래 막대 [공유](여러 파일 한 번에).
- AI를 꺼도 공유는 그대로다.
  **흐름**

```
[공유] → 공유 시트(modal, medium)
   보낼 모양:  ◉ 원본 그대로 (.hwp)     ← 기본, 마지막 선택 기억
              ○ PDF
              ○ (형식별) 한글은 .hwpx, 마크다운은 HTML·텍스트, 마인드맵은 그림(PNG) …
   [보내기] → OS 공유 창(iOS 공유 시트 / Android 공유 인텐트)
```

**규칙**

- 저장 안 된 고침이 있으면 시트 위에 "아직 저장 안 한 고침도 함께 보냅니다"를 보이고, 지금 내용을 임시 사본으로 만들어 보낸다. **원본 파일은 이 때문에 다시 쓰지 않는다**(D7 저장 규칙).
- 변환(PDF 등)이 오래 걸리면 시트 안 진행 막대와 [멈추기](5.12).
- 보낸 뒤 임시 사본은 앱 임시 폴더에서 지운다.
  **받는 쪽(다른 앱 → 이음오피스)**
- "다른 앱에서 열기"(Android 열기 인텐트, iOS 문서 형식 등록)로 받은 파일은 **보기 모드**로 연다. 위에 "받은 파일 · 원본 위치에 저장할 수 없으면 사본으로 저장" 알림.
- 다른 앱의 공유 목록에 이음오피스가 뜨는 것: Android 1판, iOS 공유 확장은 별도 실행 파일이 필요해 2판.
  **접근성** [공유] 이름 "공유", 시트 선택지는 라디오 묶음.

### 5.14 첫 실행과 사용법 안내 `FirstRun` / `Tips` (D6)

**근거가 된 공식 지침**

- Android: 권한은 기능을 쓰려는 순간에 묻는다. 설명 화면에는 "괜찮아요" 같은 빠져나가는 길을 둔다. 거절해도 막지 말고 그 기능만 줄인다. 설정으로 보내 마음을 바꾸게 하지 않는다.
- Apple 5.1.1(iv)·5.1.2(i): 동의를 강요·유도하지 않는다. 시스템 기능을 켜야만 앱을 쓰게 하지 않는다. 동의하지 않은 사람에게 다른 길을 준다.
- Google Play: "모든 파일 접근(MANAGE_EXTERNAL_STORAGE)"은 사람이 직접 파일을 고르는 앱에는 허용되지 않는다 → **쓰지 않는다.** 파일은 시스템 선택 창(SAF / 파일 앱)으로.

**이 앱에 필요한 권한(1판)**

| 일                           | 방법                                                                  | OS 권한 창                               |
| ---------------------------- | --------------------------------------------------------------------- | ---------------------------------------- |
| 파일 열기·저장               | 시스템 파일 선택 창                                                   | 없음                                     |
| 문서 폴더를 "폴더" 탭에 두기 | 폴더 고르기(Android 폴더 트리 + 오래 가는 허락, iOS 보안 범위 책갈피) | 없음 — 사람이 폴더를 고르는 것이 곧 허락 |
| 그림 넣기                    | 사진 선택 창                                                          | 없음                                     |
| 알림                         | 1판은 쓰지 않음                                                       | —                                        |
| 카메라(스캔)                 | 1판 범위 밖. 생기면 그 단추를 누를 때 묻는다                          | 그때만                                   |

→ **첫 실행에서 OS 권한 창을 하나도 띄우지 않는다.** "권한 허용을 쉽게"는 권한 창을 모아 띄우는 것이 아니라, 필요한 순간에 한 번 누르면 끝나게 만드는 것으로 푼다.

**첫 실행 흐름** (전체 화면, 2단계, 어느 단계든 [건너뛰기])

```
① 반가워요        이음오피스로 한글·PDF·마크다운… 을 열고 고칩니다.
                  계정 없이, 광고 없이, 문서는 이 기기에만.          [다음]
② 문서 폴더 연결   자주 쓰는 폴더를 연결하면 "폴더" 탭에서 바로 보여요.
   (선택)         [폴더 고르기]  [나중에]                          ← 시스템 폴더 선택 창
                  고른 뒤: "✓ 문서 폴더 연결됨 · 바꾸기는 설정에서"
→ 홈. 빈 상태면 [예시 문서 열어 보기] [파일 열기] [새로 만들기]
```

- **AI는 첫 실행에서 묻지 않는다.** 기본이 꺼짐이라 처음 보는 화면에 AI가 없다. 켜는 길은 설정 > AI의 스위치 하나다. 켜면 그 자리에서 연결(키·무료 연결) 안내가 이어진다.
- 연결 단계는 앱 계정·로그인을 요구하지 않는다.
- 첫 실행은 한 번만. 설정 > 도움말 > "처음 안내 다시 보기".

**처음 쓰는 순간의 도움말 `Tips`** (한 번씩만, 한 화면에 하나)

| 언제                          | 무엇을                                                   | 모양                       |
| ----------------------------- | -------------------------------------------------------- | -------------------------- |
| 문서를 처음 보기 모드로 열 때 | "고치려면 [편집]"                                        | [편집] 옆 말풍선           |
| 한글을 폰에서 처음 열 때      | "흐름 보기로 읽기 편하게 바꿨어요 · 쪽 보기는 여기"      | 보기 전환 옆 말풍선        |
| 처음 편집에 들어갈 때         | "자동으로 복구 사본을 만들어요. 원본은 [완료]할 때 저장" | 상단 상태 표시 아래 말풍선 |
| 처음 키보드가 뜰 때           | "[Aa]로 글자 모양 바꾸기"                                | 보조 막대 위 말풍선        |
| 처음 공유할 때                | (없음 — 시트가 스스로 설명)                              | —                          |

- 말풍선은 누르거나 다른 곳을 만지면 닫히고 다시 나오지 않는다. 막는 창(modal)으로 띄우지 않는다.
- 낭독기가 켜져 있으면 말풍선 글을 알림으로 읽고 초점은 옮기지 않는다.
- 설정 > 도움말: 사용법 짧은 글 목록(문서 열기·편집·저장과 복구·공유·흐름 보기·AI 켜고 끄기), 의견 보내기.

**거절·취소했을 때**

- 폴더 고르기를 취소: 홈 "폴더" 탭 빈 상태에 [폴더 연결] 단추. 다시 묻는 창은 띄우지 않는다.
- 연결한 폴더의 허락이 사라짐(폴더 이동·삭제·OS 정리): 그 폴더 줄에 "다시 연결" 단추와 이유.

## 6. AI 보임 규칙 (D1)

1. **진입점은 모두 `aiVisible` 하나를 읽는다.** 데스크톱 `@genoffice/ui`의 `useAppChoice`·`aiVisible`과 같은 뜻으로 맞추고, 모바일 설정 `prefs.aiEnabled`가 그 값을 낸다. 진입점 목록(모두 여기에 등록):
   - 편집 도구 막대 [AI] 단추(5.6)
   - 태블릿 오른쪽 AI 패널과 그 여닫기 단추
   - 문서 메뉴·더보기의 AI 항목
   - 선택 메뉴의 AI 항목(두지 않음이 기본, 아래 4)
   - 홈·만들기 시트의 "AI로 만들기"
   - 설정의 AI 연결 절(끄면 절 전체 숨김, 켜기 스위치만 남김)
   - (예외) 설정 > AI의 켜기 스위치는 늘 보인다 — 켜는 길이기 때문. 스위치 아래 한 줄: "켜면 문서 고치기·요약을 도와주는 AI 단추가 나타납니다. 쓰려면 AI 연결이 필요합니다."
2. **끄면 자리째 사라진다.** 빈칸·회색 단추·"AI 꺼짐" 표시를 남기지 않는다. 막대는 남은 단추로 다시 정렬된다.
3. **기본값은 꺼짐(`aiEnabled: false`).** 설정을 읽기 전에도 숨긴 채 그린다(깜빡 보였다 사라지지 않게). PC판은 기본 켜짐이라 이 점이 다르다(모바일은 키·무료 연결만 있어 AI 없이 시작하는 편이 자연스럽다).
4. **AI를 글자 선택 메뉴에 끼우지 않는다.** 선택한 글에 AI를 쓰려면 [AI] 단추를 누르면 선택이 시트에 인용되어 들어간다.
5. **결과는 미리 보고 적용한다.** 문서에 바로 쓰지 않고, 바뀐 곳 표시(데스크톱 `--color-ai-changed-*`) + [적용][되돌리기].
6. 끌 때 돌고 있는 AI 작업이 있으면 "멈추고 끌까요?"를 묻고 멈춘 뒤 끈다(데스크톱과 같음).

## 9. 만드는 순서 (제안)

1. 토큰 파일 정리: `--m-*` 간격·글자·높이·움직임, `data-window`, 시스템 막대 색. 직접 값 옮기기. (프로토타입 화면은 그대로 보여야 함)
2. 껍데기 부품: `MobileFrame`, `BackStack`, `Sheet`, `Toast`.
3. 편집 화면 뼈대: `AppBar`(저장 상태 합치기), `EditToolbar`, `KeyboardBar`, `DocViewport` 쪽/흐름 전환(흐름 보기 동작은 rhwp 쪽 작업과 함께).
4. AI 보임 규칙: `aiVisible` 한 곳으로 모으기, 진입점 목록 시험.
5. 홈: 아래 탭·레일, 만들기 시트, 목록 여러 개 고르기.
6. 공유 시트와 받기(5.13), 첫 실행·처음 도움말(5.14).
7. 부품 문서: `design-system document`로 부품마다 한 장씩, 점검은 `ui-ux-pro-max` 앱 화면 규칙과 `check:theme-colors`.

기기 확인(먼저): safe-area 값이 들어오는지(Android WebView 판), 키보드 높이 알림, 보조 막대 누를 때 한글 조합 유지(Gboard·삼성·iOS), Android 글자 크기 배율, 예측형 뒤로 가기와 시트.

## 10. 정한 것 (2026-11-24, 아래 권장안대로 — D7)

1. **저장 방식.** 제안: 복구 사본은 늘 자동, **원본 파일 쓰기는 자동이 아니라** [완료]·상태 누르기·앱 나가기 때. 이유: 한글 원본을 자주 다시 쓰는 일의 위험(저장 결과가 원본과 같아야 하는 규칙), 파일 앱 위치 쓰기 비용. 대안: 원본도 몇 초마다 자동 저장.
2. **한글 흐름 보기에서 편집을 허용하나.** 제안: 1판은 글 넣기·지우기·글자 서식까지 허용, 표 구조·쪽 모양은 쪽 보기로 넘김. rhwp에서 흐름 보기가 어디까지 되는지에 따라 줄일 수 있다.
3. **홈 아래 탭 구성.** → 11-24 [최근][폴더][도구][설정] 넷으로 정함.
4. **UI 글꼴.** 제안: OS 시스템 글꼴(데스크톱과 같은 방식, 앱 크기 0). 대안: 한 글꼴을 묶어 두 플랫폼에서 완전히 같게(앱 크기 증가).
