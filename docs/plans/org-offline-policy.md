# 조직 정책으로 외부 연결 끄기 계획

상태: **계획**(2026-11-11). 아직 코드를 바꾸지 않았다. 정한 것은 결정 기록 [0134](../tracking/decisions/0134-org-policy-blocks-external-connections.md)에 옮겼다. 단계별 세부는 구현하면서 이 문서를 고친다.

## 1. 무엇을 하려는가

회사에서 이음오피스를 쓰는 사람들에게서 같은 문의가 거듭 들어온다. AI가 기본으로 들어 있고 누구나 켤 수 있어서, 회사가 허락하지 않은 AI에 직원이 문서를 보낼 수 있다는 것이다. 그래서 AI가 없거나 막힌 판을 따로 달라고 한다.

이 계획은 **회사 관리자가 PC에 정책 값 하나를 넣으면, 그 PC의 이음오피스가 바깥으로 아무것도 보내지 않게** 한다. 로컬 AI(이 PC나 사내망의 AI 서버)는 그대로 쓴다. 업데이트 확인 하나만 예외로 둔다.

설치 파일을 따로 만들지 않는다. 설치 파일은 관리자 권한 없이 사용자 폴더에 깔리므로(`apps/shell/electron-builder.cjs`의 `nsis`), AI 없는 판을 회사가 깔아 줘도 직원이 일반판을 받아 덮어 깔 수 있다. 정책 값은 어느 폴더에 깔린 사본이든 똑같이 읽힌다. 판이 둘이면 릴리스마다 만들고 확인할 파일도 두 배가 된다.

`docs/plans/local-llm.md`가 "오프라인 모드 부재"로 남겨 둔 것 가운데 앱이 바깥과 끊기는 부분을 이 계획이 맡는다. 로컬 모델의 문맥·도구 문제는 그 계획에 그대로 남는다.

## 2. 정한 것 (저장소 주인, 2026-11-11)

1. **한 설치 파일에 정책을 둔다.** 회사 IT가 정책 값을 배포하고, 이 저장소는 값을 넣는 파일과 그룹 정책 서식, 안내 문서를 낸다.
2. **AI와 Google 드라이브를 포함해 바깥으로 나가는 연결을 모두 끊는다.** PRIVACY.md의 "What leaves your PC" 표에 있는 연결 전부와, 그 표에 없는 연결까지다(4.3절).
3. **로컬 AI는 남긴다. 범위는 이 PC와 사내망이다.** 루프백, 사설 IP, 그리고 실제로 사설 IP로 풀리는 이름 주소를 허용한다. 공인 주소는 거절한다(6절).
4. **업데이트 확인만 예외다.** 이 저장소의 GitHub 릴리스를 읽고 내려받는 요청만 통과시킨다.
5. **MCP 서버는 모두 막는다.** 원격 서버와, 이 PC에서 프로그램을 띄우는 서버 둘 다다. PC에서 띄운 프로그램은 앱과 상관없이 인터넷에 닿을 수 있어 앱이 지킬 수 없다. 로컬 AI는 앱에 들어 있는 문서 도구만 쓴다.

## 3. 정책 값

### 3.1 놓는 곳

| 운영체제 | 놓는 곳                                                                                   | 고칠 수 있는 사람                 |
| -------- | ----------------------------------------------------------------------------------------- | --------------------------------- |
| Windows  | `HKLM\SOFTWARE\Policies\IeumOffice`                                                       | 관리자(그룹 정책, Intune, `.reg`) |
| macOS    | `/Library/Managed Preferences/io.github.pblsketch.ieumoffice.plist`(구성 프로파일로 배포) | 관리자, 기기 관리 도구            |
| Linux    | `/etc/ieumoffice/policy.json`                                                             | root                              |

값은 둘이다.

| 이름                       | 종류                 | 뜻                                                  |
| -------------------------- | -------------------- | --------------------------------------------------- |
| `BlockExternalConnections` | Windows `DWORD`(1/0) | 1이면 바깥 연결을 끊는다                            |
| `AllowUpdateCheck`         | Windows `DWORD`(1/0) | 끊긴 동안 업데이트 확인을 둘지. 값이 없으면 1(둔다) |

macOS·Linux는 같은 이름의 참/거짓 값이다. `AllowUpdateCheck`는 주인이 정한 기본(업데이트 허용)을 그대로 두되, 업데이트도 직접 배포하려는 회사가 끌 수 있게 둔다.

사용자 데이터 폴더의 `ai-settings.json`·`app-settings.json`에는 넣지 않는다. 사용자가 고칠 수 있는 파일이라 막는 장치가 되지 못한다.

### 3.2 읽는 법

- 앱이 켜질 때 한 번, 터미널 명령어 프로세스가 시작할 때 한 번 읽는다. 값을 바꾸면 앱을 다시 켜야 한다.
- Windows는 이미 쓰고 있는 길(`apps/shell/src/main/default-app.ts`처럼 셸 없이 `reg query`)로 읽는다.
- 읽는 곳은 껍데기 앱 뒷단의 모듈 하나다. 편집기 뒷단과 화면은 그 결과만 받는다. 명령어(`packages/cli`)는 같은 판정 함수를 Electron 없이 부른다.
- **값이 1이 아니면 꺼진 것이다.** 키가 없거나 0이면 지금과 똑같이 동작한다.
- **키는 있는데 값을 읽지 못하면 켜진 것으로 본다.** 회사가 넣은 정책을 앱이 놓치는 쪽이 더 나쁘다. 설정의 안내 줄에 "정책을 읽지 못해 외부 연결을 꺼 두었습니다"를 보인다.
- **`reg.exe`가 막힌 PC.** 레지스트리 편집 도구를 막는 정책(`DisableRegistryTools`)이 걸린 PC에서는 `reg.exe`도 거절할 수 있다. 그때는 PowerShell을 프로필 없이 셸 없이 띄워 .NET의 레지스트리 읽기(`[Microsoft.Win32.Registry]::GetValue`)로 한 번 더 읽는다. 둘 다 실패하면 위 규칙대로 켜진 것으로 본다. 그런 PC는 회사가 관리하는 PC이므로 막히는 쪽이 맞다. 실제로 어느 것이 막히는지는 1단계에서 그 정책을 건 PC로 확인해 이 절에 적는다.

## 4. 세 층으로 막는다

기능 하나하나를 감추는 것만으로는 놓치는 연결이 생긴다. 예를 들어 Linux의 맞춤법 검사는 사전을 Google 서버에서 받아 오는데, 이 연결은 지금 PRIVACY.md에 없다. 그래서 아래 세 층을 모두 둔다. 1층이 빠져도 2층이, 2층이 빠져도 3층이 막는다.

### 4.1 1층: 입구를 감춘다

바깥으로 나가는 기능의 단추·메뉴·설정 칸을 감추거나 "조직이 꺼 둠"으로 바꾼다. 무엇을 어떻게 하는지는 5절의 표에 있다. 사람이 눌러 보고 실패하는 일이 없게 하려는 층이다.

### 4.2 2층: 제공자를 로컬 AI로 좁힌다

- `selectAiProvider`(`packages/ai-provider/src/provider-selection.ts`)는 정책이 켜진 동안 로컬 AI 서버(`customEndpoints`)만 고른다. 구독, ChatGPT 직접 연결, 키 제공자, 무료 연결은 저장된 값이 있어도 고르지 않고, 로컬 AI가 없으면 새 오류 종류 `blocked-by-policy`를 돌려준다.
- `streamForProvider`(`packages/ai-provider/src/stream.ts`)도 같은 판정을 한 번 더 한다. 명령어·MCP의 PDF·EPUB 번역이 이 길로 간다.
- Claude Code·Codex 프로그램은 띄우지 않는다. 상태 확인(버전·로그인 명령)도 돌리지 않는다. 그 프로그램들의 상태 명령이 스스로 바깥에 묻지 않는다고 장담할 수 없다.
- 에이전트 창 세션은 시작하지 않는다.
- `ai-search`의 검색·이미지·미디어·웹 읽기 도구는 AI에게 주지 않는다. `internetTools`가 `false`인 것과 같이 다루고, 도구 함수 안에서도 한 번 더 거절한다.

### 4.3 3층: 네트워크 길목에서 거절한다

앱이 내는 모든 요청을 한 판정 함수(`isAllowedUnderPolicy`)에 묻는다. 허용하는 것은 다음뿐이다.

- 앱 자신의 주소: 화면 주소(`RENDERER_SCHEME`), 다이어그램의 draw.io 주소, `file:`, `data:`, `blob:`, 개발 실행의 개발 서버.
- 로컬 AI로 허용되는 주소(6절).
- 업데이트 예외(4.4절).

길목은 셋이다.

1. **Electron 세션.** 기본 세션과 새로 생기는 모든 세션(`app.on('session-created')`)의 `webRequest.onBeforeRequest`에 판정을 건다. 화면이 불러오는 문서 속 바깥 그림·글꼴·스타일, 맞춤법 사전 받기, Electron `net` 요청이 여기서 걸린다. 다이어그램 탭의 길목(`apps/diagram/src/main/network-guard.ts`)은 이미 더 좁게 막고 있으니 그대로 둔다.
2. **뒷단의 Node 요청.** 전역 `fetch`, undici의 전역 디스패처, `http`·`https` 모듈의 요청을 앱이 켜질 때 감싸 같은 판정을 거친다. 지금 `fetch`를 부르는 뒷단 파일은 21개다(`apps/*/src/main`, `packages/*/src`). 하나씩 고치지 않고 길목 하나에서 막는다.
3. **자식 프로세스.** 정책이 켜지면 Claude Code, Codex, MCP 서버 프로그램, Node.js·uv·Python 내려받기를 띄우지 않는다. PDF 처리 프로세스와 엑셀 처리 프로그램은 바깥 요청이 없는지 구현 때 확인하고 그 결과를 이 문서에 적는다. 명령어 프로세스는 같은 정책을 읽고 2의 길목을 자기 안에 건다.

거절할 때마다 세션 이름과 대상 주소의 호스트 이름만 앱 기록에 남긴다(주소 전체와 본문은 남기지 않는다). 다이어그램 탭처럼 허용·거절 수를 세어, 시험에서 "거절된 것이 있었는가"를 확인할 수 있게 한다.

### 4.4 업데이트 예외

- `electron-updater`는 자기 세션(`electron-updater` 파티션)으로 요청한다. 그 세션에서만 `github.com`, `api.github.com`, 릴리스 파일이 내려오는 GitHub 주소를 허용한다. 다른 세션에서 같은 주소로 가는 요청은 거절한다.
- 이어 받기(`apps/shell/src/main/update-resume.ts`)는 Node `fetch`로 설치 파일을 받는다. 이 요청은 업데이트 전용 통로 함수로 바꿔, 그 함수가 낸 요청에만 같은 GitHub 주소를 허용한다.
- 업데이트 창의 상세 내역은 확인 응답에 이미 들어 있으니 새 요청이 없다.
- `AllowUpdateCheck`가 0이면 예외도 없고, 설정 → 정보의 업데이트 칸과 "업데이트 확인…" 메뉴를 감춘다.

## 5. 기능별 처리

PRIVACY.md의 표 순서다. "감춤"은 1층, 오른쪽 열은 감춘 뒤 남는 것이다.

| 기능                                                             | 정책이 켜지면                                                               |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- |
| AI 창(구독, ChatGPT 직접, 키 제공자, 무료 연결)                  | 로컬 AI만 고를 수 있다. 설정 → AI에는 로컬 AI 칸만 보인다                   |
| 무료 연결의 OpenRouter·Gemini 연결, 키 확인 요청                 | 감춤                                                                        |
| PDF AI 읽기·번역·설명·하이라이트·개요, EPUB 채우기·책 번역       | 로컬 AI로 돈다. 로컬 AI가 없으면 단추는 보이되 누르면 로컬 AI 설정으로 안내 |
| 명령어·MCP의 `pdf ai-read`·`pdf translate`·`epub translate`      | 로컬 AI로만 돈다. 없으면 `blocked-by-policy`로 끝난다                       |
| 스킬(기본·내 스킬)                                               | 그대로. 내용은 로컬 AI에게만 간다                                           |
| GitHub에서 스킬 받기·업데이트 확인, 검토한 스킬 모음             | 감춤. zip·폴더로 가져오기는 남긴다                                          |
| 첨부(PC 파일, 이음오피스 문서, `@`), 프로젝트 폴더               | 그대로. Google 드라이브에서 첨부는 감춤                                     |
| 만들기 창                                                        | 로컬 AI로 돈다. "AI 없이 바꾸기"는 그대로                                   |
| 웹 검색·그림 찾기·웹 페이지 읽기, `ieumoffice search`·`read-url` | AI 도구에서 뺀다. 명령은 `blocked-by-policy`로 끝난다                       |
| 주소로 그림 넣기(AI, MCP 클라이언트)                             | 거절                                                                        |
| 마인드맵 링크의 미리보기 그림·제목 가져오기                      | 체크 칸 감춤                                                                |
| 이미지 생성, 영상·소리 분석                                      | 감춤. 그림 보기는 로컬 AI가 그림을 받는 모델일 때만                         |
| 업데이트 확인                                                    | 예외(4.4절). `AllowUpdateCheck`가 0이면 감춤                                |
| 의견 보내기                                                      | 감춤                                                                        |
| AI 연결 안내의 "화면으로 단계 보기"(사이트)                      | 감춤. 연결 안내는 로컬 AI 연결 안내로 바뀐다                                |
| 마크다운 그림 올리기 호스트                                      | 감춤. 그림은 문서 옆에 둔다                                                 |
| 홈 파일 검색의 다시 순위 매기기                                  | 감춤                                                                        |
| Google 드라이브(연결, 고르기, 저장, AI 읽기, 첨부, 끊기)         | 설정 → 연동의 드라이브 칸과 홈의 "Google 드라이브에서 고르기"를 감춤        |
| 에이전트 창                                                      | 홈 사이드바의 항목을 감춤                                                   |
| MCP 서버(원격, PC 안 프로그램, 로그인, 런타임 내려받기)          | 설정 → 연동의 MCP 칸을 감춤. 저장된 서버는 지우지 않고 쓰지 않는다          |
| 앱 안 MCP 서버(`ieumoffice mcp`, 앱이 여는 루프백 서버)          | 그대로. PC 안에서만 열리고, 그 안의 AI 경로는 위 규칙을 따른다              |

이미 저장된 키·로그인·드라이브 연결은 지우지 않는다. 정책이 풀리면 그대로 돌아온다. 정책이 켜진 동안 앱은 그 값을 쓰지 않는다.

**문서 속 링크.** 문서의 하이퍼링크를 눌러 사용자의 브라우저로 여는 것은 그대로 둔다. 브라우저는 회사가 따로 관리하고, 앱이 보내는 것이 없다. 앱이 스스로 여는 바깥 페이지(의견 보내기 양식, 소개 사이트의 안내 절)만 감춘다. 앱에 들어 있는 도움말은 그대로다.

## 6. 로컬 AI 주소 판정

화면의 안내용 판정(`apps/shell/src/renderer/src/local-ai.ts`의 `localAddressNotice`)과 같은 범위를 뒷단에서 쓸 수 있게 옮기되, 이번에는 막는 판정이다.

- 허용: `localhost`, 루프백(`127.0.0.0/8`, `::1`), 사설 IPv4(`10/8`, `172.16/12`, `192.168/16`), 링크 로컬(`169.254/16`, `fe80::/10`), IPv6 고유 로컬(`fc00::/7`).
- 이름 주소(`llm.corp.local`, `gpu-box`)는 요청할 때 DNS로 풀어, 나온 주소가 모두 허용 범위일 때만 보낸다. 하나라도 공인 주소면 거절한다. 연결은 판정한 그 주소로 한다(판정 뒤 이름이 다른 주소로 바뀌는 것을 막는다).
- `http://`도 허용한다. 사내망 서버는 인증서 없이 도는 경우가 많다. 지금의 "암호화 없이 보냅니다" 안내는 그대로 보인다.
- 정책이 켜진 동안 로컬 AI 칸에서 공인 주소를 저장하려 하면 저장하지 않고 까닭을 보인다. 이미 저장된 공인 주소의 서버는 목록에 흐리게 남고 고를 수 없다.
- 프록시: 시스템 프록시를 거쳐도 판정은 원래 대상 주소로 한다.

## 7. 회사 IT에 건네는 것

- `tools/policy/` 아래에 정책을 켜고 끄는 `.reg` 파일 둘, 그룹 정책 서식(`IeumOffice.admx`와 `ko-KR`·`en-US`의 `.adml`), macOS 구성 프로파일 예시, Linux `policy.json` 예시.
- 안내 문서 `docs/org-policy.md`(한국어, 영어 요약). 값의 뜻, 놓는 곳, 확인하는 법(설정의 안내 줄), 한계(11절).
- 위 파일들을 묶은 `IeumOffice-org-policy-<버전>.zip`을 릴리스 자산에 함께 올린다. 파일이 작고, 회사 IT가 앱과 같은 곳에서 받는다. `docs/releasing.ko.md`의 자산 목록에 넣는다.
- README·README.en·PRIVACY.md에 "회사에서 외부 연결을 끄려면" 절을 더한다. 소개 사이트에는 3단계가 담긴 버전을 낼 때 짧은 안내 절과 저장소 문서 링크를 둔다.

## 8. 화면

- 설정 창 맨 위에 안내 줄 하나: "이 PC의 조직 정책으로 외부 연결이 꺼져 있습니다. 로컬 AI만 쓸 수 있습니다." 업데이트를 끈 정책이면 "업데이트도 관리자가 배포합니다"가 붙는다. 강조 띠나 색 막대 없이 배경과 테두리로 구분한다.
- AI 창의 연결 안내는 로컬 AI 연결 안내 한 가지로 바뀐다.
- 정책 때문에 거절된 요청의 오류는 "조직 정책으로 막혔습니다"로 보인다. 바깥 연결이 실패한 것처럼 보이지 않게 한다.
- 문구는 21개 언어 모두 채운다(터키어가 합쳐지면 22개).

## 9. 단계

1. **판정과 길목.** 정책 읽기, 판정 함수, 3층 길목(세션, Node 요청, 자식 프로세스), 2층 제공자 좁히기, 명령어 쪽. 화면은 아직 그대로라 눌러 보면 "조직 정책으로 막혔습니다"가 뜬다. 이 단계만으로 바깥에 나가는 것이 없어야 한다.
2. **화면 정리.** 5절의 감추기, 설정 안내 줄, 연결 안내, 21개 언어 문구, 도움말.
3. **IT 배포물과 문서.** 7절의 파일, `docs/contracts.md`(정책 값과 `blocked-by-policy`를 약속으로), `docs/security.md`, PRIVACY.md, README.

단계마다 PR 하나다. 1단계는 모든 편집기 뒷단을 지나므로 껍데기 앱을 다시 빌드해 확인한다.

## 10. 확인

- 단위 시험: 정책 읽기(없음, 0, 1, 읽기 실패), 주소 판정(범위 경계, IPv6, 이름 주소가 섞여 풀리는 경우), 업데이트 예외가 다른 세션·다른 함수에서는 통하지 않는 것.
- e2e: 정책을 켠 시험 프로필로 빌드한 앱을 띄우고, 모든 편집기를 열고, 로컬 AI(시험용 가짜 서버)로 대화 한 번, 5절의 기능을 차례로 눌러 본다. 끝에 길목의 거절 수와 허용된 바깥 주소 수를 확인한다. 허용된 바깥 주소는 업데이트 예외뿐이어야 한다.
- 네트워크 수준 확인: 정책을 켠 PC에서 앱을 한 시간 써 보며 바깥으로 나간 연결을 PC 쪽 도구로 기록해, 업데이트 주소 말고는 없는지 본다. 주인이 Windows에서 한 번 한다. Mac·Linux는 사용자 보고로 확인한다.
- 실제 그룹 정책: `.admx`를 넣은 PC에서 정책 편집기로 켜고 앱이 읽는지 본다.

## 11. 한계 (회사에 그대로 알린다)

- 이 정책은 앱이 스스로 지키는 장치다. 보안 경계는 아니다. 이 기능이 들어가기 전 버전은 정책을 모른다. 직원이 Claude Code·Codex나 웹 브라우저로 AI를 쓰는 것은 앱이 막을 수 없다.
- 확실히 막으려면 회사 네트워크에서 AI 회사 주소를 막아야 한다. 이 정책은 그 위에 얹어, 앱 안에서 실수로 보내는 일이 없게 하는 것이다.
- 앱은 정책을 지키지만, 정책 값을 넣고 관리하는 일과 그 PC에 어떤 버전을 깔지는 회사의 일이다.
