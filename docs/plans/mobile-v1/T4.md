# T4 — HTML 편집기와 마크다운 마무리 (모바일 1판)

휴대폰·태블릿에서 HTML 문서를 보고, 글을 고치고, 저장·공유·내보내고, AI(기본 꺼짐)로 고친다. 이미 있던 마크다운 편집기에는 바이트 그대로 저장, 찾아 바꾸기, 워드·ODT 내보내기, AI 숨기기를 더했다. 자리 표는 [README.md](README.md), 쓰는 법은 `apps/mobile/AGENTS.md`의 `### T4 HTML·마크다운 (1판)`.

## 한 일

- **새 파일로 내보내는 명령**(`mobile_web_save_new_file`, `commands/html.rs`): 시스템 저장 창으로 새 파일을 골라 바이트를 쓴다. 열린 문서의 세션·최근 목록·복구 사본·바뀜 상태는 그대로다. 받는 MIME은 워드·ODT·한글(.hwpx) 셋뿐이고, 다른 값과 틀린 base64는 `INVALID_ARGUMENT`, 저장 창 취소는 `USER_CANCELLED`다. 다리 감싸개는 `saveNewFile`(`@genoffice/mobile-bridge/html`).
- **바이트 그대로 저장**(마크다운·`.txt`·HTML): 읽을 때 BOM과 줄 끝(CRLF/LF)을 기억해 두고, 저장·다른 이름으로 저장·공유·복구 사본 때 다시 입힌다. 고치지 않은 문서는 연 때 받은 바이트를 그대로 쓴다. 복구 사본에서 되살린 글은 그 사본의 바이트로 겉봉을 정한다. UTF-8이 아닌 파일은 그 문서만 읽기 전용으로 열고 알림 띠로 까닭을 보인다.
- **마크다운 내보내기**: [⋯]에 "한글 문서로 저장"(원래 있던 것), "워드 문서로 저장", "ODT 문서로 저장"(`.md`만, `.txt`는 없음). 셋 다 PC와 같은 변환(마크다운 편집기 파서 → `exportDocxBytes`, ODT는 그 docx를 `docxToOdt`로, 한글은 `docx2hwp`)이고 새 파일 명령으로 쓴다. ODT에서 바뀌거나 빠지는 것이 있으면 PC 문구를 옮긴 확인 시트를 먼저 보인다. 한글 알림의 [열기]는 뺐다. 변환기는 처음 쓸 때 불러온다.
- **마크다운 찾아 바꾸기**: [⋯] "찾아 바꾸기" 시트(찾을 말, 이전·다음, "3/12", 바꿀 말, [바꾸기]·[모두 바꾸기]). 글자 그대로 찾고 대소문자는 기본으로 무시한다. 끝에서 처음으로 돈다. 편집 모드는 원문 칸에서 골라 보이고, 보기 모드는 미리보기 글을 CSS Custom Highlight API로 칠한다(DOM은 그대로). 바꾸기는 편집할 수 있는 문서에서만 보이고, 모두 바꾸기는 되돌리기 한 번으로 돌아간다. 한글 조합 중에는 다시 찾지 않는다. 숨김 표시 태그에 걸친 결과는 찾지도 바꾸지도 않는다.
- **마크다운 AI 숨기기**: 편집 모드에서 글을 골라 [⋯] 또는 서식 판의 "AI에게 숨기기" → 이름 시트("가림1"…) → PC와 같은 모양의 span으로 감싼다. 캐럿이 숨긴 구간 안에 있으면 같은 자리가 "숨김 풀기"가 된다. 미리보기는 숨김 표시를 안의 글로 바꿔 보인다(미리보기에만). 모델에는 `{{이름}}`만 가고, 모델의 편집은 자리 목록을 대조해 원래 span으로 되돌린다. 단추는 AI가 켜져 있을 때만 보인다.
- **HTML 편집기**(`editors/html/`): `.html`·`.htm` 열기, 새 HTML 문서(PC 빈 문서 뼈대), 다른 앱에서 열기(Android `text/html`, iOS `public.html`), 형식 그림.
  - 보기: 스크립트를 못 돌리는 틀(`sandbox="allow-same-origin"`)에 미리보기 사본(요소 번호 + CSP meta)을 넣는다. http(s)의 그림·스타일·글꼴은 불러온다. 링크는 따라가지 않고 양식은 보내지지 않는다. 원문에 `<script>`가 있으면 "휴대폰에서 실행하지 않습니다" 알림 띠.
  - 편집: 요소를 눌러 고르면(틀 위 겹침 상자) [글 고치기](시트에서 글 또는 직접 글 조각마다)·[지우기]가 막대에 나온다. [소스]로 원문 전체를 바로 고친다. 보기 모드의 [⋯] "소스 보기"는 읽기 전용이다. 모든 편집은 PC `document/`의 연산을 거친 Patch 하나다.
  - AI: PC HTML 스킬을 그대로 쓰고 도구는 `get_outline`·`read_source`·`apply_ops` 셋만 내놓는다. 요소 숨기기·숨김 풀기는 PC 표시(`data-gx-redact`)와 PC 투영·표식 검사를 쓴다.
  - 내보내기: [⋯] "워드 문서로 저장"·"ODT 문서로 저장". PC 변환기 `convertHtmlToDocx`를 스크립트 없는 틀 위의 모바일 드라이버로 부른다.
- **시험**: 모바일 `tests/web-*` 16개 파일, 다리 `tests/web-*` 5개 파일, `html.rs` 안의 Rust 시험. 실제 Chromium으로 HTML을 워드·ODT로 바꾸는 시험(`web-html-export-chromium.test.ts`, Playwright의 Chromium이 없으면 건너뜀)도 있다.

## 결정 후보 (번호는 합칠 때)

1. **내보내기는 열린 문서를 바꾸지 않는 새 파일 명령으로 한다.** 전에는 "한글 문서로 저장"이 공용 다른 이름으로 저장 명령을 써서 Rust 쪽 열린 문서가 새 `.hwpx`로 바뀌었고, 그 뒤 마크다운 저장·공유가 "열린 세션 없음"으로 조용히 실패했다. 새 명령 `mobile_web_save_new_file`은 저장소(`src/storage/**`, T6)를 고치지 않고 같은 파일 다리의 저장 창과 원자적 쓰기만 쓴다. 새 파일은 최근 목록에 넣지 않으므로 한글 알림의 [열기]를 뺐다(주인 승인 11-26, Q2). 버린 대안: 저장소에 "열린 문서를 바꾸지 않고 새 파일을 쓰고 최근 목록에 넣는" 함수를 더하기(T6과 같은 파일에서 부딪힘). [열기]를 살리려면 그 길이 필요하다.
2. **HTML 내보내기는 문서 스크립트를 돌리지 않는다.** PC(결정 0142)는 스크립트를 켠 격리 창에서 변환하지만 휴대폰 웹뷰에는 격리 세션이 없다. 그래서 문서를 미리보기와 같은 스크립트 없는 틀에 싣고, 변환기의 추출 코드를 부모 쪽에서 그 틀의 `window`·`document`를 넘겨 돌린다. 스크립트가 그리는 내용과 화면 찍기가 필요한 부분 그림(그라디언트·복잡한 SVG·장식)은 빠지고, 빠지면 알림이 그렇다고 말한다(주인 승인 11-26, Q3). 찍지 못한 블록은 그 블록에 보이던 글을 회색 문단으로 남기고(제목 모양은 잃음), 글도 없으면 "[옮기지 못한 그림]"(22개 언어)을 둔다. 변환기가 내는 영어 자리 글("Unavailable embedded content")은 쓰지 않는다. 보통 `<img>`는 캔버스로 그려 넣는다(다른 출처 그림은 빠짐).
3. **HTML 편집은 1판에서 글 고치기 + 지우기 + 소스로 좁힌다**(지우기: 주인 승인 11-26, Q5). 디자인 시스템 5.6의 HTML 줄("한글과 같은 문서형 [글자][문단][표][삽입]")과 다르다. 서식·옮기기·복제·그림 도구·스타일 패널은 2판. 받아들이면 디자인 시스템 5.6을 고친다.
4. **마크다운 숨김 규칙.**
   - 파일 모양은 PC 마크다운 편집기와 같다(`<span class="redact-span" data-redaction="" data-label="이름">글</span>`). PC에서 만든 숨김은 모바일에서, 모바일에서 만든 것은 PC에서 그대로 읽힌다.
   - 모델이 보는 글은 부를 때마다 새로 만들고, 공용 읽기(`redactMarkdownSource`) 결과와 한 글자도 다르지 않을 때만 쓴다. 다르거나 오류면 아무것도 보내지 않는다(닫힌 쪽으로 실패).
   - 모델 편집 되돌리기: 고치기 전·후의 `{{…}}` 목록이 같은 차례·같은 글일 때만 받아 원래 span으로 되돌리고, 되돌린 원문을 다시 가렸을 때 모델이 쓴 글과 같아야 한다. 그래서 숨김이 있는 문서에서 AI가 `{{x}}` 같은 글자를 새로 쓰면 거절한다.
   - 찾아 바꾸기에 더한 규칙: 숨김 표시가 있는 문서에서 바꾸기가 `<span`·`</span`·`data-redaction`의 수를 바꾸면 거절한다(`</span>`을 넣어 표시를 일찍 끝내는 것을 막음). 바꾼 뒤 `redactMarkdownSource`가 오류를 내면 되돌리고 알린다. 스펙 글귀 그대로라서, PC에서 이미 깨진 표시가 든 문서는 모든 바꾸기를 거절한다(이 문서는 어차피 AI가 막힘). "새로 오류가 날 때만 거절"로 풀 수 있다.
   - 숨기기는 고른 글이 새 span에 꼭 맞게 들어갈 때만 한다(`a </span> b` 같은 고름 거절). 고른 글에 `<`가 있으면 거절한다(PC는 이스케이프하지만 모바일은 원문 위에서 일함).
5. **HTML 미리보기는 http(s)의 그림·스타일·글꼴을 불러온다**(PC와 같은 모습, 주인 승인 11-26, Q4). 받은 HTML의 추적 그림도 불린다. 막으려면 미리보기 CSP에 `img-src data: blob:` 등을 더한다.
6. **UTF-8이 아닌 파일은 읽기 전용.** 고치면 글자가 깨져 저장되므로 그 문서만 보기·원본 공유로 연다. 마크다운·HTML 모두. 스크립트가 있는 UTF-8 아님 HTML은 UTF-8 알림 띠만 보인다.
7. **미리보기 사본에서 `<meta http-equiv="refresh">`를 무력하게 만든다.** sandbox와 CSP로는 틀이 다른 쪽으로 넘어가는 것을 막지 못한다. 스펙 밖에서 더했고 미리보기·내보내기 사본에만 한다(저장 파일은 그대로).
8. **`.txt`에도 숨기기·숨김 풀기를 둔다.** 스펙은 마크다운만 말했다. `.txt`도 AI 도구를 쓰므로 같은 규칙을 걸었고, 보통 글 미리보기는 숨김 표시 안의 글을 보인다. 빼려면 [⋯]·서식 판의 숨기기 줄을 `md`로 좁힌다.

## 발견 (고치지 않음)

1. **스펙 밖에서 막은 틈 셋**: 숨기기 고름이 새 span에 꼭 맞아야 함(결정 후보 4), HTML 요소 지우기 뒤 "지웠습니다, 되돌리기로 돌아옵니다" 알림, 찍지 못한 내보내기 블록의 글 남기기(결정 후보 2).
2. **파일 옆 상대 경로 자산(`assets/…`)은 미리보기에 안 보인다.** 휴대폰에서 문서 폴더를 읽을 권한이 없다(1판 한계). `data:` 그림과 http(s)는 보인다.
3. **편집 막대의 [글 고치기]·[지우기]는 요소를 고른 동안만 나온다.** `EditorQuickActionItem`에 `disabled`가 없고 `EditorShell`은 T4 것이 아니다.
4. **parse5가 `</body>` 뒤 공백 글 조각의 위치를 `</body>`·`</html>` 태그에 걸쳐 잡는다.** 그 범위를 덮어쓰면 태그가 지워지므로, 글 고치기는 원문 범위에 태그 모양(`<[a-zA-Z/!?]`, RCDATA는 `</title`·`</textarea`)이 든 조각을 건너뛴다.
5. **스크립트·스타일·template·iframe·noscript 등 원문 글 요소, 빈 요소, 끝 태그를 생략한 요소는 "소스에서 고치세요"로 보낸다.**
6. **고름은 시작 태그 위치 + 태그 이름으로 들고 있다.** 편집 뒤에는 Patch 묶음으로, 되돌리기·다시 하기·소스 고침 뒤에는 앞뒤 공통 부분을 뺀 Patch 하나로 옮겨 다시 찾고, 못 찾으면 고름을 푼다.
7. **PC HTML 스킬의 지시문은 여전히 `plan_page`·`image_search`·`web_search`를 말한다.** 모바일은 "이 도구만 씀" 안내와 그림 만들기 꺼짐 안내를 덧붙인다. 실제 실행에서 지시문 품질을 볼 것. `apply_ops`가 `file://` 그림을 쓰려 하면 PC 코드가 `window.htmlApi`에 닿기 전에 거절한다.
8. **HTML 숨기기는 PC `redactMarkPlan`을 따른다.** 빈 요소는 값 있는 속성을 숨기고, `<br>`처럼 숨길 것이 없으면 "이 자리는 숨길 수 없습니다".
9. **html2docx가 제목 없는 iframe·video·audio에 영어 자리 글("Embedded content"·"Video"·"Audio")을 남긴다.** 변환기 쪽 문구라 고치지 않았다. 나중에 고칠 후보.
10. **쪽 배경색 PNG는 저장 압축(stored deflate)으로 만든다.** 픽셀은 PC와 같고 바이트는 다르다.
11. **두 숨김 span 찾기가 있다.** 다리(`mobile-bridge/src/markdown/redaction.ts`, 보통 `</span>`만 닫음)와 `editors/markdownFind.ts`. 하나로 모을 후보.
12. **ODT 변환 뒤 쓰기가 실패하면 "바꾸지 못했습니다" 알림을 다시 쓴다.**
13. **호스트(데스크톱) 빌드에서는 `resolve_file_bridge`가 부를 때마다 새 다리를 준다.** T4 상태와 `MobileFileService`가 다른 시험용 다리를 든다. 기기에서는 같은 `Arc`다.
14. **새 명령은 바이트를 그대로 쓴다**(hwpx 머리 검사·저장 보정 없음). 예전 다른 이름으로 저장 길의 `apply_hwp_save_fixes`는 기준·보정 없이 같은 바이트를 냈으므로 마크다운 → 한글에서 잃는 것은 없다.
15. **새 문구는 모국어 사용자가 보지 않았다**(22개 언어, PC 번역을 쓸 수 있는 곳은 그대로 옮김).

## 의존과 라이선스

`apps/mobile/package.json`에 더함("deps:" 커밋 셋): `parse5` 8.0.1(MIT, HTML 요소 지도, PC `apps/html`과 같음), `@genoffice/odt-engine`(작업 공간, Apache-2.0, jszip은 PC가 이미 씀 — MIT/GPLv3 이중), `@genoffice/html2docx`(작업 공간, Apache-2.0, `docx` MIT). 세 커밋 모두 `package-lock.json`의 `apps/mobile` 항목을 손으로 고쳤다.

## 실기기에서 볼 것

- 미리보기: 어두운 테마에서 틀의 바탕(`color-scheme: light` + Canvas), 틀 안 링크를 눌렀을 때 이동하지 않는지, 두 손가락 확대.
- 고른 요소 상자: 틀을 밀거나 확대했을 때, 틀 안 스크롤 상자를 밀 때, 화면을 돌렸을 때 따라가는지. 빈 곳을 누르면 `<body>`가 골라진다.
- 마크다운 찾기: 찾을 말을 치는 동안 원문 칸의 고름이 보이는지(초점은 입력 칸에 남음), 원문 칸 스크롤, `::highlight` 칠, 시트가 키보드 위로 올라오는지.
- 마크다운 숨기기: 캐럿이 숨긴 구간에 들어갈 때 단추가 "숨김 풀기"로 바뀌는지.
- HTML 내보내기: 큰 문서의 시간과 메모리(추출이 화면 스레드에서 돎), 늦게 불러오는 그림.
- 다른 앱에서 HTML 열기·공유로 받기.

## 합칠 때 정리할 것

- `package-lock.json`을 다시 만든다(`npm install --package-lock-only`). "deps:" 커밋 셋(`63b07839c` parse5, `8c6e82280` odt-engine, `83e0985bf` html2docx)이 잠금 파일을 손으로 고쳤다.
- T7이 합쳐지면 `packages/mobile-bridge/src/markdown/redaction.ts`의 `hiddenTextUnverified()`가 던지는 보통 `Error(HIDDEN_TEXT_UNVERIFIED_MESSAGE)`를 T7의 `MobileAiBlockedError`(`kind: 'hidden-unverified'`)로 바꾼다. 부르는 곳: `redactedMarkdownView` ← 스킬 만들기·`createAiRun`, `buildContext`, 모든 도구.
- `apps/mobile/AGENTS.md` "항상 지켜야 하는 것"의 **마크다운 → 한글** 문단(T4 절 밖)이 아직 `saveConvertedHwpx` + 알림 [열기]를 말한다. 새 파일 명령(`mobile_web_save_new_file`)으로 쓰고 [열기]가 없으며 워드·ODT가 더해졌다고 고친다.
- 기본 사전의 `markdownToHwpDone`·`markdownToHwpDoneLoss`·`openNow`를 이제 `markdownKind`가 쓰지 않는다(기본 사전은 고치지 않음). 다른 곳에서도 안 쓰면 지운다.
- 앱에 CSP를 넣게 되면 `'unsafe-eval'`을 허락해야 한다. HTML 내보내기 드라이버가 `new Function`과 `with`로 변환기 추출 코드를 틀의 전역 위에서 돌린다.
- `config/tracks/web.ts`의 Vite 플러그인 둘이 PC·변환기 파일에 기댄다.
  - `web-html-ai-locale`: PC HTML 렌더러 안 파일이 부르는 `../i18n/locale`만 `editors/html/htmlAiLocale.ts`로 바꾼다. PC가 `locale.tsx` 이름을 바꾸면 조용히 깨진다(한국어 요약 시험이 잡음).
  - `web-html2docx-browser`: html2docx의 `generate/page-settings.ts`(`Buffer`·`node:zlib`)와 `generate.ts`(`docx`의 `Packer`) 두 파일에만 대역을 건다. 원본이 그 파일을 바꾸면 빌드가 소리 내어 실패한다.
  - 찍지 못한 블록을 어느 노드에 남길지는 `convert.ts`가 노드의 `clip` 객체를 그대로 넘기고 다른 찍기보다 먼저 `elementExists`를 부르는 데 기댄다. 원본 받아오기 때 볼 것.
