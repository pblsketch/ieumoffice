## 1. 편집기 트랙이 쓰는 공용 AI 도구 (먼저 정하는 약속)

편집기 트랙(T1 엑셀, T2 PDF, T4 HTML·마크다운)은 자기 PC 스킬을 모바일에서 돌릴 때 웹·그림 도구를 이 모듈에서 받는다. T7이 만들고, 편집기 트랙은 가져다 쓰기만 한다.

- 자리: `apps/mobile/src/renderer/ai/tools/index.ts`
- 가져오기: `import { getMobileAiTools } from '../../ai/tools'`(경로는 편집기 폴더에서 맞춘다). 모듈을 불러오는 것만으로 네트워크가 나가지 않는다. AI를 처음 쓸 때 불러오는 덩어리 안에서 가져온다.

```ts
export interface MobileAiToolAvailability {
  /** AI 켬 + "AI가 인터넷 도구 쓰기" 켬: web_search, image_search, read_url, 그림 받기 */
  readonly web: boolean
  /** "AI가 그림 만들기" 켬 + 그림 모델을 고른 키 제공자가 있음 */
  readonly imageGeneration: boolean
  /** 지금 고른 대화 모델이 그림을 볼 수 있음(PC의 modelLacksVision 판정) */
  readonly pictureAnalysis: boolean
}

export interface MobileAiTools {
  /** 실행마다 다시 읽는다(설정이 바뀌면 다음 차례부터 따른다). */
  availability(): MobileAiToolAvailability
  webSearch(query: string, maxResults?: number): Promise<WebSearchAnswer>
  imageSearch(query: string, maxResults?: number): Promise<ImageSearchAnswer>
  readUrl(url: string, offset?: number): Promise<ReadUrlAnswer>
  /** 그림 검색 결과의 주소에서 그림 바이트를 받는다(문서에 넣기 전). */
  fetchImage(url: string): Promise<FetchImageAnswer>
  generateImage(request: GenerateImageRequest): Promise<GenerateImageAnswer>
  analyzeMedia(request: AnalyzeMediaRequest): Promise<AnalyzeMediaAnswer>
  /** 이 대화에서 사람이 AI 창에 붙인 사진(이름·MIME·바이트). */
  attachments(): readonly MobileAiAttachment[]
}

export function getMobileAiTools(): MobileAiTools
```

- **답의 모양은 모바일 공용 형 하나다.** PC는 편집기마다 같은 이름 함수의 답이 다르다(한글 `fetchImage`는 `{base64, mime} | null`, PDF `deps.fetchImage`는 `{png, width, height} | null`). 그래서 편집기 트랙은 자기 PC 스킬 의존 자리에 **얇은 변환**을 둔다(한글 변환은 T7이 `ai/hwpAgent.ts`에 둔다). 공용 형은 다음을 따른다(정확한 형은 AI-T4에서 이 파일에 덧붙인다):
  - `webSearch` → `{ results: { title, url, snippet }[] } | { error, errorCode }`(PC `ai-search` `webSearch`의 결과 항목과 같은 칸)
  - `imageSearch` → `{ images: { imageUrl, width?, height?, title?, sourceUrl? }[] } | { error, errorCode }`
  - `readUrl` → `{ text, url, title?, offset, nextOffset?, totalChars } | { error, errorCode }`(PC `readUrlModelText`에 넣는 값과 같은 칸)
  - `fetchImage(url)` → `{ bytes: Uint8Array, mime } | { error, errorCode }`. 공개 http·https 주소와 **AI 결과 보관소 주소**(`generateImage`가 돌려준 것)를 모두 받는다.
  - `generateImage({ prompt, size?, model? })` → `{ url: <보관소 주소>, mime } | { error, errorCode }`. 1판은 OpenAI·Gemini(base64 답)만.
  - `analyzeMedia({ prompt, images: { bytes, mime }[] })` → `{ text } | { error, errorCode }`
- **던지지 않는다.** 실패·꺼짐은 `{ error, errorCode }`로 돌려준다. 꺼진 도구는 `errorCode: 'unavailable'`.
- **멈추면 도구 요청도 끊긴다.** AI 창의 [중지], 모두 멈춤(`stopAllMobileAi`, AI 끄기), 문서 바꾸기(`resetForDocument`), 숨김 때문에 멈춘 실행에서 `useMobileAi`가 `abortMobileAiToolCalls()`를 부른다(PC `abortMediaCalls`와 같은 일). 그때 돌던 도구 호출은 Rust 요청(중계·검색·공개 주소 요청)에 취소를 보내고 바로 `errorCode: 'cancelled'`로 답한다. 멈춘 뒤에 돌아온 그림은 보관소에 두지 않고, 그림 만들기가 잠시 바꿔 둔 중계 연결은 곧바로 되돌린다. 편집기 트랙은 따로 할 일이 없다(도구를 부르기만 하면 된다).
- **도구 목록에서 빼는 일은 편집기 스킬이 한다.** PC 스킬의 가용성 질문(`webAvailable`, `imageGenAvailable`, `pictureAnalysisAvailable` 등)에 `availability()`의 값을 그대로 넘긴다.
- **인터넷 스위치와 주소 확인은 T7이 모든 실행에 씌운다**(결정 0062, `guardOutbound`에 모바일 다리 객체를 넘김). 편집기 트랙은 따로 할 일이 없다. 대화에 나온 적 없는 주소를 읽으려 하면 AI 창에 "막기/허용" 시트가 뜬다.
- **키는 웹뷰에 없다.** 모든 요청은 Rust가 보낸다(키 제공자는 봉인 저장소의 키를 Rust가 붙이고, 검색·주소 읽기는 키 없이). 편집기 트랙이 `fetch`로 바깥에 직접 나가지 않는다.
- **편집기가 "숨김 때문에 보내지 않음"을 알리는 공용 오류.** 편집기는 숨긴 부분(가리기 표시)을 확실히 가려내지 못하면 AI에 보내지 않는다. 이때 "연결 오류"가 아니라 아래 오류를 던진다.

  ```ts
  // apps/mobile/src/renderer/ai/blocked.ts (T7)
  export type MobileAiBlockedKind = 'hidden-unverified'
  export class MobileAiBlockedError extends Error {
    readonly kind: MobileAiBlockedKind
    constructor(kind: MobileAiBlockedKind, detail?: string) // detail: English, for logs only, never shown
  }
  export function isMobileAiBlocked(error: unknown): error is MobileAiBlockedError
  ```

  - 던지는 곳: 편집기 종류의 `createAiRun`(보내기 전), 또는 실행 중 스킬의 `buildContext`·`executeTool`(차례마다 문서를 다시 읽을 때). `useMobileAi`가 세 곳 모두에서 이 오류를 잡는다(합친 스킬을 감쌀 때 `buildContext`·`executeTool`에서 던져진 것도 잡아 그 실행을 멈춘다).
  - 종류 이름: `hidden-unverified`(숨긴 부분을 확인하지 못함). 다른 까닭이 필요하면 이 합집합에 더하고 문구도 같이 더한다(T7에 요청).
  - 문구 키(T7의 `i18n/ai`, 22개 언어): 제목 `aiBlockedHiddenTitle` "숨긴 부분이 있어 보내지 않았습니다", 설명 `aiBlockedHiddenDesc` "숨긴 부분을 확실히 가려내지 못해 문서를 AI에 보내지 않았습니다. 숨김 표시를 확인한 뒤 다시 보내세요." 편집기는 이 문구를 쓰지 않고 오류만 던진다.
  - AI 창이 하는 일: 연결 오류 대신 위 알림(경고 모양, `role="alert"`)과 [다시 보내기]를 보인다. 보내지 않은 사람의 메시지는 대화에서 빼고 입력란에 되돌려 둔다. 실행 중에 막혔으면 그 실행을 멈춘다(문서를 바꾼 차례가 있으면 그 변경 카드는 남는다). 대기열은 다음 것을 보내지 않고 멈춰 둔다(다음 것도 같은 까닭으로 막힐 것이므로). 모델·네트워크로는 아무것도 나가지 않는다.
  - T7이 합쳐지기 전에 T4가 먼저 만들면, 이 파일이 아직 없으니 보통 오류를 던져 두고(연결 오류로 보임) 합친 뒤 `MobileAiBlockedError`로 바꾼다.

- 편집기의 AI 실행 자체(`createAiRun`)는 지금처럼 편집기 종류가 만든다. 질문 카드(`ask_questions`)와 인터넷 감싸개는 `ai/useMobileAi.ts`가 모든 실행에 더한다.

### 정확한 형 (AI-T4에서 덧붙임)

형의 원본은 `apps/mobile/src/renderer/ai/tools/types.ts`다. `getMobileAiTools()`는 앱에 하나인 객체를 돌려주고, 부를 때마다 지금 상태를 읽는다. useMobileAi가 묶기 전(`bindMobileAiTools`)에는 모든 도구가 `unavailable`, `availability()`는 모두 거짓이다. `index.ts`는 처음 쓸 때 불러오는 덩어리에서 가져온다(앱 첫 덩어리에 들어가지 않게). 주소 읽기의 HTML 변환(PC `htmlToText`)과 그림 만들기(PC `media-protocols.ts`)는 그 안에서 다시 처음 쓸 때 불러온다.

```ts
type MobileAiToolErrorCode =
  | 'unavailable'
  | 'invalid_input'
  | 'invalid_model'
  | 'invalid_url'
  | 'blocked'
  | 'network'
  | 'timeout'
  | 'http_error'
  | 'unsupported_type'
  | 'too_large'
  | 'empty' // PC ReadUrlErrorCode와 같은 이름
  | 'not_found'
  | 'cancelled' // 실행을 멈춰 도구 요청을 끊음(아무것도 남기지 않음)
  | 'failed'
interface MobileAiToolError {
  error: string /* 모델용 영어 */
  errorCode: MobileAiToolErrorCode
  status?: number
}
function isMobileAiToolError(value: unknown): value is MobileAiToolError

// WebSearchResult = { title, url, snippet }, ImageSearchResult = { title, imageUrl, sourceUrl, source, width?, height? } (PC ai-search shared.ts)
type WebSearchAnswer =
  { results: WebSearchResult[]; method: 'parallel' | 'duckduckgo' } | MobileAiToolError // 기본 6개, 1..20
type ImageSearchAnswer = { images: ImageSearchResult[]; method: 'duckduckgo' } | MobileAiToolError // 기본 8개, 1..20
interface ReadUrlPage {
  url: string
  title?: string
  text: string
  offset: number
  totalChars: number
  truncated: boolean
  nextOffset?: number
}
type ReadUrlAnswer = ReadUrlPage | MobileAiToolError
function mobileReadUrlModelText(page: ReadUrlPage): string // PC readUrlModelText와 같은 글
interface MobileAiPicture {
  bytes: Uint8Array
  mime: string
}
type FetchImageAnswer = MobileAiPicture | MobileAiToolError // 보관소 주소는 인터넷 스위치가 꺼져도 읽는다
interface GenerateImageRequest {
  prompt: string
  size?: string /* 1:1, 16:9 … PC aspectRatio */
  model?: string
  transparent?: boolean
}
type GenerateImageAnswer =
  | { url: string /* ai-result://… */; mime: string; model: string; provider: 'openai' | 'gemini' }
  | MobileAiToolError
interface AnalyzeMediaRequest {
  prompt: string
  images: MobileAiPicture[]
} // image/*만, 영상·음성은 unavailable
type AnalyzeMediaAnswer = { text: string } | MobileAiToolError
interface MobileAiAttachment {
  id: string
  name: string
  mime: string
  bytes: Uint8Array
}
```

- 붙인 사진 저장소(`ai/tools`에서): `addMobileAiAttachment({ name, mime, bytes } | { name, mime, base64 })`, `removeMobileAiAttachment(id)`, `listMobileAiAttachments()`, `clearMobileAiAttachments()`, `onMobileAiAttachmentsChanged(listener)`, `mobileAiAttachmentBase64(attachment)`. 메모리에만 있고 문서를 바꾸면 비운다. AI 창의 사진은 base64로 넣는다: 저장소는 보낸 메시지의 그림과 같은 문자열 하나만 쥐고, `bytes`는 도구가 읽을 때 풀어 준다(사진이 메모리에 두 벌 남지 않음).
- 멈춤: `abortMobileAiToolCalls()`(위 "멈추면 도구 요청도 끊긴다"). `ai/tools/state.ts`에 있어 첫 덩어리에서 불러도 도구 본체를 불러오지 않는다.
- 도구 설정: `refreshMobileAiToolSettings()`(실행마다 useMobileAi가 부름), `updateMobileAiToolSettings(patch)`(저장하고 캐시와 감싸개에 알림), `mobileAiToolSettings()`, `onMobileAiToolSettingsChanged(listener)`.

## 2. 1판에 넣는 것

- **AI 연결**: OpenRouter 무료 연결(`:free` 모델만), Gemini 키, API 키 제공자, 직접 운영 서버(HTTPS 주소만). ChatGPT 바로 연결은 켜지 않는다. Claude·Codex 구독은 모바일에 없다.
- **AI 창**: 모델 고르기, 중지, 대기열, 변경 카드(결정 0151의 `AiChangesCard`)와 되돌리기, 질문 카드(이미 있음), 빠른 요청 "쉬운 말로 풀기"·"번역", 사진 붙이기.
- **AI 도구**: 웹 검색, 그림 검색, 주소로 읽기, 사진 보기, 키 방식 그림 만들기.
- **설정 AI 절**: 연결, 인터넷 도구 스위치, 그림 만들기 스위치와 그림 모델, AI 결과 보관소 크기·지우기, AI 끄기("멈추고 끌까요?").
- **한글 AI**: `ai/hwpAgent.ts`가 웹·그림·사진 도구를 켠다.

## 3. 결정과 까닭

1. **키 제공자 요청은 PC의 프로토콜 코드를 웹뷰에서 그대로 쓰고, 나가는 길만 Rust 봉인 중계로 바꾼다.** (주인 승인 11-26)
   - 지금의 모바일 Rust 스트림은 `AgentMessage`(`{role, text}`, `{role:'tool', results}`)를 공급자 형식으로 바꾸지 않고 그대로 보내며, 응답의 도구 호출을 읽지 않는다. 그래서 실기기에서는 문서를 고치는 AI가 돌지 않는다(가짜 다리 대본은 도구 호출을 바로 넣어 주어 드러나지 않았다).
   - PC의 `streamOpenAiCompatible`·`streamAnthropic`·`streamGemini`와 그림 생성 코드는 Node 전용 모듈을 가져오지 않는다. 모바일 묶음에서 `ai-provider/src/fetch.ts`만 모바일 판으로 바꿔 끼우면(`config/tracks/ai.ts`의 Vite 플러그인, `ai-provider` 안에서 그 파일을 가져올 때만) 메시지 변환·도구 호출 읽기·오류 분류(`free-limit` 등)·생각 되돌려 주기가 PC와 같다. PC 파일은 고치지 않는다.
   - 웹뷰는 키 자리에 `__sealed__:<제공자>` 표식을 넣는다. Rust는 그 제공자의 정해 둔 주소(직접 운영 서버는 저장한 HTTPS 주소의 호스트)로 가는 요청에서만 표식을 진짜 키로 바꾸고, 다른 호스트·http·되돌려 보내기(redirect)는 거절한다.
   - 버린 길: Rust에 공급자 형식 변환과 도구 호출 읽기를 다시 쓰는 것. PC와 같은 일을 두 벌로 갖고, PC가 고친 것이 모바일에 오지 않는다.
2. **검색은 키 없는 길만.** PC의 기본과 같이 Parallel 검색 다음 DuckDuckGo, 그림 검색은 DuckDuckGo. 검색 키 제공자(Serper 등) 설정은 1판에 두지 않는다. (주인 승인 11-26)
3. **주소로 읽기·그림 받기는 Rust의 공개 주소 요청으로.** 이름 풀이 뒤 사설·루프백·링크 로컬 주소를 거절하고, 되돌려 보내기는 다섯 번까지 매번 다시 검사한다. 10MB·30초·50,000자와 나눠 읽기는 PC(`readUrlTool`)와 같다. 공개 주소 판정이 PC(`electron-utils/safe-remote-url.ts`, `ai-search/read-url.ts`)와 일부러 다른 곳(표 전체는 `src-tauri/src/ai/web.rs` 머리 주석):
   - **198.18.0.0/15**: PC와 같이, 이름을 풀어 나온 답이 이 범위면 VPN fake-ip 자리 주소로 보고 받아들인다(VPN이 모든 이름에 이 범위를 주고 터널 끝에서 진짜 호스트를 푼다). 주소에 글자 그대로 쓴 198.18.x.x는 거절한다.
   - **NAT64 `64:ff9b::/96`**: PC는 통째로 거절하지만 모바일은 안에 든 IPv4로 판정한다. IPv6만 있는 휴대폰 망은 IPv4만 있는 사이트를 모두 이 주소로 답하므로, 거절하면 그런 망에서 주소 읽기가 모두 막힌다.
   - **6to4 `2002::/16`**: PC 표에는 없어 공개 주소로 지나가지만, 모바일은 안에 든 IPv4로 판정한다(사설 IPv4를 품은 6to4 주소는 거절). 이 밖에도 모바일 표에는 PC에 없는 범위(문서용 주소, Teredo, 고유 로컬 NAT64 `64:ff9b:1::/48` 등)가 더 있다.
   - **되돌려 보내기 다섯 번**: PC `read_url`은 열 번까지 따라간다. 모바일은 다섯 번(spec 3.3)이고, 여섯 번째에서 거절한다.
4. **인터넷 도구 스위치와 주소 확인은 결정 0062 그대로**(기본 켬, 대화에 나온 주소는 묻지 않음, 허용은 대화가 끝날 때까지). 질문은 운영체제 창 대신 AI 창 위의 시트다.
5. **그림 만들기는 설정에서 따로 켠다**(기본 끔). 1판의 그림 제공자는 base64로 답하는 OpenAI·Gemini 둘이고, 같은 회사의 대화 키를 쓴다. 켜려면 그중 키가 연결된 제공자와 그림 모델을 고른다. OpenRouter 무료 연결로는 그림을 만들지 않는다. PC의 다른 그림 제공자(BFL·Doubao 등)는 결과 주소를 내려받거나 따로 키가 있어 1판에서 뺀다. (주인 승인 11-26)
6. **변경은 바로 적용하고 카드로 되돌린다**(결정 0151, PC와 같음). 디자인 시스템 6.5의 "미리 보고 [적용]"과 다르다. (주인 승인 11-26)
7. **되돌리기는 마지막 차례만.** 한글·엑셀·PDF가 실행 취소 기록으로 되돌리므로(결정 0151) 앞선 차례의 카드에는 되돌리기 단추를 두지 않는다.
8. **선택한 글 인용**(디자인 시스템 6.4)은 1판에 넣지 않는다. 편집기 문서(`EditorDocument`)에 선택한 글을 묻는 자리가 없고 `editorKind.ts`는 트랙이 고치지 않는다. 선택은 지금처럼 각 스킬의 문맥이 모델에 알린다. (주인 승인 11-26)
9. **노란 표시는 편집기 몫이다.** 한글의 노란 표시는 고정 파일(`hwpKind.tsx`, 흐름 보기)을 고쳐야 해 1판에서 뺀다. (주인 승인 11-26)
10. **AI 결과 보관소**는 앱 데이터 폴더의 `ai-results/`다. 설정에서 크기를 보고 지운다. 편집기 트랙이 AI 결과를 남길 일이 생기면 같은 폴더를 쓴다. (주인 승인 11-26) 지금 보관소에 실제로 두는 것은 **AI가 만든 그림(`generate_image`)뿐이다.** 웹에서 받은 그림(`fetchImage`)과 AI 창에 붙인 사진은 그 대화 동안 웹뷰 메모리에만 있고 보관소에 쓰지 않는다(사진은 한 벌, 위 1절). 승인한 문구("AI가 만든·받은 그림, 붙인 사진 사본")보다 좁혔다(8절).
11. **OpenRouter 무료 연결은 지금처럼 키 붙여넣기.** 브라우저 로그인(PKCE)은 앱으로 돌아오는 주소 조건을 확인한 뒤로 미룬다. (주인 승인 11-26)
12. **직접 운영 서버는 HTTPS 주소만**, 호스트는 제한하지 않는다(사람이 직접 적은 주소). 키는 없어도 된다. (주인 승인 11-26)
13. **가리기(선택 영역 숨기기)는 편집기 몫이다.** PC에서도 문서 범위를 가리는 일은 편집기마다 하고(워드·슬라이드·마크다운·HTML), PC 한글에는 가리기가 없다. **마크다운·HTML 숨기기(화면과 표시)는 T4가 만든다**(조율 11-26). T7의 공용 부분은 1절의 "숨김 때문에 보내지 않음" 오류와 그 알림뿐이다. 트랙 설명서는 가리기를 T7 범위에 넣었으나 주인이 이 나눔을 승인했다. (주인 승인 11-26)

## 6. 실기기에서 볼 것

- 키 봉인 저장소: Android Keystore·iOS Keychain에서 키를 넣고 빼고, 중계가 표식을 키로 바꿔 실제 공급자에 닿는지.
- 긴 답을 받는 중에 화면이 꺼지거나 다른 앱으로 넘어갔다 돌아올 때 중계 요청과 대기열이 어떻게 되는지.
- 실제 공급자 응답의 모양(OpenRouter 무료 모델, Gemini, 키 제공자들)이 대본과 같은지, 오류 분류(`free-limit`·`free-tier-model`·`credits` 등)가 실제 응답에서도 맞는지.
- 오래된 웹뷰에서 Gemini 경로가 쓰는 `AbortSignal.any`가 있는지.
- 사진 붙이기의 시스템 선택 창(권한 창이 뜨지 않는지).
- 검색·주소 읽기의 실제 TLS·DNS(인증서, 이름 풀이, 되돌려 보내기 다시 검사), IPv6만 있는 망에서의 주소 검사와 연결.

## 8. 합칠 때 정리할 것

- `AiStorageRows`: T6 가지의 `StorageSection`은 자기 저장 공간 카드 뒤에 `<AiStorageRows>`를 형제로 그린다. 그래서 T7의 `AiStorageRows`가 자기 카드(제목 "AI 결과 보관소")를 갖도록 바꿨다. 합친 뒤 저장 공간 절 아래에 카드 둘이 이어 보이는지 본다. `.dryforge/handoff.md` 7절의 "자기 카드 안에서 그린다"는 실제와 다르다.
- `apps/mobile/tsconfig.json`의 주석 "The phone has no `window.hwpApi`: the tools that use it are not offered there."는 이제 맞지 않는다(실행 동안 대역이 있고 웹·그림 도구가 나온다). T7 소유가 아니라 고치지 않았다.
- `styles/mobile-tokens.css`의 `.mobile-changes-card`·`.mobile-changes-summary` 규칙은 이제 쓰는 곳이 없다(변경 카드는 공용 `AiChangesCard`와 `AiSheetPanel.css`). T7 소유가 아니라 지우지 않았다.
- 첫 덩어리 크기: 788.03 kB / 215.33 kB(T7 전) → 824.51 kB / 227.10 kB(AI-T3 뒤) → 1,021.01 kB / 287.44 kB(T7 끝). 다른 트랙과 합친 뒤 다시 잰다. 문구 묶음을 처음 쓸 때 불러오게 하려면 S0의 문구 묶음 방식을 바꿔야 한다.
- 한글 쪽 편집기 묶음에 `studio/fonts/RHWPOldHangul-Regular.woff2`가 없어 미리보기에서 404가 난다(T7과 무관, studio 묶음 쪽).
- AI 결과 보관소의 뜻을 승인 문구보다 좁혔다: 주인이 승인한 6절 8("AI가 만든·받은 그림, 붙인 사진 사본")과 달리 지금은 AI가 만든 그림만 둔다(3의 10). 받은 그림과 붙인 사진은 메모리에만 있다. 합칠 때 `.dryforge/handoff.md` 6절 8과 결정 후보의 문구를 이 실제에 맞춘다. 받은 그림·사진도 보관소에 두기로 하면 그때 웹뷰 쪽 쓰기를 더한다.
- `apps/mobile/AGENTS.md`의 T7 절 밖 두 줄("항상 지켜야 하는 것"의 **보안과 요금 경로**, **한글 AI 도구**)을 T7이 사실에 맞게 고쳤다(봉인 중계의 표식, 공용 AI 도구로 도는 웹·그림·사진 도구). 다른 트랙도 같은 줄을 고쳤으면 합칠 때 두 쪽 내용을 모두 살린다.
