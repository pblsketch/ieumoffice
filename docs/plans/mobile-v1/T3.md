# T3 — PDF 도구 (모바일 1판)

PC "PDF 도구"의 1판 묶음을 모바일 [도구] 화면으로 낸다. 처리 코드는 새 공용 패키지 `@genoffice/pdf-ops`로 PC와 함께 쓴다. 자리 표는 [README.md](README.md), 쓰는 법은 `apps/mobile/AGENTS.md`의 `### T3 PDF 도구 (1판)`.

## 공용 패키지 약속 (`@genoffice/pdf-ops`)

T2와 합치는 쪽이 읽는 약속이다. 바꾸면 이 절을 함께 고친다. 같은 이름은 PC에 있던 것과 뜻·입출력이 같다. 페이지 번호는 따로 적지 않으면 0부터.

- 패키지: `packages/pdf-ops`, `exports`는 `.`(전부)와 pdf-lib 없는 진입점 `./tool-ids`·`./tool-rules`·`./split-plan`·`./page-range`(화면·preload용), `"sideEffects": false`, 의존은 `pdf-lib`만. PDFium·qpdf·그림 다시 쓰기는 부르는 쪽이 넣는다. Node·Electron·네트워크 없음.
- **도구 영역 형·상수**(`./tool-ids`, PC `apps/shell/src/shared/pdf-tools-api.ts`에서 옮김; 용량 단계 `COMPRESS_LEVELS`·`CompressLevel`·`LEVEL_TARGETS`도 여기): `PDF_TOOL_IDS`, `PdfToolId`, `PdfToolOptions`, `PdfInputProblem`, `PdfToolAccept`, `PdfToolInputKind`, `PDF_TOOL_PAPERS`·`PdfToolPaper`, `PDF_TOOL_SHEET_PAGES`, `PDF_TOOL_ANNOT_KINDS`·`PdfToolAnnotKind`, `PDF_TOOL_MARGINS`·`PdfToolMargin`.
- **도구 규칙**(PC `tools.ts`에서; pdf-lib 없는 것은 `./tool-rules`에 — `PAPER_POINTS`·`MARGIN_POINTS`·입력 수·`checkOptions`·`outputNames`·`splitPlanFromOptions`·`pagesToText`·`PdfToolRefusal`·`InspectResult`·`CheckedOptions`·`DEFAULT_ANNOT_KINDS`; 파일을 읽는 `inspectPdf` 등은 `tools.ts`): `isPdfToolId`, `toolTakesMany`, `toolMinInputs`, `toolAccepts`, `toolInputKind`, `toolOutputExtension`, `MAX_PASSWORD_BYTES`(127), `PdfToolRefusal`(`'no-text' | 'no-annots' | 'not-smaller' | 'no-bookmarks'`), `InspectResult`, `inspectPdf(bytes)`, `inspectImage(bytes)`, `encryptedPageCount(bytes)`, `inspectToolInput(bytes, kind, accept)`(PC 창의 `pagesFor`), `checkOptions(tool, raw, pageCount, backgroundPages = 1)`, `CheckedOptions`, `DEFAULT_ANNOT_KINDS`, `splitPlanFromOptions(options, pageCount)`, `pagesToText(pages)`, `outputNames(tool, sourceName, count, options)`(PC 규칙 그대로, 떼는 확장자에 heic·heif·webp·gif·bmp·avif·tif·tiff를 더함), `readBookmarksBytes(bytes)`, `checkToolResult(tool, bytes)`(PC 창의 결과 다시 확인), `FoundBlankPages`.
- **실행기**: `PageEngine { mergePdfBytes(first, others); extractPagesBytes(bytes, pages); rotateAllPages(bytes, delta); removePages(bytes, pages); readText(bytes); mergePagesBytes?; setPageSizeBytes?; splitPagesBytes? }`, `RunDeps { engine; recode?; onProgress?; signal? }`, `runPdfTool(tool, inputs, options, deps)`(`encrypt`·`decrypt`·`repair`는 여기서 돌지 않음), `runSplitPdfTool(first, sourceName, options, deps?)`(엔진 필요 없음). PC `tools.ts`는 지금 시그니처 그대로(`deps` 선택)인 감싸개를 남겨 PC 엔진(`save-pdf.ts`·`read-text.ts` 원래 함수)을 채운다.
- **분할**(`split-plan.ts`, `split-pdf.ts`에서): 지금 내보내는 이름 전부 — `planSplitParts`, `formatSplitOutputNames`, `parseSplitRangeList`, `formatSplitRangeList`, `sanitizeSplitName`, `MIN_SPLIT_MAX_BYTES`, `MAX_SPLIT_MAX_BYTES`, `splitSubfolderName`, 형들, `executeSplitPlan`, `readPdfBookmarks`, `readBookmarksFromDoc` 등. 파일 경로를 쓰는 `uniqueSplitSubfolder`만 PC에 남는다.
- **페이지 범위**: `parsePageRange(text, pageCount)`, `PageRangeResult`.
- **이미지**: `ImageKind`, `ImageInfo`, `ImagesToPdfOptions`, `readImageInfo`, `orientedImageMatrix`, `imagesToPdfBytes(images, options)`, 새 `imagesToPdfFrom(next: AsyncIterable<Uint8Array>, options)`(같은 그림·순서면 같은 바이트).
- **양면 인쇄·배경 겹치기**(2판 도구): `blankPagesToAdd`, `duplexMergeBytes`, `overlayMatrix`, `overlayPdfBytes`, `OverlayOptions`.
- **주석**: `AnnotKind`, `ANNOT_KINDS`, `COMMENT_ANNOT_KINDS`, `StripAnnotsOptions`, `annotKindOf`, `stripAnnotsBytes`, `stripCommentAnnotsBytes`.
- **용량 줄이기**: `COMPRESS_LEVELS`, `CompressLevel`, `LEVEL_TARGETS`, `SourceImage`, `RecodedImage`, `ImageRecoder`, `CompressResult`, `sourceOf`, `samplesToBgra`, `compressPdfBytes(bytes, level, recode, { onProgress, signal })`.
- **PDFium을 받아 쓰는 것**: `BlankPagesPdfium`, `isNearlyWhite`, `shrinkBitmap`, `findBlankPages(m, doc, onProgress)` 등 `blank-pages.ts`의 이름 전부, `RepairPdfium`, `RepairFailedError`, `pdfiumOpens(m, bytes, password)`, `repairPdfBytes(m, bytes)`, `salvagePdfBytes(bytes)`, 새 `withPdfiumDocument(m, bytes, password, fn)`와 `PdfiumOpenError { code: 'wrong-password' | 'unreadable' }`, 형 `PdfiumDocModule`. `blank-pages.ts`는 `MAX_THUMBS`·`RENDER_LONG_SIDE`·`THUMB_LONG_SIDE`·`BlankPageCandidate`·`BlankPagesResult`·`BlankReason`·`PageThumb`도 내보낸다.
- **qpdf를 받아 쓰는 것**: `QpdfInstance`, `CreateQpdf`, `EncryptOptions`, `WrongPasswordError`, `QpdfFailedError`, 새 `qpdfEncrypt(create, wasmLocation, bytes, { userPassword, ownerPassword, restrict })`, 새 `qpdfDecrypt(create, wasmLocation, bytes, password, opens)`. 막기를 고르지 않을 때의 아무도 모르는 주인 암호는 부르는 쪽이 만든다(PC `randomUUID()`, 모바일 `crypto.getRandomValues` 32바이트 16진). PC `qpdf.ts`의 `encryptPdfBytes`·`decryptPdfBytes`는 이름·인자 그대로.
- **거울 함수(모바일용, PC 원래 함수와 같은 결과)**: `mergePdfInOrder(inputs)`(= `mergePdfBytes`, 입력을 하나씩 읽음), `extractPdfPages`(= `extractPagesBytes`), `rotateAllPdfPages(bytes, delta)`(= `applySaveRequest` 회전만), `removePdfPages(bytes, pages)`(= `applySaveRequest` 쪽 지우기만), `readPdfTextWith(m, bytes, options?)`(= `readPdfText`, 형 `PdfTextDoc`·`PdfPageText`·`ReadPdfTextOptions`·`PdfTextPdfium`; PDFium이 열지 못하면 `PdfiumOpenError`로 거절 — PC는 일반 Error), `mirrorPageEngine(loadPdfium)`.

원래 파일이 내보내던 이름은 하나도 빠짐없이 옮겼고 원래 자리에서 다시 내보낸다(위는 대표 이름). PC 셸 `tools.ts`에는 PC 전용으로 `pcPageEngine`, `PcRunDeps`(= `RunDeps`), `MAX_TOOL_INPUT_BYTES`, `toolRunsAsJob`, `jobFor`, `jobBytesOf`, `foundBlankPagesOf`가 남는다.

## 한 일

- **공용 패키지 `@genoffice/pdf-ops`**: PC PDF 도구 가운데 이음오피스가 만든 파일(분할, 페이지 범위, 이미지로 PDF, 양면 인쇄, 배경 겹치기, 주석 지우기, 용량 줄이기, 빈 페이지 찾기, 복구, qpdf 핵심)과 셸 `tools.ts`의 규칙·실행기를 옮겼다. 원래 자리 파일은 같은 이름을 다시 내보낸다. 원본 GenOffice와 함께 쓰는 `save-pdf.ts`·`read-text.ts`·`text-edit.ts`는 고치지 않았고, 모바일용 거울 함수가 같은 바이트(텍스트는 같은 글자)를 낸다.
- **PC는 그대로**: PC 결과 기준선(`apps/shell/tests/pdf-tools-golden.test.ts`, 160항목 — 늘 같은 결과는 SHA-256, 암호 걸기처럼 실행마다 바뀌는 것은 구조·내용)을 옮기기 전에 기록했고, 표를 고치지 않은 채 끝까지 통과한다. PC 도구의 회전·빈 페이지 지우기는 지금처럼 `applySaveRequest`를 쓴다.
- **pdf-lib 없는 진입점**: 화면 쪽이 쓰는 것(도구 id·선택지, 규칙, 분할 계획, 페이지 범위)을 pdf-lib 없는 모듈로 나눴다. 옮기는 도중 한때 PC 도구 창 화면 묶음이 0.35MB → 1.14MB로 커졌던 것을 되돌렸고(지금 0.35MB, pdf-lib 없음), 모바일 도구 화면 덩어리도 33KB다(pdf-lib은 엔진 작업 스레드에만).
- **모바일 엔진**(`tools/engine/`): ES 모듈 작업 스레드, PDFium·qpdf는 처음 필요할 때 앱 묶음에서, 입력은 하나씩, [멈추기]는 작업 스레드 종료, 메모리 부족 알림.
- **모바일 화면**(`tools/`, `home/ToolsTab.tsx`): 도구 목록, 파일(시스템 선택 창), 도구별 옵션 시트(PC와 같은 기본값·문구), 처리(진행·멈추기 확인), 빈 페이지 축소판 검토, 결과 시트(열기·공유·다른 곳에 저장, 분할은 조각별 + ZIP, 버리기 전 확인).
- **Rust·다리**: `mobile_pdf_tools_share`, `mobile_pdf_tools_save_copy`(`commands/pdf_tools.rs`), `@genoffice/mobile-bridge/pdf-tools`. 열린 문서 세션·최근 목록·복구 사본을 건드리지 않는다.
- **문구**: 22개 언어 184개(PC 도구 창 문구 152개를 그대로 가져옴, 모바일 32개).

## 결정 후보 (번호는 합칠 때)

1. **공용 패키지는 이음오피스 파일만 옮기고, 원본 공유 파일은 거울 함수로**(주인 승인 11-26). 버린 대안: 원본 공유 함수까지 옮기기(원본 받아오기 충돌), T2의 Node 대역 빌드로 PC 코드 그대로 부르기(T2가 먼저 합쳐져야 함).
2. **PC 결과 기준선 시험을 두고 표를 고치지 않는다.** 원본 받아오기로 PC 도구 결과가 바뀌면 이 시험이 깨진다 — 그때는 바뀐 것이 맞는지 확인하고 사람이 표를 다시 만든다(`PDF_TOOLS_GOLDEN_WRITE=1`).
3. **pdf-lib 없는 진입점**(`./tool-ids`, `./tool-rules`, `./split-plan`, `./page-range`)을 화면·preload가 쓴다.
4. **결과는 메모리에만, [열기]는 이름 없는 문서로**(주인 승인). 결과 저장은 열린 문서 세션을 바꾸지 않는 T3 전용 명령으로 — 기존 "다른 이름으로 저장" 명령은 저장한 파일을 열린 문서로 바꿔 버려 쓰지 않았다.
5. **분할 결과는 조각별 + ZIP**, **사진은 기기가 풀 수 있으면 JPEG(0.92)로**, **결과 이름은 PC 그대로(영어 꼬리)**(모두 주인 승인).

## 발견 (고치지 않음)

1. **PC 도구 창(`pdf-tools-window.ts`)은 입력 판정·결과 다시 확인을 아직 자기 사본으로 한다.** 공용 `inspectToolInput`·`checkToolResult`로 바꾸면 기존 시험 `apps/shell/tests/pdf-tools-wiring.test.ts`가 그 파일의 글자 세 줄을 찾다가 실패한다(기존 시험은 고치지 않는 규칙). 동작은 같고, 공용 쪽은 `packages/pdf-ops/tests/tools.test.ts`가 지킨다. 합칠 때 그 시험의 기대를 `packages/pdf-ops/src/rules.ts`로 옮기면 창도 공용을 쓸 수 있다.
2. **병합·사진→PDF는 입력을 하나씩 읽지만 최대 메모리는 크게 줄지 않는다.** pdf-lib가 저장할 때까지 붙인 내용과 그림을 쥐고 있어서다. 분할 ZIP은 조각을 작업 스레드로 복사하므로 잠깐 두 배를 쓴다. 결과는 base64로 Rust에 넘긴다(전송층이 원시 바이트를 받지 않음, T2 발견 3과 같음). 아주 큰 PDF에서 실기기 메모리를 볼 것.
3. **책갈피 분할에서 책갈피가 있는지 미리 보지 않는다.** 화면에서 읽으면 pdf-lib이 화면 덩어리로 들어온다. 책갈피가 없으면 실행할 때 "책갈피 없음"으로 알린다(PC는 고를 때 알림).
4. **영어 문구에서 "Split by page count" 단추와 그 아래 숫자 칸이 둘 다 "Pages per file"로 읽힌다.** PC 문구를 그대로 가져와서다(한국어는 다르다).
5. **용량 줄이기는 그림을 다시 쓰기 시작하기 전(큰 파일을 읽는 동안)에는 움직이는 막대만 보인다.**
6. **옵션 칸·빈 페이지 칸의 고른 표시 강조는 `:has()`를 써서** Chrome 105+·iOS 15.4+에서만 보인다(그 아래에서는 확인 표시만).
7. **새 문구(모바일 32개)는 모국어 사용자가 보지 않았다.**
8. 무거운 엔진 시험(빈 페이지 125쪽)이 다른 일로 PC가 바쁠 때 시간 초과가 한 번 났다. 따로 돌리면 통과한다.

## 실기기에서 볼 것

- 파일 여러 개 고르기(`<input multiple>`)가 Android 웹뷰(Tauri)와 iOS에서 되는지, 사진 선택 창이 권한 창 없이 뜨는지, iPhone의 HEIC가 JPEG로 넘어오는지.
- 큰 PDF(수백 쪽·수백 MB) 용량 줄이기·병합의 메모리, 처리 중 앱이 뒤로 갔을 때(iOS는 JS를 멈춤).
- iOS 15~16.3에서 용량 줄이기·사진 바꾸기가 화면 스레드 캔버스로 도는지.
- 공유·다른 곳에 저장(SAF·Files) 창, ZIP 공유가 메신저에서 열리는지.

## 문구 키 (T6)

화면 문구는 `i18n/pdfTools/<언어>.ts`(22개 언어)에 있다. 키는 두 가지다.

- **PC 문구 그대로**: PC 도구 창(`apps/shell/src/renderer/src/i18n/pdf-tools/<언어>.ts`)의 값을 가져와 키만 바꾼다. 모바일 키는 `pdfTools` + PC 키(첫 글자 대문자). 도구·묶음·선택지 이름이 PC와 갈라지지 않도록 고쳐 쓰지 않는다. `tests/pdf-tools-i18n.test.ts`가 22개 언어 모두 PC 값과 같은지 본다.
- **모바일 문구**: PC 창에 없거나 PC 문장이 휴대폰에서 틀리는 것. 22개 언어로 따로 썼다.
- 가져오지 않는 PC 문구(시험의 금지 목록): `localNote`(이 PC), `toolEdit`·`descEdit`(가림 포함), `editorHint`(리본), `run`(새 파일로 저장), `openResult`(탭), `reveal`(폴더), `errMissing`, `errTooLarge`·`rejectTooLarge`(1GB 한도), `errSameAsSource`·`errUnsavedTarget`(저장 창·열린 탭), `splitSubfolder`, `splitVisualInEditor`, `hintImages`·`rejectNotImage`(JPG·PNG만 받는다는 말). 2판 도구 문구는 쓰지 않을 뿐 금지는 아니다.
- 자리 표시는 `{이름}` 모양(`translateMobile(lang, key, { n })`). PC 문구는 PC와 같은 이름(`{n}`, `{name}`, `{done}`, `{total}`, `{pages}`)을 쓴다.
- 아이콘은 `components/icons/pdfTools.tsx`의 `pdfToolsIcons`(도구 id → 아이콘, 편집·서명 카드는 `edit`). 모양은 PC 리본 아이콘과 같다.

- `pdfToolsDiscardConfirm` — 저장하지 않은 결과는 사라집니다. (모바일)
- `pdfToolsCancel` — 취소 (모바일)

PC의 `errFailed`(처리하지 못했습니다)는 그 밖의 실패에, `pdfToolsMakeFailed`는 결과 다시 확인(`checkToolResult`)에서 떨어졌을 때, `pdfToolsRepairFailed`는 복구가 두 길 모두 실패했을 때 쓴다. 결과 시트의 [닫기]는 `pdfToolsClose`, 저장 안 함 확인 창은 `pdfToolsDiscardConfirm` + [`pdfToolsClose`][`pdfToolsCancel`], 멈추기 확인 창은 `pdfToolsStopConfirm` + [`pdfToolsStop`][`pdfToolsContinue`]이다.
