# T3 — PDF 도구 (모바일 1판)

PC "PDF 도구"의 1판 묶음을 모바일 [도구] 화면으로 낸다. 처리 코드는 새 공용 패키지 `@genoffice/pdf-ops`로 PC와 함께 쓴다. 자리 표는 [README.md](README.md), 쓰는 법은 `apps/mobile/AGENTS.md`의 `### T3 PDF 도구 (1판)`.

## 공용 패키지 약속 (`@genoffice/pdf-ops`)

T2와 합치는 쪽이 읽는 약속이다. 바꾸면 이 절을 함께 고친다. 같은 이름은 PC에 있던 것과 뜻·입출력이 같다. 페이지 번호는 따로 적지 않으면 0부터.

- 패키지: `packages/pdf-ops`, `exports: { ".": "./src/index.ts" }`, 의존은 `pdf-lib`만. PDFium·qpdf·그림 다시 쓰기는 부르는 쪽이 넣는다. Node·Electron·네트워크 없음.
- **도구 영역 형·상수**(PC `apps/shell/src/shared/pdf-tools-api.ts`에서 옮김): `PDF_TOOL_IDS`, `PdfToolId`, `PdfToolOptions`, `PdfInputProblem`, `PdfToolAccept`, `PdfToolInputKind`, `PDF_TOOL_PAPERS`·`PdfToolPaper`, `PDF_TOOL_SHEET_PAGES`, `PDF_TOOL_ANNOT_KINDS`·`PdfToolAnnotKind`, `PDF_TOOL_MARGINS`·`PdfToolMargin`.
- **도구 규칙**(PC `tools.ts`에서): `isPdfToolId`, `toolTakesMany`, `toolMinInputs`, `toolAccepts`, `toolInputKind`, `toolOutputExtension`, `MAX_PASSWORD_BYTES`(127), `PdfToolRefusal`(`'no-text' | 'no-annots' | 'not-smaller' | 'no-bookmarks'`), `InspectResult`, `inspectPdf(bytes)`, `inspectImage(bytes)`, `encryptedPageCount(bytes)`, `inspectToolInput(bytes, kind, accept)`(PC 창의 `pagesFor`), `checkOptions(tool, raw, pageCount, backgroundPages = 1)`, `CheckedOptions`, `DEFAULT_ANNOT_KINDS`, `splitPlanFromOptions(options, pageCount)`, `pagesToText(pages)`, `outputNames(tool, sourceName, count, options)`(PC 규칙 그대로, 떼는 확장자에 heic·heif·webp·gif·bmp·avif·tif·tiff를 더함), `readBookmarksBytes(bytes)`, `checkToolResult(tool, bytes)`(PC 창의 결과 다시 확인), `FoundBlankPages`.
- **실행기**: `PageEngine { mergePdfBytes(first, others); extractPagesBytes(bytes, pages); rotateAllPages(bytes, delta); removePages(bytes, pages); readText(bytes); mergePagesBytes?; setPageSizeBytes?; splitPagesBytes? }`, `RunDeps { engine; recode?; onProgress?; signal? }`, `runPdfTool(tool, inputs, options, deps)`(`encrypt`·`decrypt`·`repair`는 여기서 돌지 않음), `runSplitPdfTool(first, sourceName, options, deps?)`(엔진 필요 없음). PC `tools.ts`는 지금 시그니처 그대로(`deps` 선택)인 감싸개를 남겨 PC 엔진(`save-pdf.ts`·`read-text.ts` 원래 함수)을 채운다.
- **분할**(`split-plan.ts`, `split-pdf.ts`에서): 지금 내보내는 이름 전부 — `planSplitParts`, `formatSplitOutputNames`, `parseSplitRangeList`, `formatSplitRangeList`, `sanitizeSplitName`, `MIN_SPLIT_MAX_BYTES`, `MAX_SPLIT_MAX_BYTES`, `splitSubfolderName`, 형들, `executeSplitPlan`, `readPdfBookmarks`, `readBookmarksFromDoc` 등. 파일 경로를 쓰는 `uniqueSplitSubfolder`만 PC에 남는다.
- **페이지 범위**: `parsePageRange(text, pageCount)`, `PageRangeResult`.
- **이미지**: `ImageKind`, `ImageInfo`, `ImagesToPdfOptions`, `readImageInfo`, `orientedImageMatrix`, `imagesToPdfBytes(images, options)`, 새 `imagesToPdfFrom(next: AsyncIterable<Uint8Array>, options)`(같은 그림·순서면 같은 바이트).
- **양면 인쇄·배경 겹치기**(2판 도구): `blankPagesToAdd`, `duplexMergeBytes`, `overlayMatrix`, `overlayPdfBytes`, `OverlayOptions`.
- **주석**: `AnnotKind`, `ANNOT_KINDS`, `COMMENT_ANNOT_KINDS`, `StripAnnotsOptions`, `annotKindOf`, `stripAnnotsBytes`, `stripCommentAnnotsBytes`.
- **용량 줄이기**: `COMPRESS_LEVELS`, `CompressLevel`, `LEVEL_TARGETS`, `SourceImage`, `RecodedImage`, `ImageRecoder`, `CompressResult`, `sourceOf`, `samplesToBgra`, `compressPdfBytes(bytes, level, recode, { onProgress, signal })`.
- **PDFium을 받아 쓰는 것**: `BlankPagesPdfium`, `isNearlyWhite`, `shrinkBitmap`, `findBlankPages(m, doc, onProgress)` 등 `blank-pages.ts`의 이름 전부, `RepairPdfium`, `RepairFailedError`, `pdfiumOpens(m, bytes, password)`, `repairPdfBytes(m, bytes)`, `salvagePdfBytes(bytes)`, 새 `withPdfiumDocument(m, bytes, password, fn)`와 `PdfiumOpenError { code: 'wrong-password' | 'unreadable' }`.
- **qpdf를 받아 쓰는 것**: `QpdfInstance`, `CreateQpdf`, `EncryptOptions`, `WrongPasswordError`, `QpdfFailedError`, 새 `qpdfEncrypt(create, wasmLocation, bytes, { userPassword, ownerPassword, restrict })`, 새 `qpdfDecrypt(create, wasmLocation, bytes, password, opens)`. 막기를 고르지 않을 때의 아무도 모르는 주인 암호는 부르는 쪽이 만든다(PC `randomUUID()`, 모바일 `crypto.getRandomValues` 32바이트 16진). PC `qpdf.ts`의 `encryptPdfBytes`·`decryptPdfBytes`는 이름·인자 그대로.
- **거울 함수(모바일용, PC 원래 함수와 같은 결과)**: `mergePdfInOrder(inputs)`(= `mergePdfBytes`, 입력을 하나씩 읽음), `extractPdfPages`(= `extractPagesBytes`), `rotateAllPdfPages(bytes, delta)`(= `applySaveRequest` 회전만), `removePdfPages(bytes, pages)`(= `applySaveRequest` 쪽 지우기만), `readPdfTextWith(m, bytes)`(= `readPdfText`, `PdfTextDoc`·`PdfPageText`), `mirrorPageEngine(loadPdfium)`.

실제로 옮긴 이름이 위보다 많으면(원래 파일이 내보내던 이름 전부를 옮김) 마지막에 이 절을 고친다.

## 주인 결정 (11-26 승인)

기획 질문 11개를 주인이 "모두 권장대로" 승인했다. 결과는 메모리에 두고 결과 시트에서 고름(열기는 이름 없는 문서로), 분할은 조각별 + ZIP, 사진은 기기가 풀 수 있으면 JPEG로, 결과 이름은 PC 그대로, 공용 패키지는 이음오피스 파일만 옮기고 원본 공유 파일은 거울 함수로, 소유 밖 파일 셋은 다시 내보내기(approved out-of-track edit, 따로 커밋), 이 사본에서 `npm install --ignore-scripts` 한 번, 분할은 네 방식 + 이름 설정, 편집기 카드는 "편집·서명" 하나, 처리 중 화면 꺼짐 막기는 T6 훅, `annot-delete.ts` 넓히기는 하지 않음.

## 의존과 라이선스

`apps/mobile`에 `@genoffice/pdf-ops`(작업 공간), `pdf-lib`(MIT), `@embedpdf/pdfium`(MIT), `@neslinesli93/qpdf-wasm`(ISC, 안의 qpdf는 Apache-2.0), `jszip`(MIT 또는 GPL-3.0 중 MIT로 씀)을 더했다. `apps/pdf`·`apps/shell`은 `@genoffice/pdf-ops`를 `devDependencies`에(electron-vite가 묶도록). `npm run licenses` 통과.

## 문구 키 (T6)

화면 문구는 `i18n/pdfTools/<언어>.ts`(22개 언어)에 있다. 키는 두 가지다.

- **PC 문구 그대로**: PC 도구 창(`apps/shell/src/renderer/src/i18n/pdf-tools/<언어>.ts`)의 값을 가져와 키만 바꾼다. 모바일 키는 `pdfTools` + PC 키(첫 글자 대문자). 도구·묶음·선택지 이름이 PC와 갈라지지 않도록 고쳐 쓰지 않는다. `tests/pdf-tools-i18n.test.ts`가 22개 언어 모두 PC 값과 같은지 본다.
- **모바일 문구**: PC 창에 없거나 PC 문장이 휴대폰에서 틀리는 것. 22개 언어로 따로 썼다.
- 가져오지 않는 PC 문구(시험의 금지 목록): `localNote`(이 PC), `toolEdit`·`descEdit`(가림 포함), `editorHint`(리본), `run`(새 파일로 저장), `openResult`(탭), `reveal`(폴더), `errMissing`, `errTooLarge`·`rejectTooLarge`(1GB 한도), `errSameAsSource`·`errUnsavedTarget`(저장 창·열린 탭), `splitSubfolder`, `splitVisualInEditor`, `hintImages`·`rejectNotImage`(JPG·PNG만 받는다는 말). 2판 도구 문구는 쓰지 않을 뿐 금지는 아니다.
- 자리 표시는 `{이름}` 모양(`translateMobile(lang, key, { n })`). PC 문구는 PC와 같은 이름(`{n}`, `{name}`, `{done}`, `{total}`, `{pages}`)을 쓴다.
- 아이콘은 `components/icons/pdfTools.tsx`의 `pdfToolsIcons`(도구 id → 아이콘, 편집·서명 카드는 `edit`). 모양은 PC 리본 아이콘과 같다.

### 결과 시트

- `pdfToolsDoneOne` — 새 파일을 만들었습니다: {name}
- `pdfToolsDoneMany` — 파일 {n}개를 만들었습니다.
- `pdfToolsClose` — 닫기
- `pdfToolsResultTitle` — 결과 (모바일)
- `pdfToolsOpen` — 열기 (모바일)
- `pdfToolsShare` — 공유 (모바일)
- `pdfToolsSaveCopy` — 다른 곳에 저장 (모바일)
- `pdfToolsSaved` — 저장했습니다. (모바일)
- `pdfToolsSaveFailed` — 저장하지 못했습니다. (모바일)
- `pdfToolsShareFailed` — 공유하지 못했습니다. (모바일)
- `pdfToolsSizeChange` — 원래 크기 {before} → 새 크기 {after} (모바일)
- `pdfToolsZipShareAll` — ZIP 하나로 모두 공유 (모바일)
- `pdfToolsZipSaveAll` — ZIP 하나로 모두 저장 (모바일)
- `pdfToolsDiscardConfirm` — 저장하지 않은 결과는 사라집니다. (모바일)
- `pdfToolsCancel` — 취소 (모바일)

PC의 `errFailed`(처리하지 못했습니다)는 그 밖의 실패에, `pdfToolsMakeFailed`는 결과 다시 확인(`checkToolResult`)에서 떨어졌을 때, `pdfToolsRepairFailed`는 복구가 두 길 모두 실패했을 때 쓴다. 결과 시트의 [닫기]는 `pdfToolsClose`, 저장 안 함 확인 창은 `pdfToolsDiscardConfirm` + [`pdfToolsClose`][`pdfToolsCancel`], 멈추기 확인 창은 `pdfToolsStopConfirm` + [`pdfToolsStop`][`pdfToolsContinue`]이다.
