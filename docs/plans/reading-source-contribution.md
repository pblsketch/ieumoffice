# HWP·PDF·EPUB 성능과 저장 보존 개선

## 기준과 목적

공식 저장소 `main`의 `098baf6b44fe2df5aaf44f8e45a85a649794734e`를 기준으로,
문서 편집을 유지하면서 대용량 문서의 중복 읽기·상주 자료·화면 밖 작업을 줄인다.
변경은 소스에 적용하며 설치된 앱의 파일을 수정하는 방식에 의존하지 않는다.

## 변경 범위

| 영역 | 변경                                                                                                                                                                                                                                         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 공통 | ZIP 범위 읽기와 실제 해제량 검사, 저장 충돌 검사의 스트리밍 해시, 탭 표시 상태 전달을 추가한다.                                                                                                                                              |
| PDF  | 불변 파일 소스와 PDFium 파일 콜백을 쓰는 작업자로 표시 쪽을 먼저 그린다. 텍스트·비트맵 캐시에 예산을 두고, 확대 화면은 타일로 그린다. PDF.js 편집·검색·대체 표시 경로를 유지한다. Windows OCR 호출은 비동기로 실행하고 동시 요청을 제한한다. |
| EPUB | 큰 책을 파일 기반 ZIP 소스로 열고 자원·저장을 스트리밍한다. 수정하지 않은 장 모델은 최근 8개·추정 16MiB 안에서 보관하며, 수정본·실행 취소 상태는 보존한다. 검색 시 반복 탐색도 줄인다.                                                       |
| HWP  | 숨긴 탭의 재생성 가능한 화면 자료와 보조 조회를 줄인다. 이어진 문단의 쪽 시작 원점과 SVG/PDF 출력의 음수 자간 글폭을 보완한다. 기존 캡션 위치 메뉴를 엔진 명령과 연결하고 글꼴 메타데이터 처리를 보완한다.                                   |
| 검증 | 실제 WASM의 편집·저장·재열기, 쪽 경계·표·병합·이미지 보존, 잘못된 요청의 거절을 검사한다. 출처는 `tools/hwp-validation/README.md`와 `NOTICE`에 둔다.                                                                                         |

HWP 엔진은 `0.9.0-ieum.28`이다. 기존 main의 일괄 서식 배치 패치 0043과
PDF CMap 패치 0044를 유지하고, 쪽 원점 수정은 0045, 글폭 수정은 0046으로 더했다.
34개 패치를 모두 적용해 WASM을 다시 빌드하며, PDF 가져오기 기본 기능도 유지한다.
엔진 정체성은 `vendor/rhwp-core/package.json`의 버전·고정 커밋·WASM SHA-256으로 확인한다.

## 트레이드오프와 한계

- 캐시에서 내보낸 쪽·장을 다시 찾으면 재로딩·재그리기 비용이 든다. 확대·탭 전환 직후 선명한 화면을 다시 준비하는 시간이 생길 수 있다.
- PDF와 큰 EPUB의 불변 사본은 임시 디스크 공간과 처음 열 때의 I/O를 사용한다. 정상적인 보기 종료 때 정리한다.
- EPUB의 수정한 장과 이력은 캐시 예산으로 버리지 않는다. 많은 장을 편집하면 메모리가 늘 수 있다. 16MiB는 장 모델의 추정 예산이며 앱 전체 메모리 상한이 아니다.
- PDF.js 편집 모델과 대체 경로는 남아 있다. 모든 작업에서 파일 길이의 버퍼가 사라지는 구조는 아니다.
- 숨겨진 탭의 보조 정보는 다시 보이거나 요청할 때 준비한다. 문서·편집 이력은 유지한다.
- HWP 검사는 자체 엔진의 일관성과 보존을 확인한다. 다른 PC의 글꼴, 모든 문서와 공식 렌더러의 배치 일치까지 입증하지 않는다.
- 캡션 위치 변경은 검증한 본문 표·그림·도형과 셀 안 그림에 한정한다. 중첩 표·머리말·각주·글상자 안 표는 잘못된 대상을 수정하지 않도록 막는다.

## 재현과 검증

```sh
npm ci
npm run typecheck
npm run lint
npm run format:check -- --base origin/main
npm run test -w @genoffice/pdf -- --maxWorkers=1
npm run test -w @genoffice/epub -- --maxWorkers=1
npm run test -w @genoffice/epub-engine -- --maxWorkers=1
npm run test -w @genoffice/hwp
node tools/hwp-validation/run.mjs --engine-version 0.9.0-ieum.28 --synthetic --out ../outputs/hwp-validation-new
```

메인·preload 코드를 고친 뒤에는 해당 편집기와 셸을 새로 빌드해 실행한다.
타입 검사나 예전 실행 파일의 결과로 새 코드의 동작을 판단하지 않는다.
Windows에서 실패한 공용 경로 시험은 수정하지 않은 동일 main 사본에서도 재현해 구분한다.
이 PR의 통합 검증 결과는 PR 본문에 적으며, 과거 개발본의 속도 수치를 이번 빌드의 결과로 쓰지 않는다.

`tools/profile-*`와 `tools/summarize-reading-comparison.mjs`는 선택적인 개발 계측 도구다.
사용자 문서·개인 경로·측정 원시 자료는 저장소에 넣지 않는다. 메모리를 비교할 때는
RSS·작업 집합과 프로세스 전용 커밋을 구분하고, 앱 전체와 개별 뷰의 측정을 섞지 않는다.

## 개인용 설치 파일

`npm run dist:win:local`은 전체 소스를 빌드해 Windows 설치 파일을 만들고 게시하지 않는다.
준비 조건은 `docs/operations.md`의 개인용 Windows 빌드 설명을 따른다.
버전은 `0.12.12+local.<식별자>`처럼 빌드 메타데이터로 구분한다.
`-local` 시험판 표기로 같은 정식 버전이 새 업데이트로 보이던 문제를 피하면서,
다음 정식 버전의 업데이트 확인을 유지한다.
